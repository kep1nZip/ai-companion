## 1. Architecture Audit

Per subsystem, verifikasi:
- [ ] Tidak ada import yang melanggar Independence Policy domain itu (cek daftar larangan di master context tiap subsystem).
- [ ] Public API (method yang dipanggil dari luar folder) belum berubah signature-nya dari yang terakhir didokumentasikan.
- [ ] Tidak ada circular import baru.
- [ ] Tidak ada akses attribute internal lintas modul (`obj._private_thing` dari luar class-nya) — semua komunikasi lewat method publik.

## 2. Documentation Audit

- [ ] `README.md` — ada & mencerminkan cara install/jalanin project saat ini (versi terbaru).
- [ ] `CHANGELOG.md` — ada, mencatat tiap versi v0.1→v0.9.5 minimal 1 baris ringkas (bisa disusun dari riwayat master context).
- [ ] `ROADMAP.md` — mencerminkan Phase 1-4 yang sudah ada di master context, update status jadi "v1.0 in progress".
- [ ] `ARCHITECTURE.md` — diagram + penjelasan tiap subsystem (bisa diturunkan dari bagian 3-6 master context).
- [ ] `TECH_STACK.md` — daftar semua dependency (`requirements.txt`) + alasan pemilihan tiap library besar (google-genai, PySide6, faster-whisper, mss, dst).
- [ ] `CODE_STYLE.md` — ✅ sudah dibuat di sesi ini.
- [ ] Version number konsisten di `config/constants.py`, README, dan tag git (kalau pakai git).

## 3. Code Quality Audit

Per file, cek:
- [ ] Naming konsisten dengan `CODE_STYLE.md`.
- [ ] Type hints lengkap di semua public method.
- [ ] Docstring ada di semua class.
- [ ] Tidak ada import yang tidak dipakai.
- [ ] Tidak ada dead code (method yang tidak pernah dipanggil dari mana pun — **cek khusus bug lama seperti duplikasi `_build_contents()` di v0.9.5, kemungkinan ada pola serupa di file lain yang sering di-edit bertahap**: `ai/companion.py`, `ai/context_builder.py`, `behavior/behavior_engine.py`).
- [ ] Tidak ada duplicate logic (2 fungsi berbeda yang melakukan hal yang sama).
- [ ] Magic number sudah dipindah ke `config/constants.py`.
- [ ] Format logging konsisten (lihat `CODE_STYLE.md` §6).

## 4. Performance Audit

Ukur (pakai `DeveloperService.get_performance()` yang sudah ada sejak v0.9.5!):
- [ ] Gemini latency (chat & TTS)
- [ ] Vision latency (capture + analyze)
- [ ] Behavior update time
- [ ] Routine update time
- [ ] Initiative evaluation time
- [ ] Memory lookup time
- [ ] Waktu startup total (load Whisper model dulu yang paling berat historis)

**Jangan optimasi apa pun sampai ada angka nyata dari `PerformanceTracker`.** No premature optimization (eksplisit di spec).

## 5. Thread Safety Audit

- [ ] GUI thread vs `ChatWorker`/`VoiceWorker`/`SpeakWorker`/`AvatarWorker` — semua komunikasi lewat Qt Signal, bukan shared mutable state langsung.
- [ ] `PerformanceTracker` sudah pakai `threading.Lock` (v0.9.5) — cek subsystem lain yang diakses dari >1 thread (`AvatarManager._parameter_layers`, dst) apakah butuh lock serupa.
- [ ] Shutdown path (`closeEvent`) — semua worker/thread di-stop dengan bersih, tidak ada thread yang "menggantung" saat aplikasi ditutup.

## 6. Error Handling Audit

- [ ] Tiap subsystem fail gracefully (sudah jadi pola konsisten sejak v0.6.0 — Behavior/Vision/Routine/Initiative semua fallback ke default kalau gagal). Verifikasi ini masih berlaku di SEMUA titik, bukan cuma yang paling sering diuji.
- [ ] Tidak ada exception yang bisa bocor sampai crash aplikasi tanpa ke-log dulu.

## 7. Logging Audit

- [ ] Format konsisten di semua subsystem (bandingkan style logging `behavior/` vs `vision/` vs `routine/` vs `initiative/` — apakah semua ikut pola yang sama).
- [ ] Tidak ada log yang duplikat (2 baris log untuk 1 event yang sama).
- [ ] Rotation & retention `config/logger.py` masih sesuai kebutuhan (1MB rotation, 7 hari retention — cek apakah masih pas untuk penggunaan v1.0).

## 8. Testing Policy

Belum ada test suite terbentuk sepanjang percakapan ini. Prioritas kalau mau mulai:
- [ ] Unit test subsystem yang paling "pure function" dulu (`behavior/emotion_rules.py`, `behavior/relationship_rules.py`, `initiative/initiative_rules.py`, `routine/routine_rules.py`) — tidak butuh mock rumit karena murni logic.
- [ ] Integration test `Companion.chat()` end-to-end (mock `GeminiClient` biar tidak perlu API key sungguhan saat test).
- [ ] Smoke test startup — `python main_gui.py` jalan tanpa exception sampai window muncul.
- [ ] Regression test untuk bug yang sudah pernah terjadi (lihat daftar 9 bug di master context bagian 7 — masing-masing idealnya punya 1 test yang memverifikasi bug itu tidak muncul lagi).

## 9. Packaging Policy

- [ ] `requirements.txt` lengkap & versi ter-pin (atau minimal ada `requirements-lock.txt`).
- [ ] Tidak ada hardcoded absolute path (`F:\ai-companion...`, `H:\!ai-companion-terbaru!...` — ini KELIHATAN di beberapa traceback yang di-paste sebelumnya, PASTIKAN tidak ada path Windows spesifik developer yang ke-hardcode di kode, cuma di lingkungan lokal).
- [ ] `.env.example` disediakan (template, tanpa API key asli).
- [ ] Rencana installer Windows + portable build.

## 10. Security Audit

- [ ] API key cuma dari `.env`, tidak pernah hardcoded atau ter-log.
- [ ] `logs/app.log` tidak pernah mencatat isi `.env`/API key mentah.
- [ ] Tidak ada file sensitif (`.env`, `memory.db`, `vtube_token.json`) yang ter-commit ke git kalau pakai version control (cek `.gitignore`).
