# v2.8 — Conversation Intelligence — Laporan Eksekusi

**Scope dieksekusi (sesuai keputusan Teacher):** Phase 5 (Conversation Closure) + Phase 3+6 (Conversation Guidance via prompt) + Phase 20 (Observability jujur).
**Sengaja TIDAK dikerjakan:** Phase 8 (Topic-Aware History Selection — history masih unbounded, belum ada masalah nyata), field Current Topic/Follow-up Detected/Topic Shift (butuh classifier sungguhan, memicu Stop Condition #1 spec).
**Tidak ada perubahan arsitektur Conversation/ContextBuilder** — keduanya tetap seperti sebelumnya secara struktural, cuma ditambah 1 method baca (`get_last_user_message()`) dan 1 modul kecil baru (`ai/conversation_signals.py`).

---

## 1. Phase 5 — Conversation Closure ✅

**Alur (persis pola v2.7 Vision/Memory-aware Initiative):**
```
Conversation.get_last_user_message()  [baca _history yang sudah ada]
    -> ai/conversation_signals.py::detect_closure()  [regex/keyword, TIDAK ada LLM kedua]
    -> DecisionContext.conversation_closed (bool)
    -> ConversationClosureRule (soft penalty -10, BUKAN hard suppression)
```

**File baru:** `ai/conversation_signals.py` — 12 pattern regex (case-insensitive) untuk frasa penutup umum ("oke makasih", "udah ngerti", "sip", "besok aja lanjut", dst). Fungsi murni, tidak ada state, tidak ada panggilan network/provider apa pun.

**Method baru:** `Conversation.get_last_user_message()` — murni membaca `_history` mundur sampai ketemu `role="user"` terakhir. Tidak menambah state baru — Conversation tetap satu-satunya source of truth.

**Rule baru:** `ConversationClosureRule` di `initiative_rules.py` — weight `-10.0`, dipilih dari magnitude terkecil yang SUDAH dipakai rule lain (`MoodBonusRule`/`CuriosityRule`/`MemoryRelevanceRule`, semua 10.0) — bukan angka baru, konsisten dengan alasan konservatif yang sama seperti v2.7 untuk sinyal yang belum tervalidasi pemakaian nyata.

**Terverifikasi nyata:**
- 15 skenario teks (positif & negatif) diuji, termasuk edge case "Oke, tapi kenapa masih error?" (harus **TIDAK** terdeteksi closure — dan memang tidak, PASS).
- End-to-end lewat `Companion` sungguhan: riwayat "error 500 → saran → Oke makasih udah ngerti" → `conversation_closed=True` → rule aktif → muncul di `reasons`. Riwayat "Kalau pakai async gimana?" (masih aktif) → rule TIDAK aktif.
- Kedua penalty (`RecentInteractionPenaltyRule` -20 dari v2.7 + `ConversationClosureRule` -10 baru) **menumpuk secara alami** saat closure baru terjadi — total -30, semakin meyakinkan Initiative diam tepat setelah percakapan ditutup.

## 2. Phase 3 + 6 — Conversation Guidance (Prompt) ✅

**File diubah:** `prompts/system_rules.txt` — file yang SUDAH ADA (bukan file baru), ditambah 5 kalimat di akhir:
- Pakai riwayat untuk memahami topik saat ini.
- Pesan pendek/bergantung konteks ("kalau yang ini?", "terus?") diperlakukan sebagai lanjutan topik, bukan pertanyaan baru berdiri sendiri.
- Kalau Teacher pindah topik, ikuti topik baru — jangan paksa kembali ke topik lama.
- Jangan ulangi saran/pertanyaan yang sudah diberikan kalau Teacher sudah merespons itu (mis. "sudah dicoba").
- Kalau referensi genuinely ambigu, tanya klarifikasi singkat — jangan menebak percaya diri.

**Tidak ada classifier/topic engine baru** — murni instruksi tambahan ke model yang SUDAH menerima riwayat mentah lengkap (temuan Phase 0: LLM sudah "melihat" transkrip, cuma belum diminta eksplisit memanfaatkannya untuk hal-hal ini).

**Terverifikasi:** `load_prompts()` + `build_system_prompt()` tetap berhasil dimuat, kalimat baru muncul di posisi yang benar dalam system prompt gabungan.

## 3. Phase 20 — Developer Observability ✅

**3 field baru ditambahkan ke `Companion.get_context_debug_snapshot()`** (dict yang sama dari v2.6, tidak perlu ubah schema `DeveloperSnapshot` karena `context_debug` sudah generik `Optional[dict]`):
- `recent_turns_used` — `len(get_history(max_messages=cap))`, angka yang BENAR-BENAR akan dipakai kalau chat terjadi sekarang.
- `history_filtered` — `history_message_count - recent_turns_used` (0 kalau cap belum aktif, sesuai kondisi Teacher saat ini).
- `conversation_closed` — hasil deteksi terakhir, reuse `_detect_conversation_closure()` yang sama dengan Phase 5.

**SENGAJA TIDAK ditambahkan:** Current Topic, Follow-up Detected, Topic Shift — ketiganya butuh mekanisme deteksi topik sungguhan untuk diisi jujur (audit Phase 0 §9), yang berarti classifier/LLM kedua — di luar guardrail v2.8. Ini bukan kelalaian, ini keputusan eksplisit yang sudah disetujui Teacher.

**Terverifikasi nyata:** `DeveloperService.get_snapshot()` end-to-end — semua field terisi benar (`Conversation Closure: Yes` untuk riwayat closure sungguhan), muncul di GUI card "Context" dan markdown export.

## 6. Yang Masih Perlu Manual (Tidak Bisa Saya Klaim di Sandbox)

- **Kualitas nyata dari prompt guidance** (Phase 3+6) — apakah model (Gemini/Local) benar-benar mengikuti instruksi baru ini butuh percakapan nyata dari Teacher untuk dinilai, bukan sesuatu yang bisa saya klaim dari sandbox.
- **Ketepatan pattern closure** — 12 pattern yang saya buat mencakup frasa umum Indonesia informal, tapi Teacher mungkin punya gaya bicara/frasa penutup yang belum tercakup. Kalau ternyata sering false-negative (closure asli tidak terdeteksi) atau false-positive (dianggap closure padahal masih lanjut), pattern-nya bisa disesuaikan — desainnya sengaja modular (satu file kecil, gampang ditambah) untuk itu.
- **`main_gui.py`** — regresi umum perlu observasi Teacher langsung, pola sama seperti versi-versi sebelumnya.
