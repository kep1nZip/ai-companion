## Phase 1 — Configuration Cleanup

**Dieksekusi:**
1. **Provider factory bersama** (`ai/providers/factory.py`, file baru) — logic pemilihan `AI_PROVIDER`/`MEMORY_PROVIDER` yang sebelumnya inline & terduplikasi di `main_gui.py` dipindah ke satu tempat (`build_language_provider()`, `build_memory_provider()`). Murni dipindah apa adanya, lalu di-reuse — tidak ada logic baru.
2. **`main.py` (CLI) diperbaiki** — sekarang reuse factory yang sama dengan `main_gui.py`. Env yang sama sekarang menghasilkan provider yang sama, berapa pun entrypoint yang dijalankan. Vision **sengaja tidak** diikutkan di CLI (CLI tidak pernah punya screen capture loop — menambahkannya akan jadi fitur baru, di luar scope audit provider).
3. **Log message provider-aware** (`ai/companion.py`) — `"Gemini Request"`/`"Gemini Reply"` yang sebelumnya selalu literal "Gemini" apa pun provider aktifnya, sekarang menyebut provider yang benar-benar dipakai (`"Local Request"` / `"Gemini Request"`). Murni teks log, tidak ada perubahan behavior.

**Tidak dieksekusi (dicatat, bukan diabaikan):**
- Asimetri model-name-hardcoded (Gemini) vs model-name-env (Local) — dinilai kemungkinan disengaja, tidak diubah tanpa keputusan eksplisit Teacher/GPT.
- Rename `Companion._gemini` → nama netral provider — dinilai berisiko lebih besar dari manfaatnya, tidak dieksekusi.

## Phase 3 — Performance Baseline

**Status: ✅ Selesai — dijalankan Teacher, `N_RUNS=5` per subsystem/provider.**

| Subsystem | Provider | Sukses | Mean | P50 | Min | Max | Error Rate |
|---|---|---:|---:|---:|---:|---:|---:|
| Language Generation | Local | 5/5 | 11.91s | 11.40s | 11.01s | 13.84s | 0% |
| Language Generation | Gemini | 5/5 | 16.61s | 19.17s | 3.97s | 27.94s | 0% |
| Memory Extraction | Local | 5/5 | 3.39s | 2.30s | 2.29s | 7.77s | 0% |
| Memory Extraction | Gemini | 5/5 | 20.59s | 23.24s | 2.39s | 29.46s | 0% |
| Vision | Local | 5/5 | 30.72s | 23.91s | 19.81s | 63.34s | 0% |
| Vision | Gemini | 5/5 | 19.17s | 21.37s | 8.40s | 27.94s | 0% |

**Analisis (observasi, bukan kesimpulan final — sesuai §17 spec "Measure → Identify bottleneck → Change → Measure again"):**

1. **Language Generation:** Local lebih konsisten & cepat rata-rata (mean 11.91s vs 16.61s), tapi Gemini punya run tercepat (3.97s), jauh lebih cepat dari run tercepat Local (11.01s). Variance Gemini sangat lebar (3.97s–27.94s) — kemungkinan dipengaruhi jaringan/antrian API. Tidak bisa disimpulkan "Local pasti lebih cepat" dari 5 run saja, tapi datanya condong ke arah situ.
2. **Memory Extraction:** Local jauh lebih cepat (mean 3.39s vs 20.59s) — beda cukup besar untuk dicatat sebagai temuan kuat. Relevan karena `MEMORY_PROVIDER` default saat ini masih `"gemini"` — kalau konsisten di run tambahan, ini alasan konkret untuk mempertimbangkan ganti default (keputusan Teacher/GPT).
3. **Vision:** Local justru paling lambat & paling variatif dari semua subsystem (mean 30.72s, max 63.34s) — lebih lambat dari Vision Gemini (mean 19.17s). Berlawanan dengan asumsi umum "Local selalu lebih cepat". Kemungkinan penyebab: preprocessing gambar (resize ke `max_dimension=1280` dari hotfix v2.3) + inference VLM di GPU lokal Teacher (RX 6600 8GB, Vulkan backend) lebih berat dibanding text-only. Max 63.34s masih jauh dari timeout default 120s, jadi tidak error, tapi worth diperhatikan kalau Vision Local dipakai di mode AUTO (interval berulang).

**Rekomendasi:** angka-angka ini sudah cukup untuk masuk Decision Gate sebagai *documented baseline* — tapi keputusan "ganti default provider mana pun" sebaiknya tunggu minimal 1–2 sesi run tambahan (5 run rentan ke outlier) sebelum dijadikan keputusan permanen.

**Status: ✅ Selesai — 4/4 kombinasi construct benar (sandbox) + chat round-trip sungguhan (Teacher, LM Studio + Gemini API asli).**

| Kombinasi | AI | Memory | Vision | Observability | Chat Round-trip |
|---|---|---|---|---|---|
| A | Local | Gemini | Local | ✅ PASS | ✅ PASS — **65.44s** |
| B | Gemini | Local | Local | ✅ PASS | ✅ PASS — **40.32s** |

| D | Gemini | Gemini | Gemini | ✅ PASS | ✅ PASS — **27.89s** |

**Observasi (untuk Phase 4/9, bukan klaim final):** Kombinasi A (65.44s) jauh lebih lambat dari 3 kombinasi lain (27–41s), padahal Language Local sendirian di Phase 3 cuma mean 11.91s. Kemungkinan karena kombinasi PERTAMA yang dites di sesi itu (cold-start LM Studio pertama kali load model ke VRAM lebih lambat dari run berikutnya) — pola ini konsisten dengan Vision Local yang juga jadi subsystem paling lambat di Phase 3. Bukan bug, tapi karakteristik nyata Local provider di hardware Teacher: run pertama/cold jauh lebih lambat dari run selanjutnya.

**Rekomendasi:** v2.4 **layak diajukan sebagai Decision Gate PASS** ke GPT. Tiga catatan non-blocking yang layak dibawa serta (bukan alasan FAIL, tapi bukan berarti diabaikan):

1. **Vision Local jadi subsystem paling lambat** di Phase 3 (mean 30.72s, max 63.34s) — kalau Teacher berencana pindahkan `VISION_PROVIDER` default ke `"local"` sebagai bagian dari menuntaskan status v2.3, angka ini relevan dipertimbangkan dulu (trade-off privasi/biaya-nol vs kecepatan).
2. **Cold-start Local lebih lambat** dari run berikutnya (terlihat dari Kombinasi A 65.44s vs Language Local baseline 11.91s) — bukan bug, tapi baik diketahui Teacher: run pertama setelah start LM Studio wajar terasa lebih lambat.
3. **Status v2.3** (`VISION_PROVIDER` default `local` vs `gemini`) masih belum diputuskan eksplisit — tidak menghalangi v2.4 PASS (keduanya tetap berfungsi independen), tapi baik diselesaikan sebelum v2.5.
