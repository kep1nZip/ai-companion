# V3.8 — Context-Aware Initiative & Proactive Support

## 0. Milestone Identity

**Version:** v3.8  
**Name:** Context-Aware Initiative & Proactive Support  
**Status:** PLANNED  
**Previous milestone:** v3.7 — Conversational Feedback & Repair Intelligence  
**Primary goal:** Improve Initiative's decision about **whether Arona should proactively speak** by reusing the increasingly rich context evidence built across v3.2–v3.7, while keeping Initiative strictly decision-only.

---

# 1. Why V3.8

The recent milestones have strengthened Arona's context intelligence:

```text
v3.2 → Memory Quality
v3.3 → Contextual Recall
v3.4 → Memory Relevance Ranking
v3.5 → Temporal Awareness & Task Continuity
v3.6 → Response Calibration
v3.7 → Conversational Feedback & Repair
```

However, Initiative has historically had a simpler information set.

V3.8 asks:

> **Given everything Arona currently knows from the existing context systems, is there a meaningful reason to proactively speak now?**

This is not a new generation system.

It is an improvement to the existing **"should Arona speak?"** decision.

---

# 2. Core Principle

V3.8 provides Initiative with **better truthful evidence**.

Initiative may reason from signals such as:

```text
recent unresolved issue
recent conversation anchor
relevant memory
recent closure
recent correction
recent feedback
continuity / idle category
temporal continuity
recent interaction
```

Initiative must NOT become:

```text
response generator
task manager
planner
memory manager
second LLM
conversation critic
```

The division remains:

```text
Initiative
    ↓
Should Arona proactively speak?
    ↓
YES / NO

If YES:
    ↓
Existing autonomous generation flow
    ↓
LLM
    ↓
Arona response
```

# 8. Phase 3 — Recent Unresolved Context

V3.8 should recognize that unresolved issues can be useful reasons for proactive support.

Example:

```text

"Masih error di auth."

[Teacher becomes idle]

Potential Initiative evidence:
recent_unresolved = true
```

This does NOT mean:

```text

```

It means:

> There is a meaningful unresolved topic that may justify proactive support once other Initiative constraints are satisfied.

# 9. Phase 4 — Recent Closure Guard

Explicit closure should act as a **proactivity brake**, especially immediately after the closure.

Examples:

```text
"oke ngerti, makasih"
"udah cukup"
"sip, paham"
```

Possible evidence:

```text
recent_closure = true
```

Expected policy:

```text
recent closure
        ↓
reduce immediate proactive interruption
```

This is not:

```text
conversation_ended = true
```

Closure is evidence, not a permanent state.

---

# 10. Phase 5 — Recent Correction Guard

Recent correction should also reduce premature autonomous interruption.

Example:

```text
Teacher:
"Bukan itu maksudku."
```

Then immediately:

```text
Arona should not aggressively start another unrelated autonomous topic.
```

The current correction should first be handled by the existing conversational path.

V3.8 may use:

```text
recent_correction = true
```

as a temporary brake signal.

Do not create:

```text

```

persistently.
