# AI Companion (Arona)
## v1.5.2 — Auto Vision — Claude Context / Execution Specification

> **Status:** `PLANNED — NOT IMPLEMENTED`

v1.5.2 memperkenalkan **Auto Vision** sebagai kelanjutan resmi dari **Vision Experience v1.5** dan **Capture UX v1.5.1**.

v1.5.2 **boleh menambahkan scheduler Vision baru** karena milestone ini memang secara khusus diperuntukkan untuk fitur Auto Vision.

Namun:

> **Auto Vision adalah scheduler untuk memperbarui `VisionContext`. Auto Vision BUKAN Autonomous Chat.**
>
> **Auto Vision tidak boleh membuat Arona berbicara sendiri.**

# 2. Objective

Implementasikan Auto Vision sehingga Teacher dapat memilih:

- `OFF`
- `MANUAL`
- `AUTO`

dengan behavior berikut.

### OFF

- Tidak ada capture.
- Tidak ada `VisionContext` yang digunakan oleh chat.
- Tidak ada scheduler.

### MANUAL

- Tidak ada scheduler.
- Teacher dapat menggunakan:

```text
[ Capture Now ]
```

### AUTO

- Vision scheduler aktif.
- Vision memperbarui context secara berkala.
- `Capture Now` tetap tersedia.

# 11. Freshness Policy

Auto Scheduler harus menghormati freshness policy.

Namun:

> Scheduler tidak boleh capture setiap 30 detik secara buta jika context masih dianggap valid oleh backend.

Gunakan semantics existing:

```text
VisionContext
    ↓
is_fresh()
```

Jika context masih fresh:

```text
Reuse context.
```

Jika context stale atau belum tersedia:

```text
Capture.
```

---

# 12. Important Distinction: Capture Now

`Capture Now` berbeda dari Auto Scheduler.

### Capture Now

Teacher meminta refresh.

```text
→ force refresh
```

### Auto

Scheduler memeriksa kondisi.

```text
→ refresh hanya jika diperlukan
```

Jadi meskipun context masih fresh:

```text
Capture Now
```

tetap boleh memaksa refresh.

Tetapi:

```text
Auto Scheduler
```

harus menghindari capture yang tidak perlu.

Scheduler **tidak** bertanggung jawab terhadap:

- Gemini prompt;
- Behavior;
- Emotion;
- Routine;
- Initiative;
- Avatar;
- Voice;
- GUI.

# 17. Thread Safety

Ini **WAJIB** diperhatikan.

Sekarang terdapat beberapa kemungkinan caller:

- Manual Capture
- Auto Scheduler
- Chat / `get_context()`

Mereka bisa terjadi bersamaan.

Scheduler tidak boleh menyebabkan:

```text
refresh()
refresh()
```

bersamaan.

Tambahkan mekanisme serialisasi yang aman di Vision.

Misalnya:

```text
_capture_lock
```

atau equivalent.

Tujuannya:

```text
Manual Capture
        \
         → Vision.refresh()
        /
Auto Scheduler
```

tidak boleh menjalankan dua network request bersamaan.

---

# 18. Skip Overlapping Auto Capture

Jika Auto Scheduler ingin capture tetapi Vision sedang melakukan manual capture:

```text
Manual Capture
    ↓
IN PROGRESS

Auto Scheduler
    ↓
SKIP THIS CYCLE
```

Jangan queue puluhan capture.

Jangan menunggu lama hanya untuk kemudian melakukan capture yang sudah tidak relevan.

---

# 19. Recommended Refresh Semantics

Tambahkan internal semantics semacam:

```python
refresh()
```

untuk force capture.

Dan:

```python
refresh_if_needed()
```

untuk scheduler.

Perbedaannya:

```text
refresh()
→ selalu paksa capture

refresh_if_needed()
→ hanya capture jika context tidak fresh
```

Ini merupakan boundary yang sangat berguna agar `Capture Now` dan Auto tidak memiliki semantics yang sama.

---

# 20. Vision OFF Semantics

Ini sangat penting.

v1.5.1 memiliki known limitation:

```text
Capture
 ↓
Context fresh
 ↓
OFF
 ↓
Companion.chat()
```

context lama masih bisa digunakan sampai TTL habis karena toggle hanya berada di GUI.

v1.5.2 harus memperbaiki limitation ini.

Saat:

```python
vision.set_mode(OFF)
```

maka:

1. Scheduler **STOP**
2. Vision menjadi disabled
3. Current `VisionContext` di-invalidasi
4. `get_context()` mengembalikan `None`

Dengan begitu:

> **OFF = benar-benar OFF**

Tidak ada context visual yang tetap dipakai oleh chat setelah OFF.

# 22. Mode Transition

| Transition | Behavior |
|---|---|
| `OFF → MANUAL` | Scheduler tetap berhenti. `Capture Now` enabled. |
| `OFF → AUTO` | Start scheduler. Capture according to policy. |
| `MANUAL → AUTO` | Start scheduler. |
| `AUTO → MANUAL` | Stop scheduler. Tidak ada capture otomatis lagi. `Capture Now` tetap tersedia. |
| `AUTO → OFF` | Stop scheduler. Clear `VisionContext`. Disable Capture. |

# 33. Scheduler Timing

When AUTO starts:

Recommended behavior:

```text
AUTO enabled
 ↓
do NOT immediately capture twice
 ↓
perform first capture according to policy
```

Preferred design:

```text
AUTO ON
 ↓
Capture immediately once
 ↓
wait 30s
 ↓
refresh if needed
 ↓
wait 30s
...
```

This provides immediate usefulness.

However, if an existing fresh context is available:

```text
AUTO ON
 ↓
reuse fresh context
 ↓
wait until next check
```

This avoids unnecessary requests.

# 36. Recommended Signals

If GUI needs live updates, use Qt signals in the worker/UI boundary.

# 37. Error Handling

Auto Vision failure:

- **do not** crash application;
- **do not** disable Auto permanently;
- **do not** spam error dialogs.

Recommended:

```text
log warning
 ↓
keep previous fresh/stale context if appropriate
 ↓
mark capture failure
 ↓
retry at next interval
```

If repeated failures occur, UI may show:

```text
Auto Vision: Last capture failed
```

without modal popups every 30 seconds.

---

# 38. Retry Policy

Do not create exponential-backoff complexity unless necessary.

Simple policy:

```text
capture fails
 ↓
log
 ↓
wait until next scheduled cycle
 ↓
try again
```

Manual `Capture Now` may retry immediately.

---

# 39. Rate Limit / Quota Safety

Auto Vision can generate Gemini Vision requests.

Therefore:

- never capture more frequently than configured interval;
- no duplicate concurrent requests;
- no capture on every chat;
- no capture on page open;
- no capture merely because context was requested;
- no retry loop without delay.

# 47. Scheduler Design

Recommended internal design:

```python

    def __init__(self, refresh_callback, interval_seconds=30):
        ...

    def start(self):
        ...

    def stop(self):
        ...

        ...
```

The scheduler receives a callback or backend method.

It must not:

- instantiate Vision;
- instantiate ScreenCapture;
- instantiate ImageAnalyzer.

---

# 48. Scheduler Implementation Requirements

The scheduler must:

- have one worker/thread at most;
- support clean stop;
- use a stop event;
- avoid busy waiting;
- avoid overlapping captures;
- not import Qt;
- not access GUI;
- not call Gemini directly.

Recommended primitives:

```python
threading.Thread
threading.Event
Lock
```

or equivalent safe standard-library mechanism.

> Do not use a GUI `QTimer` as the backend Vision scheduler if that would make backend behavior depend on Qt.

---

# 49. Capture Coordination

There are two capture sources:

1. Manual `Capture Now`
2. Auto Scheduler

They must share one capture coordination mechanism.

Desired rule:

```text
if capture already running:
    auto cycle skips
```

Manual Capture should remain responsive and should not queue an unlimited backlog.
