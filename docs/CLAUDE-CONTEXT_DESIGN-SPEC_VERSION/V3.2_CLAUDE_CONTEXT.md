## 4. Alasan Setiap Perubahan

### Phase 1+3 — `ai/memory_extractor.py`
**Alasan:** audit membuktikan gap sebenarnya adalah specificity, bukan klasifikasi temporal.
**Perubahan:** 3 paragraf baru di `EXTRACTION_SYSTEM_PROMPT` — contoh eksplisit "aku lagi debugging" (TERLALU SAMAR, jangan simpan) vs "aku lagi debugging backend LeadEstate" (CUKUP SPESIFIK, simpan), plus larangan eksplisit mengarang/memperkaya detail yang tidak disebutkan sumber ("Teacher suka ngoding" TIDAK BOLEH diperkaya jadi "...pakai VS Code" kalau VS Code tidak pernah disebut). Prompt-only, nol schema/logic baru.

### Phase 4 — Keputusan Sengaja Tidak Mengubah Kode
**Alasan:** audit membuktikan mekanisme keyword-match sudah solid untuk 5 dari 7 kategori recall test spec §7; keterbatasan sinonim adalah trade-off inheren dari pendekatan keyword (bukan bug), dan memperbaikinya butuh semantic search/embedding — **dilarang keras** oleh spec. Didokumentasikan sebagai known limitation di audit, nol kode diubah, sesuai instruksi eksplisit ("keep sebagai known limitation kecuali measurement membuktikan perlu").

### Phase 6+7 — `ai/companion.py`, `developer/developer.py`, `ui/developer.py`
**Alasan:** relation (`NEW/DUPLICATE/UPDATE/SUPERSEDES`) sudah dihitung deterministik sejak v2.5, tapi hilang setelah `_persist_fact()` — data yang SUDAH ADA, tinggal dicatat.
**Perubahan:**
- `_persist_fact()` — parameter `history: Optional[list] = None` baru (default `None` = perilaku identik sebelumnya, backward-compat penuh untuk pemanggil lama termasuk test file).
- `Companion._memory_decision_history` / `_recall_decision_history` — rolling window in-memory (limit 30, pola `PerformanceTracker`), **bukan database baru**, hilang saat restart (disengaja).
- `Companion.get_memory_decision_debug_snapshot()` — agregat jujur: candidate/saved/updated/superseded/duplicate/failed count + 10 keputusan terakhir + recall query/result count.
- Dashboard card baru "Memory Decisions" (GUI + markdown export) — read-only, reuse total.

**Tidak ada** field/klaim seperti "LLM used memory successfully" — sesuai larangan eksplisit spec §10.

### Phase 8 — `test_memory_quality_validation.py`
**Alasan:** kategori project/activity/temporary-intent belum ada test coverage-nya.
**Perubahan:** 3 kategori baru (`PROJECT_SPECIFIC_CASES`, `ACTIVITY_VAGUE_CASES`, `TEMPORARY_INTENT_CASES`), diperluas dari file yang sudah ada (bukan file baru), pola identik penambahan `CONTRADICTION_SEQUENCE` sebelumnya. `CaseResult.passed` diperluas menangani 2 kategori baru tanpa mengubah logic 4 kategori lama.
