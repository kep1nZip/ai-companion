# 6. Phase 1 — Conversation Continuity

Arona perlu mempertahankan konteks topik yang sedang aktif.

Contoh:

```text
Teacher:
"Kenapa API-ku error 500?"

Arona:
...

Teacher:
"Kalau pakai async gimana?"
```

Pesan kedua seharusnya dipahami sebagai kelanjutan pembahasan teknis sebelumnya.

Prioritas:

```text
Immediate recent turns
>
Current topic turns
>
Older conversation
```

Jangan membuang recent turns hanya karena memory persistent tersedia.

---

# 7. Phase 2 — Follow-Up Awareness

Pesan seperti:

```text
"Kalau yang ini?"
"Terus?"
"Kenapa?"
"Bisa nggak?"
"Yang tadi maksudku."
```

sering bergantung pada turn sebelumnya.

Gunakan existing conversation history.

Do NOT membuat second LLM hanya untuk menentukan apakah sebuah pesan merupakan follow-up.

---

# 8. Phase 3 — Reference Resolution

Target reference yang umum:

```text
itu
ini
yang tadi
yang pertama
masalah tadi
dia
```

Context terdekat seharusnya tersedia bagi LLM.

Jika referensi benar-benar ambiguous:

```text
Ask clarification.
```

Jangan mengarang referent hanya demi menjawab dengan yakin.

---

# 9. Phase 4 — Topic Shift

Topic shift harus memengaruhi prioritas context, bukan menghapus history.

Contoh:

```text
Topic A
    ↓
Topic B
```

Target:

```text
Current topic = high priority
Old topic = lower priority
```

Persistent Memory tetap terpisah dari Conversation history.

---

# 10. Phase 5 — Conversation Closure

Kenali sinyal seperti:

```text
"Oke makasih."
"Udah ngerti."
"Sip."
"Besok aja lanjut."
"Udahan dulu."
```

Expected:

```text
No forced continuation.
```

Closure signal dapat digunakan untuk membantu Initiative mengambil keputusan.

Namun:

```text
Conversation
→ signal
Initiative
→ decision
```

Jangan membuat Conversation langsung mengontrol Initiative.

---

# 11. Phase 6 — Repetition Reduction

Arona tidak seharusnya terus mengulang:

- saran yang sama;
- pertanyaan yang sama;
- acknowledgment yang sama;
- pembukaan topik yang sama.

Contoh:

```text
Arona:
"Coba restart server."

Teacher:
"Sudah."
```

Respons berikut tidak boleh otomatis mengulang:

```text
"Coba restart server."
```

Gunakan recent conversation sebagai signal.

Jangan membuat response-history database baru.

---

# 12. Phase 7 — Conversation Context Budget

v2.6 sudah memiliki history budget.

v2.8 tidak boleh menghapus atau mengganti mekanisme itu secara sembarangan.

Prioritas konseptual:

```text
Current Teacher Message
        ↓
Immediate previous turns
        ↓
Current topic turns
        ↓
Recent conversation
        ↓
Older conversation
```

Batas akhir harus ditentukan dari baseline nyata.

Jangan menetapkan angka arbitrer tanpa pengukuran.

---

# 13. Phase 8 — Topic-Aware History Selection

Jika history berisi:

```text
A1 A2 A3
B1 B2
C1
D1 D2
```

dan Teacher kembali membahas Topic B, context ideal bisa mengutamakan:

```text
B1
B2
+
latest relevant turns
```

daripada hanya mengambil:

```text
last N messages
```

Tetapi implementation harus dimulai sederhana.

Prioritas teknik:

```text
lexical overlap
recency
explicit follow-up markers
current position
```

Jangan langsung membuat:

```text
embeddings
vector DB
semantic index
```

# 16. Voice/Text Continuity

Voice dan keyboard tetap masuk ke:

```text
same Companion
same Conversation
```

Contoh:

```text
Keyboard:
"Aku mau cerita sesuatu."

Voice:
"Tadi yang aku maksud adalah..."
```

Context harus tetap tersedia lintas modalitas.

---

# 17. Vision Interaction

Vision memberikan environmental context.

Contoh:

```text
Conversation:
Teacher sedang membahas coding.

Vision:
VS Code sedang terbuka.
```

Vision dapat membantu response.

Namun:

```text
Vision ≠ conversation authority
```

Freshness rules v2.6 tetap wajib dipatuhi.

---

# 18. Memory Interaction

Memory adalah persistent fact.

Conversation adalah immediate discussion context.

Jangan menyamakan keduanya.

Contoh:

```text
Conversation:
Teacher sedang membahas React.

Memory:
Teacher pernah mengerjakan project tertentu.
```

Memory hanya masuk jika relevan.

Superseded memory tidak boleh diperlakukan sebagai current fact.

---

# 19. Relationship / Emotion

Relationship dan Emotion tetap berada di Behavior architecture.

Conversation Intelligence boleh menentukan bahwa tone/context tertentu lebih relevan, tetapi tidak boleh mengambil alih logic:

```text
BehaviorEngine
Emotion
Relationship
```

Tidak membuat duplicate state.

# 29. Decision Gate

## PASS

v2.8 PASS apabila:

- [ ] Follow-up conversations remain coherent.
- [ ] Topic shifts are handled naturally.
- [ ] Recent references are resolved better.
- [ ] Ambiguity does not produce confident hallucination.
- [ ] Conversation closure is respected.
- [ ] Repetition is reduced.
- [ ] History remains bounded.
- [ ] Internal context remains clean.
- [ ] Active/superseded memory behavior remains correct.
- [ ] Local provider works.
- [ ] Gemini provider works.
- [ ] Voice/Text share the same conversation.
- [ ] Autonomous interaction remains stable.
- [ ] GUI remains responsive.
- [ ] No critical regression exists.

## CONDITIONAL PASS

Allowed when:

- some topic edge cases remain;
- some references are ambiguous;
- history selection needs future tuning;
- overall conversational quality remains acceptable.

Document all limitations.

## FAIL

FAIL apabila:

- Recent context is systematically lost.
- Old irrelevant history dominates.
- Topic shifts are consistently mishandled.
- Closure causes forced conversation.
- Repetition increases.
- Internal context leaks.
- An additional LLM classification pipeline is introduced without justification.
- Companion/ContextBuilder boundaries are broken.
- Critical regression appears.
