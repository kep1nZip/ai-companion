# V3.3 — Contextual Recall & Reference Intelligence

## Status

**Planned**

V3.3 melanjutkan fondasi:

```text
v3.0 → Adaptive Companion Intelligence & Personalization
v3.1 → Adaptive Presence & Natural Conversation
v3.2 → Memory Precision & Recall Intelligence
```

Fokus V3.3:

> Membuat Arona lebih tepat memahami referensi dan kesinambungan konteks seperti “yang tadi”, “lanjut yang kemarin”, “project yang mana?”, atau “yang barusan aku bilang”, tanpa membuat arsitektur conversation menjadi kompleks.

Prinsip:

```text
Reuse existing systems > create new systems
Current context > unrelated old context
Clarification > confident guessing
Measure before adding intelligence
Smallest safe change
```

---

# 1. Tujuan Utama

V3.3 bertujuan meningkatkan kemampuan Arona untuk menghubungkan:

```text
Current Teacher Message
        ↓
Recent Conversation
        ↓
Conversation Anchor
        ↓
Relevant Memory
        ↓
ContextBuilder
        ↓
Local / Gemini
        ↓
Coherent Response
```

Contoh:

```text
Teacher:
"Aku lagi debugging backend LeadEstate."

Arona:
"Semangat, Teacher."

Teacher:
"lanjut yang tadi"

Arona:
"Backend LeadEstate yang tadi, ya?"
```

Contoh ambiguous:

```text
Teacher:
"Aku lagi ngerjain LeadEstate dan project Arona."

Teacher:
"lanjut yang tadi"

Arona:
"Yang Teacher maksud LeadEstate atau project Arona?"
```

Target utama bukan membuat Arona lebih sering menjawab, tetapi membuat respons terhadap referensi menjadi lebih tepat.

# 4. Phase 1 — Conversation Anchor Detection

## Tujuan

Identifikasi anchor yang sedang aktif tanpa membuat semantic engine besar.

Conceptual anchor:

```text
project
activity
topic
entity
preference
current task
recent subject
```

Contoh:

```text
Teacher:
"Aku lagi debugging backend LeadEstate."

Possible anchor:
project = LeadEstate
activity = debugging
subject = backend
```

Anchor bukan persistent memory.

Anchor adalah:

```text
short-lived conversation signal
```

---

# 5. Anchor Rules

Anchor detection harus memprioritaskan existing information:

```text
current message
recent turns
existing memory relevance
existing project/activity memory
vision context jika fresh
```

Jangan mengubah setiap noun menjadi anchor.

Target:

```text
Useful anchor
≠
every keyword
```

Jika tidak ada anchor yang cukup kuat:

```text
anchor = None
```

dan sistem tetap menggunakan behavior lama.

---

# 6. Phase 2 — Follow-up / Reference Resolution

Target phrase:

```text
"yang tadi"
"yang barusan"
"lanjut yang kemarin"
"itu"
"ini"
"yang pertama"
"project tadi"
"masalah tadi"
"yang sebelumnya"
```

Reference harus dicoba resolve menggunakan:

```text
current message
+
recent conversation
+
active anchor
+
relevant memory if necessary
```

Jangan langsung melakukan memory search untuk setiap pesan.

Urutan default:

```text
Immediate conversation
        ↓
Active anchor
        ↓
Relevant persistent memory
```

Conversation harus tetap menjadi sumber utama untuk reference yang jelas-jelas menunjuk pada percakapan baru.

---

# 7. Phase 3 — Contextual Memory Query

Jika reference membutuhkan persistent context:

```text
Teacher:
"lanjut project yang kemarin"
```

gunakan anchor/query yang telah diekstrak dari conversation:

```text
"project backend LeadEstate"
```

lalu reuse:

```text
_select_relevant_memories(query)
```

Jangan membuat recall engine kedua.

---

# 8. Recall Priority

Default priority:

```text
Current message
        >
Immediate previous turns
        >
Active conversation anchor
        >
Recent relevant memory
        >
Older relevant memory
        >
Unrelated memory
```

Ini mencegah memory lama mengalahkan konteks percakapan yang baru saja terjadi.

---

# 9. Phase 4 — Ambiguity Handling

Jika ada lebih dari satu candidate yang masuk akal:

```text
Candidate A
Candidate B
```

Arona **tidak boleh memilih secara arbitrary**.

Expected:

```text
Clarification
```

Contoh:

```text
Teacher:
"Aku punya LeadEstate dan project Arona."

Teacher:
"lanjut yang tadi"

Arona:
"Yang Teacher maksud LeadEstate atau project Arona?"
```

Clarification harus singkat dan natural.

---

# 10. Confidence / Ambiguity Boundary

Jika resolution confidence rendah:

```text
DO NOT GUESS
```

Tidak boleh:

```text
ambiguity
↓
random candidate
↓
confident response
```

Target:

```text
uncertainty
↓
clarification
```

Tidak perlu confidence score baru jika existing data tidak mendukung angka yang meaningful.

Gunakan state sederhana bila cukup:

```text
RESOLVED
AMBIGUOUS
UNRESOLVED
```

Bahkan enum/state baru hanya boleh dibuat jika audit menunjukkan dibutuhkan oleh API.

---

# 11. Phase 5 — Topic / Anchor Continuity

Active anchor dapat berubah secara natural:

```text
Topic A
   ↓
Topic B
   ↓
Topic A kembali
```

Contoh:

```text
Teacher:
"Kenapa API error?"

...

Teacher:
"Ngomong-ngomong avatar Arona gimana?"

...

Teacher:
"Balik ke API tadi, kalau async?"
```

Expected:

```text
Arona dapat kembali memahami Topic A
```

tanpa menganggap Topic B sebagai satu-satunya context permanen.

---

# 12. Phase 6 — Memory vs Conversation Boundary

V3.3 harus mempertahankan:

```text
Conversation
→ immediate context

Memory
→ persistent context
```

Contoh:

```text
Conversation:
"tadi kita bahas backend."

Memory:
"Teacher mengerjakan LeadEstate."
```

Keduanya dapat membantu reference resolution, tetapi jangan otomatis mengubah conversation fragment menjadi memory.

Jangan membuat:

```text
every conversation anchor
→ saved memory
```

---

# 13. Phase 7 — Vision-assisted Reference

Vision boleh membantu jika reference berhubungan dengan layar saat ini.

Contoh:

```text
Teacher:
"yang ini error"

Recent conversation:
sedang membahas coding

Fresh Vision:
VS Code + error dialog
```

Vision dapat menjadi supporting context.

Namun:

```text
Vision
≠
authority
```

Stale Vision tetap mengikuti freshness policy.

Vision OFF harus tetap menghasilkan behavior yang valid.

---

# 14. Phase 8 — Initiative Interaction

Reference intelligence dapat memberikan signal ke Initiative ketika relevan.

Contoh:

```text
Teacher kembali setelah idle
+
conversation anchor masih aktif
+
relevant unresolved thread
```

Ini dapat menjadi signal bahwa interaction opportunity lebih meaningful.

Tetapi:

```text
Reference Intelligence
→ signal

Initiative
→ decision
```

Jangan membuat Reference Intelligence memulai autonomous response secara langsung.

```text
LLM call per reference
```

```text
existing conversation
+
deterministic/lightweight signals
+
existing memory search
+
one main language-model generation
```

Measure:

```text
reference detection latency
memory query latency
context assembly latency
LLM latency
```

Jika added complexity tidak memberikan quality improvement yang jelas:

```text
reject the optimization.
```

# 22. Stop Conditions

Claude **MUST stop dan report** jika:

1. Reference resolution membutuhkan LLM kedua pada setiap turn.
2. Conversation DB baru dianggap diperlukan.
3. Vector DB / RAG dianggap wajib.
4. ContextBuilder harus menjadi orchestrator.
5. MemoryManager harus diganti.
6. Voice/Autonomous memerlukan conversation history terpisah.
7. Provider-specific reference logic muncul.
8. Anchor harus dipersistenkan tanpa design eksplisit.
9. Ambiguity tidak dapat diselesaikan tanpa membuat sistem kompleks.
10. Quality regression lebih besar daripada manfaat reference intelligence.

# 23. Decision Gate

## PASS

V3.3 PASS apabila:

- clear references dapat di-resolve secara konsisten;
- ambiguous references meminta clarification;
- topic continuity tidak rusak;
- return to older topic tetap mungkin;
- relevant memory digunakan ketika diperlukan;
- irrelevant/superseded memory tidak mengambil alih;
- Vision membantu hanya ketika fresh/relevant;
- Voice/Text tetap satu Conversation;
- Local bekerja;
- Gemini bekerja;
- Initiative boundaries tetap benar;
- ContextBuilder tetap assembly-only;
- Developer observability truthful;
- GUI tetap responsif;
- tidak ada critical regression.

## CONDITIONAL PASS

Dapat digunakan apabila:

- beberapa reference natural-language masih ambiguous;
- synonym recall masih terbatas;
- sebagian anchor belum dapat diekstrak dengan deterministic rules;
- behavior tetap acceptable dan limitation terdokumentasi.

## FAIL

FAIL apabila:

- Arona sering menebak reference yang salah;
- ambiguity justru meningkatkan hallucination;
- old topic mendominasi current topic;
- memory irrelevant masuk sebagai reference utama;
- second LLM muncul tanpa justifikasi;
- architecture boundaries rusak;
- critical regression muncul.

# 25. Expected Implementation Philosophy

V3.3 seharusnya terasa seperti:

```text
Existing Conversation
+
Existing Memory
+
Existing ContextBuilder
+
small reference signals
```

bukan:

```text
New AI reasoning engine
```

Prioritas:

```text
Conversation context
>
Simple deterministic signal
>
Existing memory relevance
>
LLM
```

Dengan demikian LLM tetap menjadi komponen utama untuk memahami bahasa natural, sedangkan application layer hanya membantu menyediakan context yang tepat dan menjaga ambiguity.

# 26. Final Principle

V3.3 bukan:

```text
"buat Arona mengingat semua hal."
```

bukan juga:

```text
"buat Arona menebak maksud Teacher."
```

V3.3 adalah:

```text
"buat Arona lebih tepat menghubungkan
apa yang Teacher katakan sekarang
dengan konteks yang memang relevan."
```

Core principles:

```text
Conversation > memory for immediate references
Relevant memory > random memory
Clarification > guessing
Fresh Vision > stale Vision
Current topic > old topic
Existing architecture > new infrastructure
Measure > speculate
```
