## 1. Purpose

v2.2.2 berfokus pada **validasi kualitas dan stabilitas Local Memory Extraction** setelah implementasi v2.2 dan hotfix v2.2.1.

Fokus milestone ini bukan menambah arsitektur baru, melainkan memastikan bahwa:

- Local Memory Extraction menghasilkan memory yang masuk akal.
- Instruksi anti-hedging dari v2.2.1 bekerja dengan benar.
- Performa chat tetap responsif ketika extraction berjalan di background.
- Provider Gemini dan Local sama-sama dapat diuji melalui konfigurasi yang sama.
- Developer Dashboard menampilkan provider yang sedang digunakan dengan benar.
- Masalah contradiction/supersession tetap dicatat sebagai issue yang belum diselesaikan, bukan diam-diam dianggap selesai.

## 3. Kondisi Dasar Sistem

Arsitektur memory saat ini:

```text
Teacher message
      ↓
Companion.chat()
      ↓
MemoryExtractionWorker
      ↓
MemoryExtractor
      ↓
LanguageModelProvider
      ├── GeminiProvider
      └── LocalProvider
      ↓
JSON memory candidates
      ↓
MemoryManager
      ↓
SQLite memory.db
```

Extraction berjalan asynchronous melalui:

```text
threading.Thread(daemon=True)
queue.Queue
```

Satu worker digunakan untuk memproses memory extraction secara serial.

## 9. Known Issue

### 9.1 Memory Contradiction / Supersession

Masalah:

```text
Suka americano
↓
Tidak suka americano lagi
```

saat ini dapat menjadi dua memory terpisah.

Root cause:

`MemoryExtractor.extract()` saat ini terutama bekerja berdasarkan pesan Teacher saat ini dan tidak diberi pengetahuan eksplisit tentang memory lama yang mungkin bertentangan.

Sementara `MemoryManager.save_memory()` melakukan deduplication berdasarkan kecocokan yang ada, bukan semantic supersession.

### Status

```text
Known Issue
Not solved in v2.2.2
```

### Kandidat solusi masa depan

Pendekatan yang pernah dipetakan:

1. Presentation-only ordering/marking berdasarkan `updated_at`.
2. Extraction dengan related existing memories dan marker seperti `supersedes_id`, lalu MemoryManager melakukan replacement.
3. Menunda implementasi sampai lebih banyak data real-world tersedia.

v2.2.2 **tidak memilih salah satu pendekatan tersebut secara otomatis**.

## 12. Decision Gate

### PASS

v2.2.2 dapat ditutup sebagai **Accepted** apabila:

- Gemini baseline tetap stabil.
- Local extraction bekerja untuk explicit facts.
- Hedged statements tidak lagi menjadi confirmed memory.
- Noise tidak banyak menghasilkan false positive.
- GUI tetap responsif.
- Tidak ada regression penting.
- Known issue contradiction telah didokumentasikan.

### CONDITIONAL PASS

Boleh diterima dengan catatan apabila:

- Local quality belum sempurna tetapi masih usable.
- Ada beberapa false positive/negative yang perlu monitoring.
- Contradiction masih unresolved.

Dalam kondisi ini, contradiction tetap dicatat sebagai backlog.

### FAIL

Milestone belum dapat diterima apabila:

- Local Provider sering crash.
- JSON extraction tidak stabil.
- Hedged statements kembali tersimpan sebagai confirmed facts.
- GUI freeze karena extraction.
- Worker menyebabkan aplikasi gagal shutdown.
- Ada regression penting.
