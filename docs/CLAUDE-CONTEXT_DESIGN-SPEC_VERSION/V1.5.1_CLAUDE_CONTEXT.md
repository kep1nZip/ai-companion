# Apa yang diminta (dari ChatGPT pemandu)

v1.5.1 = refinement **Vision Capture UX + Manual Refresh** di atas Vision Experience v1.5 yang sudah ada.

Prinsip utama:

- Manual Capture tetap menjadi mode utama.
- Tambahkan **Capture Now** sebagai aksi eksplisit untuk memaksa `Vision.refresh()`.
- Capture Now tetap tersedia ketika Vision ON.
- Capture tidak boleh terjadi otomatis hanya karena chat atau halaman Vision dibuka.
- Fresh `VisionContext` tetap dipakai ulang oleh chat.
- Jangan membuat scheduler Vision baru.
- Jangan mengimplementasikan Auto Vision.
- Jangan mengubah `vision/*`, `ai/companion.py`, atau `ai/context_builder.py` kecuali inspection membuktikan blocker nyata.
- Jangan membuat screenshot preview atau menyimpan screenshot.
- Gunakan `VisionWorker` yang sudah ada dari v1.5.
- GUI harus tetap responsif selama capture/network call.
- Jangan membuat backend state machine kedua hanya demi presentation state UI.
- Jika Auto diminta, perlakukan sebagai milestone/spec terpisah (v1.6+), bukan kelanjutan kecil v1.5.1.

Design Spec secara eksplisit menyatakan bahwa v1.5.1 **bukan Vision System v2 dan bukan Auto Vision implementation**.

# Fakta penting dari inspeksi/spec v1.5.1

## 1. AUTO memang belum ada dan sengaja ditunda

Vision saat ini:

```text
Vision
├── OFF / ON → GUI-only state
├── Manual mode → tersedia
├── Capture Screen → tersedia
└── AUTO → BELUM ADA
```

Tidak ada scheduler Vision existing yang aman untuk direuse.

Alasan penundaan Auto:

- tidak ada scheduler Vision existing;
- `IdleScheduler` adalah milik Avatar;
- `RoutineScheduler` adalah milik Routine;
- membuat scheduler baru berarti architecture addition;
- `Vision.refresh()` adalah blocking/network-bound.

Kesimpulan: **jangan membuat VisionScheduler, AutoVisionManager, timer polling, atau scheduler baru di v1.5.1.**

## 2. `Vision` tidak memiliki enable/disable backend

`Vision` tidak memiliki:

- `enable()`
- `disable()`
- `is_enabled`

ON/OFF yang digunakan GUI tetap merupakan state presentation/control lokal.

Konsekuensinya sudah diketahui: toggle OFF mencegah **capture baru dari GUI** karena tombol Capture Now dinonaktifkan, tetapi tidak menghapus context lama yang masih fresh di dalam `Companion`.

Jangan memperbaiki behavior tersebut secara diam-diam dengan mengubah `Companion.chat()`.

## 3. Capture baru tetap aksi eksplisit

Flow capture:

```text
Teacher
  ↓
Vision GUI
  ↓
Capture Now
  ↓
VisionWorker
  ↓
Companion.capture_vision()
  ↓
Vision.refresh()
  ↓
VisionContext
```

`Capture Now` berarti:

```text
Paksa Vision.refresh() sekarang.
```

Bukan:

```text
start scheduler
enable continuous vision
capture only when stale
capture on every chat
```

Walaupun context masih fresh, klik Capture Now **tetap melakukan refresh baru** karena Teacher mungkin sengaja ingin Vision melihat kondisi layar terbaru.

## 4. Chat tetap reuse context dan tidak melakukan capture

Flow chat tidak berubah:

```text
Teacher
  ↓
Companion.chat()
  ↓
Vision.get_context()
  ↓
ContextBuilder
  ↓
Gemini
  ↓
Arona
```

Jika context masih fresh:

```text
No new capture.
Reuse existing context.
```

Jika context stale:

```text
No automatic capture.
```

Chat tidak boleh menjadi trigger capture baru.

Membuka halaman Vision juga tidak boleh melakukan capture.

# Yang sudah diimplementasikan

## 1. `ui/vision.py` — diperbarui

Claude mengidentifikasi empat gap UX nyata pada implementasi v1.5:

1. Tombol belum berubah teks menjadi `Capturing...` saat capture berjalan.
2. `showEvent()` / `_render()` dapat salah me-re-enable tombol ketika user pindah halaman lalu kembali saat capture masih berjalan.
3. Label tombol masih `📷 Capture Screen`, sedangkan spec v1.5.1 meminta `Capture Now`.
4. Wording freshness belum menggunakan format `Fresh — N seconds old` / `Stale — N seconds old` / `No Vision Context`.

Perbaikan aktual:

### `_is_capturing`

Ditambahkan:

```python
self._is_capturing = False
```

State ini sengaja dipisahkan dari `_enabled`.

Tujuannya adalah memastikan UI tahu bahwa ada capture yang masih in-flight, walaupun `_render()` dipanggil dari `showEvent()`, toggle, atau event lain.

### Capture Now

Tombol sekarang:

```text
Capture Now
```

dan tetap menjadi jalur manual utama.

### Capturing state

Saat capture berjalan:

```text
Capturing...
```

Tombol disabled.

Klik berulang selama worker masih berjalan langsung diabaikan.

Setelah result/error:

```text
Capture Now
```

aktif kembali.

### Freshness wording

Jika context tersedia:

```text
Fresh — N seconds old
```

atau:

```text
Stale — N seconds old
```

Jika belum ada context:

```text
No Vision Context
```

Age diambil dari `VisionContext.age_seconds()`.

Tidak ada TTL baru yang dibuat.

### Vision OFF

Saat OFF:

```text
Vision: ○ OFF

Vision is off. No new capture will be taken.

[ Capture Now ]  disabled
```

Saat ON:

```text
Vision: ● ON

[ Capture Now ]
```

### Mode

Mode tetap ditampilkan sebagai teks statis:

```text
Manual (only mode currently available)
```

Tidak ada dropdown Auto.

Ini disengaja karena Auto belum berfungsi dan UI tidak boleh memberikan pilihan fiktif.

### Capture failure

Tetap satu pesan generik:

```text
Vision capture failed. Please try again.
```

Tidak dibuat dua kategori error karena backend Vision memang tidak memberikan informasi yang cukup kepada GUI untuk membedakan capture failure dan analysis failure.

### Tidak ada screenshot preview

GUI hanya menggunakan data structured/public dari `VisionContext`:

- `summary`
- `application`
- `timestamp`
- `age`
- `ttl`
- `is_fresh`

Private screenshot data seperti `_last_captured_image` tidak disentuh untuk display.

# Detail arsitektur yang HARUS dipertahankan

## Capture path

`ui/vision.py` tidak membuat Vision backend baru.

Ia menggunakan:

```text
self._companion
    ↓
Companion.capture_vision()
    ↓
Vision.refresh()
```

Worker yang digunakan adalah `ui/vision_worker.py` existing dari v1.5.

Tidak boleh membuat:

- `Vision` instance kedua;
- `ScreenCapture` kedua;
- `ImageAnalyzer` kedua;
- worker kedua khusus Vision;
- scheduler baru.

## Normal chat path

Tetap:

```text
Companion.chat()
    ↓
Vision.get_context()
    ↓
ContextBuilder
    ↓
Gemini
```

Jangan mengubah behavior menjadi:

```text
Companion.chat()
    ↓
Vision.refresh()
```

Itu akan mengubah capture policy dan berada di luar scope v1.5.1.

# Capture State vs Backend State

Design Spec meminta UI mampu membedakan state seperti:

- Ready
- Capturing
- Analyzing
- Fresh
- Stale
- Failed
- Vision Off

Namun ini **bukan izin untuk membuat backend state machine kedua**.

Pada implementasi aktual v1.5.1, granular state `Capturing...` terutama merupakan presentation state berdasarkan `_is_capturing` dan lifecycle worker.

Jangan menambahkan state machine backend hanya untuk memenuhi tampilan UI.

# Deviasi / keputusan desain yang disengaja

## 1. Tidak ada Auto Mode

Ini bukan fitur yang lupa dibuat.

Auto secara eksplisit deferred.

Jika user meminta Auto, buat pembahasan/spec milestone baru, bukan modifikasi diam-diam terhadap v1.5.1.

## 2. Tidak ada dropdown Auto

Design Spec mengizinkan struktur:

```text
Mode
● Manual
○ Auto (Coming Soon)
```

tetapi juga secara eksplisit menyarankan teks statis:

```text
Mode: Manual
```

jika "Coming Soon" mengganggu UX.

Implementasi memilih pendekatan teks statis:

```text
Manual (only mode currently available)
```

## 3. Tidak ada screenshot preview

Tidak mengambil atau menyimpan screenshot hanya demi preview GUI.

Context yang sudah diproses tetap menjadi source untuk UI.

## 4. Tidak ada Vision history database

Jangan membuat:

- `VisionHistoryManager`
- `VisionDatabase`
- `VisionCaptureTable`

Untuk v1.5.1 cukup current context + timestamp/age.

## 5. Tidak ada automatic capture berdasarkan freshness

Stale context tidak menyebabkan capture otomatis.

Fresh context juga tidak menghalangi tombol Capture Now.

# Known limitation

## Toggle OFF tidak menghapus context lama yang masih fresh

Ini limitation yang sudah diketahui dari v1.5 dan sengaja tidak diperbaiki di v1.5.1.

Skenario:

```text
Capture
  ↓
Context masih fresh
  ↓
Teacher OFF
  ↓
Companion.chat()
```

`Companion.chat()` masih dapat menggunakan context lama sampai TTL habis karena toggle ON/OFF adalah GUI-side dan `Companion` tidak mengetahui status GUI tersebut.

Design Spec secara eksplisit meminta limitation ini **jangan diperbaiki dengan mengubah `Companion.chat()` otomatis**.

Jika user ingin:

```text
OFF = immediate hard block
```

perlakukan sebagai design milestone terpisah karena membutuhkan perubahan backend architecture.

# Acceptance Criteria v1.5.1

Manual Capture:

- `Capture Now` exists.
- `Capture Now` works when Vision ON.
- `Capture Now` disabled when Vision OFF.
- Capture cannot be triggered concurrently.
- Capture result updates `VisionContext`.
- Freshness display updates.

Context Reuse:

- Fresh context reused by normal chat.
- Opening Vision page does not capture.
- Chat does not automatically capture.
- Stale context does not trigger implicit capture.

Privacy:

- Vision OFF prevents new capture.
- Vision status remains visible.
- No screenshot stored.
- No screenshot logged.

Regression target:

- Chat
- Memory
- Voice
- Avatar
- Vision
- Routine
- Initiative
- Settings
- Developer Tools

# Instruksi untuk sesi Claude berikutnya

1. **Anggap v1.5.1 sudah diimplementasikan secara kode, tetapi belum otomatis dianggap runtime-verified.** Tanyakan/cek terlebih dahulu apakah user sudah menjalankan dan mengetesnya.

2. **Jangan mengimplementasikan Auto Vision sebagai "bug fix".** Auto adalah milestone terpisah dan membutuhkan desain scheduler yang aman.

3. Jika user melaporkan capture bermasalah, cek urutan berikut:
   - Vision ON?
   - tombol berubah menjadi `Capturing...`?
   - worker berjalan?
   - `Companion.capture_vision()` dipanggil?
   - `Vision.refresh()` menghasilkan context?
   - kartu freshness/context berubah?

4. Jika user melaporkan Arona tidak menyebut visual context, jangan langsung mengubah Vision GUI. Pastikan dulu capture berhasil dan `VisionContext` fresh serta memiliki `summary`/`application`.

5. Jika user meminta OFF benar-benar menghapus/block context lama, jelaskan bahwa itu membutuhkan perubahan terhadap `Companion`/backend policy dan bukan refinement UI kecil.

6. Jika user meminta Auto, buat/spec-kan milestone baru (v1.6+) terlebih dahulu.

7. Jika user meminta screenshot preview, jangan mengambil `_last_captured_image` private secara sembarangan. Itu membutuhkan keputusan privacy/storage baru.

8. **Jangan membuat instance Vision/ScreenCapture/ImageAnalyzer kedua.** Reuse instance yang sudah dimiliki oleh `Companion`.

9. **Jangan membuat screenshot persistence.** Jangan menyimpan bytes, base64, path screenshot, atau screenshot history.

10. **Jangan mengubah `Companion.chat()` agar capture otomatis.** Normal chat tetap reuse `get_context()`.

11. Architecture Freeze Policy dari v1.0 tetap berlaku untuk subsystem di luar scope GUI.

12. Pola established dari v1.1-v1.5 tetap berlaku:
    - constructor injection/reuse instance;
    - `QStackedWidget` untuk page switching;
    - append-only styling bila menambah CSS;
    - worker hanya jika blocking/network-bound call memang membutuhkan background thread;
    - jangan mengarang backend state/API yang tidak ada;
    - jangan mengarang error detail yang tidak diberikan backend.

13. User berkomunikasi dalam Bahasa Indonesia; kode dan komentar teknis boleh menggunakan English.

# Final architectural rule

```text
MANUAL FIRST.

Capture Now = explicit action.

Fresh context = reuse.

Chat ≠ capture trigger.

Opening Vision page ≠ capture trigger.

OFF = no new GUI capture.

No automatic scheduler.

No screenshot persistence.

No fake backend API.

No second Vision instance.

Auto = future milestone/spec.
```

v1.5.1 selesai pada level **implementasi UX yang diminta**, tetapi status **DONE & VERIFIED** baru boleh digunakan setelah runtime verification di environment user benar-benar dikonfirmasi.
