## 1. Apa Project Ini

AI Waifu Companion desktop app, terinspirasi Arona (Blue Archive). Bukan sekadar chatbot — dirancang modular supaya bisa berkembang jadi companion dengan voice, avatar Live2D, memory, emosi, dll.

**Prinsip pengembangan:** incremental, per-milestone, jangan lompat fitur, jangan overengineering, jangan redesign arsitektur tanpa alasan kuat.

**Filosofi inti:** Desktop GUI **bukan** aplikasinya. Aplikasi sesungguhnya adalah `Companion`. GUI, Voice, Avatar (+animasinya), dan Behavior Engine hanyalah layer di sekitar `Companion`:

```
Teacher
  ↓
Conversation
  ↓
Emotion Analyzer ──┐
Relationship Analyzer ──┤
Internal State Rules ───┴→ Behavior Engine → BehaviorState (single source of truth, skeleton, BELUM terhubung ke Companion)
  ↓ (rencana v0.6.5)
Companion (+ Memory + waktu + nanti BehaviorState) → Gemini → reply (str)
  ↓
GUI chat bubble │ TTS → AudioPlayer + Lip Sync │ HaloMapper → Hotkey ekspresi │ Idle Animation
```

**Human-in-the-Loop Memory Policy (v0.3):** Memory milik Teacher. **Avatar Independence Policy (v0.5):** avatar cuma me-render reaksi visual, opsional. **Animation Independence Policy (v0.5.1/v0.6.1):** layer animasi independen digabung `AvatarManager`. **Behavior Engine Policy (v0.6.0):** Behavior Engine cuma menghasilkan state, tidak pernah bahasa/kontrol langsung. **Emotion Transition Policy (v0.6.2):** emosi = state machine yang bergerak. **Relationship Base/Current Policy (v0.6.3):** tiap dimensi relationship punya `base` (manual) & `current` (otomatis) terpisah. **BehaviorState Single Source of Truth Policy (v0.6.4, BARU, rekomendasi GPT):** `BehaviorState` sekarang cuma berisi **3 blok besar** — `emotion: EmotionState`, `relationship: RelationshipState`, `internal: InternalState` (gabungan Mood+Energy+Curiosity+Initiative) — bukan field pipih satu-satu. Kalau nanti mau nambah dimensi baru (Stress, Confidence, Focus), cukup nambah field di `InternalState`, `BehaviorState` itu sendiri **tidak perlu berubah**. Tujuannya: mulai v0.6.5, semua sistem lain (PromptBuilder, Avatar, Voice, Vision, Routine System) cukup baca `BehaviorState` sebagai satu objek utuh, tanpa perlu tahu detail implementasi tiap subsystem di baliknya.

## 4. Arsitektur (WAJIB Dipertahankan)

```
Terminal (main.py)     Desktop GUI (main_gui.py + ui/window.py)
        │                              │
        └──────────────┬───────────────┘
                        ↓
                   Companion (ai/companion.py)   ← BELUM terhubung ke BehaviorEngine
                        ↓
     ┌──────────────────┼──────────────────┐
     ↓                  ↓                  ↓
Conversation       MemoryManager       GeminiClient
                        ↓
                     memory.db  ← nyimpen Relationship state DAN Internal State (kategori "general" + marker masing-masing)

Voice/Avatar/Lip Sync/Idle Animation: TIDAK BERUBAH sejak v0.6.1.

BehaviorEngine.update(user_input, reply):
    emotion_state = EmotionCoordinator.process_message(user_input)
    relationship_state = RelationshipCoordinator.process_message(user_input, emotion_state=emotion_state)
    internal_state = InternalStateCoordinator.process_message(user_input, emotion_state=emotion_state, relationship_state=relationship_state)
    → BehaviorState(emotion=emotion_state, relationship=relationship_state, internal=internal_state)
      [3 BLOK BESAR, single source of truth — rekomendasi GPT]

InternalStateCoordinator.process_message() secara internal:
   1. propose_mood(emotion_window, energy.value) -> MoodProposal   [butuh streak 3 emosi searah berturut-turut]
   2. apply_mood(current_mood, proposal) -> Mood baru
   3. compute_energy_delta(mood, elapsed) -> delta energy (biaya ngobrol vs pemulihan idle)
   4. compute_curiosity_delta(user_input) + compute_curiosity_decay(elapsed) -> delta curiosity
   5. compute_initiative_delta(energy, curiosity, relationship_state, idle_seconds) -> delta initiative
   6. InternalStateHistory.record() + save() ke MemoryManager

BehaviorEngine MASIH BELUM dipanggil dari Companion/ui manapun — terisolasi sampai v0.6.5.
```

**Aturan besi (v0.1–v0.6.3, tetap berlaku penuh):** `Companion`/`VoiceManager`/`AvatarManager` masing-masing satu-satunya koordinator domainnya. UI Independence. Conversation vs Memory tidak dicampur. Emotion Arona ≠ Emotion Teacher. Analyzer manapun (Emotion/Relationship/Internal) tidak boleh panggil Gemini. Persistence behavior data lewat method publik `MemoryManager`, bukan tabel baru.

**Aturan besi BARU v0.6.4 — Internal State & BehaviorState Restructuring:**
- **`BehaviorState` cuma punya 3 field state**: `emotion`, `relationship`, `internal` (+ `timestamp`) — **JANGAN** tambah field pipih baru langsung ke `BehaviorState` untuk dimensi behavior apa pun. Dimensi baru (Stress, Confidence, Focus, dll) HARUS masuk sebagai field baru di `InternalState`, bukan di `BehaviorState`.
- **Mood TIDAK instan mengikuti Emotion** — `propose_mood()` butuh **streak 3 emosi searah berturut-turut** (positif atau negatif) sebelum mengusulkan pergeseran mood, sesuai spec "Mood does not instantly follow Emotion". Energi sangat rendah (≤20) override langsung ke `SLEEPY` tanpa perlu streak.
- **Energy berkurang dari "biaya ngobrol", pulih dari waktu idle** — `compute_energy_delta()` selalu punya base cost negatif tiap `process_message()`, dikompensasi recovery berbasis `elapsed_seconds()`. Mood Cheerful/Relaxed mempercepat recovery (State Interaction dari spec).
- **Curiosity naik dari kata kunci pertanyaan/hal baru, meluruh pasif seiring waktu** — dua komponen delta terpisah (`compute_curiosity_delta` untuk sinyal aktif, `compute_curiosity_decay` untuk peluruhan pasif) dijumlah jadi satu delta per pesan.
- **Initiative HANYA disimpan nilainya di v0.6.4 — TIDAK memicu autonomous chatting apa pun** — sesuai spec eksplisit "Current milestone only stores the value. No autonomous chatting." `idle_seconds` yang tinggi ikut menaikkan initiative, tapi tidak ada trigger aksi apa pun.
- **`Relationship` tidak pernah langsung mengubah `Mood`** — Relationship cuma memengaruhi `Initiative` (Trust tinggi → initiative naik sedikit, Comfort rendah → initiative turun sedikit), sesuai spec "Relationship does not directly change Internal State" (kecuali initiative, yang eksplisit diizinkan spec di bagian "Relationship Integration").
- **Update selalu gradual** — semua delta di-clamp `±5` lewat `_clamp_step()` di `internal_state_rules.py`, sama pola dengan Relationship System.
- **Manual override backend siap (`manual_override(component, value)`) tapi GUI belum dibuat** — sesuai spec eksplisit "Current milestone implements backend only."

## 9. Keputusan Desain Kumulatif (Tambahan v0.6.4)

- **`BehaviorState` direstrukturisasi jadi 3 blok besar (`emotion`/`relationship`/`internal`)** — rekomendasi eksplisit GPT, diterapkan penuh karena project sudah cukup besar untuk butuh "single source of truth" yang stabil bentuknya, terlepas dari berapa banyak dimensi internal yang ditambah di masa depan.
- **`Mood`, `Energy`, `Curiosity`, `Initiative` digabung jadi satu `InternalState`**, bukan 4 field terpisah di `BehaviorState` — supaya penambahan dimensi baru (Stress/Confidence/Focus) di masa depan cukup mengubah `InternalState`, `BehaviorState` sendiri tidak pernah perlu diubah lagi.
- **Mood pakai mekanisme "streak" (3 emosi searah berturut-turut)**, bukan langsung rata-rata atau threshold sesaat — implementasi konkret dari spec "Mood does not instantly follow Emotion", memberi jeda alami sebelum tren emosi benar-benar dianggap sebagai pergeseran mood jangka panjang.
- **Energy dan Curiosity masing-masing punya 2 sumber delta (aktif + pasif/decay)** yang dijumlah sebelum diterapkan — memisahkan "apa yang terjadi karena ada sinyal baru" dari "apa yang terjadi seiring waktu", konsisten dengan pola `decay()`/`apply_transition()` yang sudah dipakai di Emotion (v0.6.2) dan Relationship (v0.6.3).
- **`InternalStateCoordinator` menyimpan `_emotion_window` (list 10 EmotionState terakhir) secara internal** — bukan menambah tanggung jawab baru ke `EmotionHistory` (v0.6.2), supaya `EmotionCoordinator` tetap tidak tahu apa-apa soal Mood; window ini murni kebutuhan internal `propose_mood()`.
- **`TYPE_CHECKING` guard dipakai untuk circular import `InternalStateHistory`↔`InternalState`**, beda solusi dari kasus Emotion/Relationship (pisah file fisik) — dipilih karena kebutuhannya cuma type hint, bukan konstruksi objek nyata saat import time, jadi solusi yang lebih ringan sudah cukup.
- **v0.6.4 menutup semua pekerjaan "isi TODO" di `BehaviorEngine`** — `update()` sekarang benar-benar lengkap tanpa placeholder tersisa, menandai Phase 2 tinggal 1 milestone lagi (v0.6.5) sebelum benar-benar terhubung ke aplikasi.
