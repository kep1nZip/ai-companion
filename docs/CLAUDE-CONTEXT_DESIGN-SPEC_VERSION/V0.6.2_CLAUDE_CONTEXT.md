## 1. Apa Project Ini

AI Waifu Companion desktop app, terinspirasi Arona (Blue Archive). Bukan sekadar chatbot — dirancang modular supaya bisa berkembang jadi companion dengan voice, avatar Live2D, memory, emosi, dll.

**Prinsip pengembangan:** incremental, per-milestone, jangan lompat fitur, jangan overengineering, jangan redesign arsitektur tanpa alasan kuat.

**Filosofi inti:** Desktop GUI **bukan** aplikasinya. Aplikasi sesungguhnya adalah `Companion`. GUI, Voice, Avatar (+animasinya), dan Behavior Engine hanyalah layer di sekitar `Companion`:

```
Teacher
  ↓
Conversation
  ↓
Emotion Analyzer (v0.6.2) → Emotion Transition → Behavior Engine → BehaviorState (skeleton, BELUM terhubung ke Companion)
  ↓ (rencana v0.6.5)
Companion (+ Memory + waktu + nanti BehaviorState) → Gemini → reply (str)
  ↓
GUI chat bubble │ TTS → AudioPlayer + Lip Sync │ HaloMapper → Hotkey ekspresi │ Idle Animation (blink+breathing)
```

**Human-in-the-Loop Memory Policy (v0.3):** Memory milik Teacher. **Avatar Independence Policy (v0.5):** avatar cuma me-render reaksi visual, opsional. **Animation Independence Policy (v0.5.1, diperluas v0.6.1):** layer animasi independen (Lip Sync, Expression, Idle) digabung `AvatarManager`. **Behavior Engine Policy (v0.6.0):** Behavior Engine cuma menghasilkan state, tidak pernah bahasa/kontrol langsung. **Emotion Transition Policy (v0.6.2, BARU, rekomendasi GPT):** Emosi Arona **bukan nilai statis** yang di-overwrite tiap pesan — dia adalah **state machine yang bergerak secara alami**: naik saat ada sinyal baru (dipuji, kabar baik, dst), meluruh (decay) seiring waktu kalau tidak ada interaksi. Contoh alur: `Neutral → Happy(0.45) → [dipuji] → Excited(0.92) → [waktu berlalu] → Happy(0.60) → [idle] → Neutral(0.20)`. Fondasi ini disiapkan supaya Relationship (v0.6.3), Mood & Energy (v0.6.4), bahkan Vision (v0.7) nanti tinggal memanfaatkan state yang sudah ada, tanpa redesign Emotion lagi.

## 4. Arsitektur (WAJIB Dipertahankan)

```
Terminal (main.py)     Desktop GUI (main_gui.py + ui/window.py)
        │                              │
        └──────────────┬───────────────┘
                        ↓
                   Companion (ai/companion.py)   ← BELUM terhubung ke BehaviorEngine
                        ↓
     ┌──────────────────┼──────────────────┐
     ↓                  ↓                  ↓
Conversation       MemoryManager       GeminiClient
                        ↓
                     memory.db

Voice/Avatar/Lip Sync/Idle Animation: TIDAK BERUBAH sejak v0.6.1 (lihat riwayat kalau butuh detail).

Emotion System (BARU v0.6.2, terisolasi dari Companion/GUI, tapi SUDAH terhubung ke BehaviorEngine):

EmotionCoordinator(memory_manager=None)          [behavior/emotion.py]
        ↓ .process_message(user_input)
   1. decay(current_state)                       [behavior/emotion_rules.py — peluruhan berbasis waktu]
        ↓
   2. EmotionAnalyzer.analyze(user_input, decayed_state) -> EmotionTransitionProposal
        [behavior/emotion_analyzer.py — keyword/regex, BUKAN Gemini]
        ↓
   3. apply_transition(decayed_state, proposal) -> EmotionState BARU
        [behavior/emotion_rules.py]
        ↓
   EmotionHistory.record(old_state)               [behavior/emotion_history.py — in-memory, belum SQLite]
        ↓
   .current -> EmotionState (immutable, snapshot terakhir)

BehaviorEngine.update(user_input, reply) memanggil EmotionCoordinator.process_message()
lalu membangun BehaviorState BARU dengan emotion=hasil, subsystem lain (mood/relationship/
energy/curiosity/initiative) masih TODO placeholder dari state sebelumnya.

BehaviorEngine MASIH BELUM dipanggil dari Companion/ui manapun — terisolasi sampai v0.6.5.
```

**Aturan besi (v0.1–v0.6.1, tetap berlaku penuh):** `Companion` satu-satunya koordinator Conversation+Memory+Gemini. `VoiceManager`/`AvatarManager` satu-satunya koordinator masing-masing domainnya. UI Independence (Qt cuma di `ui/`). Conversation vs Memory tidak boleh dicampur. Layer animasi (Lip Sync, Expression, Idle) tidak boleh bicara ke `VTubeStudioClient` langsung.

**Aturan besi BARU v0.6.2 — Emotion System:**
- **Emosi Arona ≠ emosi Teacher.** Pesan Teacher cuma **memengaruhi**, bukan **menentukan langsung**. Contoh dari spec: Teacher cerita "aku dipromosikan!" (emosi Teacher: senang) → Arona jadi **EXCITED** (ikut senang UNTUK Teacher), **bukan** disamakan begitu saja jadi "Happy".
- **`EmotionAnalyzer` TIDAK PERNAH memanggil Gemini** — dilarang eksplisit di spec ("Do NOT implement sentiment analysis using Gemini"). Implementasi v0.6.2 pakai keyword/regex matching sederhana.
- **Emosi adalah state machine yang bergerak (Emotion Transition), bukan nilai statis** — `decay()` selalu dipanggil dulu (peluruhan berbasis waktu berlalu) sebelum `apply_transition()` menerapkan proposal baru. Ini prinsip inti yang harus dipertahankan di semua sub-versi berikutnya.
- **`EmotionState` immutable** (`frozen=True`) — perubahan selalu objek baru, field: `current`, `intensity` (0.0-1.0), `timestamp`, `previous`, `reason`, `duration_seconds`.
- **`EmotionCoordinator`/`EmotionAnalyzer` TIDAK PERNAH akses SQLite langsung** — `memory_manager` di-inject lewat constructor (Dependency Injection), belum ada query yang benar-benar dipanggil di v0.6.2 (disiapkan untuk kebutuhan masa depan).
- **`EmotionHistory` belum persisten** — in-memory list saja (`max_size=200`, FIFO), SQLite integration ditunda "if needed" sesuai spec.
- **Emotion System TIDAK PERNAH bicara ke Avatar/Voice langsung** — kalau nanti (v0.6.5) `EmotionState.intensity` perlu memengaruhi animasi/suara, itu HARUS lewat `BehaviorState` → `Companion`/`AvatarManager`, bukan panggilan langsung dari `behavior/emotion*.py`.
- **`BehaviorEngine` boleh diisi (bukan di-redesign) untuk mengisi `TODO` yang sengaja ditinggalkan sejak v0.6.0** — signature (`__init__`, `.current`, `.update()`, `.reset()`) tetap 100% identik, cuma isinya yang bertambah lengkap tiap sub-versi. Ini beda dengan "redesign" yang dilarang.
- **`BehaviorEngine` (dan Emotion System di dalamnya) masih 100% terisolasi dari `Companion`/`ui/window.py`** — belum ada satu baris pun yang mengimpor `behavior/*` dari luar folder `behavior/`. Baru terhubung di v0.6.5.

## 5. Kontrak API Tiap Modul

### Modul v0.1–v0.6.1
Tidak berubah — lihat riwayat sebelumnya untuk signature lengkap.

### `behavior/emotion_state.py` — `Emotion` (Enum) + `EmotionState` (dataclass, immutable) (BARU v0.6.2, lokasi baru untuk `Emotion`)
```python
class Emotion(Enum):
    NEUTRAL, HAPPY, EXCITED, EMBARRASSED, SAD, WORRIED, THINKING, SURPRISED, PROUD, SLEEPY
    # diperluas dari 7 (v0.6.0) jadi 10 nilai sesuai daftar spec v0.6.2
DEFAULT_EMOTION = Emotion.NEUTRAL

@dataclass(frozen=True)
class EmotionState:
    current: Emotion = DEFAULT_EMOTION
    intensity: float = 0.0            # divalidasi 0.0-1.0 di __post_init__
    timestamp: datetime
    previous: Optional[Emotion] = None
    reason: Optional[str] = None
    duration_seconds: float = 0.0

elapsed_seconds() -> float   # dihitung LIVE saat dipanggil (time.now - timestamp)
DEFAULT_EMOTION_STATE = EmotionState()
```

### `behavior/emotion_rules.py` — `decay()`, `apply_transition()`, `EmotionTransitionProposal` (BARU v0.6.2)
```python
@dataclass(frozen=True)
class EmotionTransitionProposal:
    emotion: Emotion
    intensity: float
    reason: str

decay(state: EmotionState) -> EmotionState
    # Peluruhan berbasis waktu. Kalau intensity turun di bawah threshold (0.15),
    # pindah ke _DECAY_TARGET (mis. EXCITED->HAPPY->NEUTRAL). Kecepatan decay
    # per-emosi beda (excited/surprised meluruh cepat, sad/worried lambat).

apply_transition(base_state: EmotionState, proposal: EmotionTransitionProposal) -> EmotionState
    # Kalau proposal.emotion == base_state.current: reinforce (intensity naik/max).
    # Kalau beda: transisi penuh ke emosi baru, previous=emosi lama.
```

### `behavior/emotion_analyzer.py` — `EmotionAnalyzer` (BARU v0.6.2)
```python
EmotionAnalyzer(memory_manager: Optional[MemoryManager] = None)
analyze(user_input: str, current_state: EmotionState) -> EmotionTransitionProposal
```
Keyword/regex matching (`_PRAISE_PATTERNS`, `_GOOD_NEWS_PATTERNS`, `_BAD_NEWS_PATTERNS`, `_SURPRISE_PATTERNS`). **Bukan** AI/Gemini. Kalau tidak ada pola cocok → proposal "tetap seperti sekarang" (tidak reset ke neutral paksa, biar `decay()` yang mengatur peluruhan alami).

### `behavior/emotion_history.py` — `EmotionHistory` (BARU v0.6.2)
```python
EmotionHistory(max_size: int = 200)
record(state: EmotionState) -> None
recent(limit: int = 20) -> list[EmotionState]
clear() -> None
```
In-memory saja, belum SQLite.

### `behavior/emotion.py` — `EmotionCoordinator` (update v0.6.2: dari cuma-enum jadi coordinator)

## 9. Keputusan Desain Kumulatif (Tambahan v0.6.2)

- **`Emotion` enum dipindah secara fisik ke `emotion_state.py`**, `emotion.py` jadi coordinator + re-export — solusi teknis untuk circular import (`EmotionState` butuh `Emotion`, coordinator butuh `EmotionState`), sambil tetap menjaga kontrak publik `from behavior.emotion import Emotion` tidak berubah dari v0.6.0.
- **Emotion Transition adalah 2 langkah terpisah**: `decay()` (peluruhan pasif berbasis waktu) SELALU dijalankan dulu, baru `apply_transition()` (reaksi aktif terhadap pesan baru) — memisahkan "apa yang terjadi kalau tidak ada apa-apa" dari "apa yang terjadi kalau ada sinyal baru", biar masing-masing gampang dites/di-tuning independen.
- **Kecepatan decay berbeda per-emosi** (excited/surprised meluruh cepat ~menit, sad/worried meluruh lambat) — emosi "meledak" secara alami memang lebih cepat reda daripada emosi yang lebih dalam, sesuai intuisi psikologis sederhana yang diminta terasa "natural" oleh spec.
- **`EmotionAnalyzer` sengaja pakai keyword/regex, bukan model AI apa pun** — bukan cuma karena dilarang pakai Gemini, tapi juga karena "Emotion calculations must be lightweight... No network calls... No blocking operations" — regex memenuhi ini secara alami.
- **`reason` sebagai field di `EmotionState`/`EmotionTransitionProposal`** — bukan cuma buat logging, tapi juga menyiapkan basis kalau nanti (v0.6.5+) Arona perlu "menjelaskan" kenapa dia merasa begitu (mis. ke Gemini lewat prompt context, atau ke Teacher lewat command debug).
- **`BehaviorEngine.update()` signature dipertahankan `(user_input, reply)`** walau `reply` belum dipakai Emotion System — supaya sub-versi berikutnya (Relationship dll, yang mungkin perlu menganalisis reply juga) tidak perlu breaking change ke signature yang sudah ada.
- **Mengisi `TODO` yang sudah disiapkan ≠ redesign** — prinsip yang dipegang konsisten sejak v0.6.0: `BehaviorEngine` sengaja dibuat dengan kerangka kosong yang bisa diisi bertahap, jadi tiap sub-versi Phase 2 secara teknis "mengisi", bukan "mendesain ulang".

## 11. Roadmap Selanjutnya

- **v0.6.3 — Relationship System:** logic pertumbuhan `RelationshipState` (trust/comfort/affection/respect/familiarity), mulai membaca/menulis lewat `MemoryManager`.
