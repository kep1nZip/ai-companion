## v1.9 — Companion Intelligence: ✅ SELESAI & CONFIRMED AMAN

**Tujuan:** relevansi context yang dikirim ke model — jangan asal tempel semua subsystem ke setiap prompt.

**Perubahan (2 file: `ai/companion.py`, `ai/context_builder.py`):**
1. **Routine Relevance** — `Routine Suggestion` di context sekarang HANYA muncul kalau `Initiative.should_start == True`. Sebelumnya routine pending (mis. Lunch Reminder) selalu nempel ke prompt apa pun topik obrolannya (bisa nyempil di tengah pertanyaan teknis).
2. **Memory Relevance** — ganti dari "load N memori terbaru secara buta" jadi `search_memory()` (SQL LIKE yang sudah ada sejak v1.1) per kata kunci dari pesan Teacher, dengan fallback ke recency kalau nol match.
3. **Bugfix (ditemukan Teacher via testing nyata):** `Routine.mark_completed()` sebelumnya jalan cuma karena Gemini berhasil membalas APAPUN — bukan karena beneran dipakai. Sekarang digerbang oleh `decision_result.should_start` yang sama.

**Status:** Diverifikasi isolated test (lolos semua) DAN dikonfirmasi Teacher lewat `main_gui.py` sungguhan — "aman banget".

**Interim fix (di luar v1.9, insiden terpisah):** Google mempercepat pensiun `gemini-2.5-flash` (lebih awal dari jadwal resmi Okt 2026) → error 404. Diganti ke `gemini-3.6-flash` (model stable/GA saat ini) di `config/constants.py`, baik untuk chat utama maupun Vision.

## v2.0 — Model Migration: 🚧 SEBAGIAN SELESAI (Step 1-6 dari 9)

**Filosofi (dari spec):** Gemini TIDAK dihapus, jadi salah satu Provider yang bisa ditukar. Companion tetap satu-satunya orchestrator — provider TIDAK PERNAH tahu Memory/Vision/Behavior/Routine/Initiative/GUI.

### Selesai:

**Step 1-3 — Provider Abstraction**
- `ai/providers/base.py` (baru): `LanguageModelProvider` (ABC) + `ProviderError`/`ProviderResponseError`/`ProviderRateLimitError` — kontrak provider-agnostic, dirumuskan dari kontrak `GeminiClient.send()` yang sudah ada (bukan ditebak).
- `ai/providers/gemini_provider.py` (baru): `GeminiProvider` — adapter tipis, **reuse `GeminiClient` (`ai/gemini.py`) tanpa diubah sama sekali**, cuma menerjemahkan exception Gemini-spesifik (`ClientError`, deteksi "429") jadi exception provider-agnostic.
- `ai/companion.py`: `self._gemini` sekarang bertipe `LanguageModelProvider`, constructor terima `provider=` opsional (default `None` → otomatis `GeminiProvider`, 100% backward compatible, `main_gui.py` lama tidak perlu berubah).
- Diverifikasi: Companion jalan dengan provider palsu apa pun (bukti abstraksi nyata, bukan rename), `GeminiProvider` perilakunya identik dengan sebelum diabstraksi.

**Step 4 — Add Local Provider**
- Hardware Teacher dinilai dulu (bukan asal pilih): Ryzen 7 7700x, **RX 6600 8GB** (tidak masuk daftar resmi ROCm AMD), 32GB RAM.
- Riset: backend **Vulkan** via **LM Studio** direkomendasikan (jalan native di Windows, tidak butuh ROCm).
- `ai/providers/local_provider.py` (baru): `LocalProvider` — bicara ke local server lewat REST API bergaya OpenAI (`/v1/chat/completions`), menerjemahkan `list[types.Content]` (format Gemini SDK yang dipertahankan sebagai kontrak bersama) ke format OpenAI chat DI DALAM provider sendiri — Companion/ContextBuilder/Conversation nol perubahan.
- `test_local_provider.py` (baru): script CLI standalone buat tes koneksi tanpa perlu jalanin seluruh app.

**Step 5 — Teacher's own testing (model selection)**
- Percobaan 1: `qwen3.5-9b` — reasoning-heavy, `reasoning_tokens: 864`, sering timeout/kosong.
- **Model final: `qwen/qwen3-vl-8b` (Q4_K_M)** — stabil, `reasoning_tokens: 0`, ~27 tok/s generation, ~193 tok/s prompt eval, total ~10 detik per balasan pendek. **Ini keputusan Teacher sendiri berdasarkan pengukuran nyata di hardware-nya** (bukan rekomendasi Claude yang di-hardcode).

**Step 6 — Integrate configuration**
- `config/settings.py`: `AI_PROVIDER` (env var, default `"gemini"` — tidak berubah dari sebelumnya), `LOCAL_PROVIDER_BASE_URL`, `LOCAL_PROVIDER_MODEL_NAME`.
- `main_gui.py`: baca `AI_PROVIDER` → construct `LocalProvider` kalau `"local"`, else `None` (Companion pakai `GeminiProvider` default-nya sendiri).
- `GEMINI_API_KEY` TETAP WAJIB apa pun `AI_PROVIDER`-nya — Vision & Memory Extraction (lihat di bawah) belum dimigrasikan, masih butuh Gemini yang valid.
- **Dikonfirmasi Teacher LIVE**: `python main_gui.py` dengan `AI_PROVIDER=local` sukses, log LM Studio menunjukkan request/response yang benar, balasan Arona (persona) tetap konsisten lewat local model.

### Belum dikerjakan (Step 7-9 + sengaja di luar cakupan):

- **Step 7 — Full regression suite**: baru sebatas konfirmasi manual chat teks jalan. Voice/Avatar/Routine/Vision/Developer Dashboard/Autonomous Interaction (v1.8) BELUM diverifikasi ulang secara eksplisit dengan `AI_PROVIDER=local` aktif.
- **Step 8 — Performance Matrix formal**: data mentah sudah ada dari log LM Studio (~10s/reply, ~27 tok/s), belum disusun jadi tabel perbandingan formal vs Gemini.
- **Step 9 — Memilih default permanen**: MASIH opt-in lewat `.env` (`AI_PROVIDER=local`), Gemini tetap default kalau env var tidak diset. Belum ada keputusan final "local jadi default selamanya".
- **Tidak ada toggle di Settings GUI** — provider switching saat ini murni lewat `.env`, belum ada UI.

### Vision & Memory Extraction — SENGAJA belum dimigrasikan (dikonfirmasi ke Teacher, bukan lupa):

- **Vision**: `ImageAnalyzer` (`vision/image_analyzer.py`) masih 100% Gemini, konstruksinya independen total dari `AI_PROVIDER` (di `main_gui.py`, dibuat sebelum logic pemilihan provider). Alasan tidak direkomendasikan pindah dulu:
  1. `LocalProvider` saat ini cuma menerjemahkan **teks** (`content.parts[0].text`) — kalau dipaksa reuse untuk Vision, data gambar akan **hilang diam-diam** (bug, bukan sekadar belum optimal).
  2. Vision (terutama Auto Vision v1.5.2, capture berkala) akan **rebutan resource GPU/server** dengan chat utama kalau sama-sama lewat LM Studio yang sama — saat ini mereka terpisah (Vision→Gemini, Chat→bisa local), jadi tidak saling mengganggu.
  3. `parse_vision_context()` mengharapkan format output terstruktur (SUMMARY/APPLICATION) yang sudah teruji reliable dengan Gemini — belum divalidasi ke model lokal.
- **Memory Extraction**: `MemoryExtractor` (`ai/memory_extractor.py`) juga masih 100% Gemini. Alasan tidak direkomendasikan pindah dulu: `Companion._remember_if_useful()` dipanggil **synchronous, sebelum `return reply`** di `chat()` — kalau dipindah ke local apa adanya, setiap chat akan kena LATENSI GANDA (≈10 detik chat utama + ≈10 detik memory extraction ≈ 20 detik/pesan), karena belum dibuat non-blocking/background.
