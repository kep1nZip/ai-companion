# 2. Prinsip Utama

## 2.1 GUI adalah Presentation Layer

GUI hanya menampilkan status dan meminta aksi.

GUI tidak boleh menjadi tempat business logic Avatar.

```text
User
 ↓
Avatar GUI
 ↓
AvatarManager
 ↓
Existing Avatar System
 ↓
VTube Studio
```

GUI tidak boleh melewati AvatarManager hanya untuk mempermudah implementasi.

## 2.2 Existing Avatar System adalah Source of Truth

Sebelum implementasi, Claude wajib membaca source aktual dari:

- `avatar/`
- `ui/avatar_worker.py` jika ada;
- konfigurasi VTube Studio yang ada;
- `ui/window.py`;
- `ui/navigation.py`;
- `ui/theme.py`;
- modul yang digunakan AvatarManager.

Jangan mengarang state, parameter, hotkey, atau API baru.

## 2.3 Jangan Membuat AvatarManager Kedua

Semua halaman GUI yang membutuhkan Avatar harus menggunakan instance AvatarManager existing jika arsitektur aktual memang demikian.

Gunakan dependency injection, misalnya:

```python
AvatarPage(avatar_manager)
```

jika cocok dengan kontrak source aktual.

Jangan membuat `AvatarManager(...)` baru secara sembarangan di `ui/avatar.py`.


# 9. Control Policy

Kontrol UI harus berasal dari kemampuan nyata AvatarManager.

Contoh:

```text
AvatarManager.connect()
AvatarManager.disconnect()
AvatarManager.trigger_expression(...)
AvatarManager.trigger_hotkey(...)
```

**Hanya gunakan method yang benar-benar ditemukan saat inspeksi.**

Jangan membuat method backend hanya karena UI membutuhkannya.

Jika fitur belum memiliki API:

```text
UI tidak menyediakan tombolnya.
```

bukan:

```text
Tambahkan API baru tanpa alasan.
```

# 10. Worker / Threading Policy

```text

 ↓

 ↓
```

Jika worker existing tidak cocok:

1. jelaskan gap;
2. periksa apakah perubahan kecil aman;
3. jangan melakukan redesign worker tanpa kebutuhan nyata.
