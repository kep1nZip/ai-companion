## 5. Core Design Principles

### 5.1 Explicit Provider Selection

Contoh:

```env
AI_PROVIDER=local
MEMORY_PROVIDER=gemini
VISION_PROVIDER=local
```

Jika provider gagal, jangan diam-diam berpindah provider lain.

```text
NO SILENT FALLBACK
```

### 5.2 Single Configuration Source

Gunakan konfigurasi provider yang sudah ada terlebih dahulu.

```text
Reuse existing configuration
        ↓
Remove unnecessary duplication
        ↓
Add new configuration only when justified
```

Jangan membuat konfigurasi terpisah per subsystem bila konfigurasi existing memang dapat dipakai.

### 5.3 No Provider Logic Leakage

Hindari provider logic tersebar di runtime:

```python
if provider == "local":
    ...
elif provider == "gemini":
    ...
```

Provider-specific behavior harus berhenti di boundary provider.

## 18. Quality Gate

### PASS

- Provider configuration konsisten.
- Provider selection stabil.
- Tidak ada silent fallback.
- Dashboard akurat.
- Kombinasi provider berjalan.
- Tidak ada regression penting.
- Performance baseline terdokumentasi.
- Resource behavior dipahami.
- Startup/shutdown stabil.

### CONDITIONAL PASS

Digunakan bila ada trade-off performa/resource yang dapat diterima atau provider tertentu memang lebih cocok untuk subsystem tertentu.

### FAIL

- Provider selection salah.
- Configuration corrupt.
- Silent fallback terjadi.
- Runtime/GUI freeze karena perubahan provider.
- Regression ke subsystem stabil.
- Shutdown menjadi tidak aman.
- Behavior menjadi tidak dapat diprediksi.

## 22. Final Principle

v2.4 bukan milestone untuk membuat Arona "lebih banyak fitur".

v2.4 adalah milestone untuk membuat fondasi provider yang sudah ada menjadi:

```text
lebih konsisten
lebih terukur
lebih mudah dikontrol
lebih mudah didiagnosis
lebih efisien
```

Prinsip akhir:

```text
Do not optimize what has not been measured.
Do not refactor what is already stable.
Do not add abstraction without a real boundary problem.
Do not hide provider failures with silent fallbacks.
```

Setelah v2.4 selesai dan stabil, milestone berikutnya ditentukan berdasarkan hasil pengukuran nyata, bukan asumsi roadmap.
