# Temuan penting dari inspeksi (`speech/voice_manager.py`, dkk)

Ini bukan asumsi — sudah dikonfirmasi baca source langsung sebelum implementasi:

1. **`VoiceState` enum** persis 5 nilai: `IDLE, RECORDING, TRANSCRIBING,
   THINKING, SPEAKING`. Tidak ada state `ERROR` — error ditangani lewat
   exception (`VoiceError`), bukan state.
2. **`stop_recording_and_respond()` itu SATU blocking call** yang di
   dalamnya sudah mencakup STT → `Companion.chat()` → TTS → playback,
   baru `return (user_text, reply)` di akhir, SETELAH audio selesai
   diputar. Konsekuensi: di Voice GUI, box "You said"/"Arona:" baru terisi
   setelah audio balasan selesai — ini kontrak asli backend, bukan
   keterlambatan bug di GUI.
3. **`AudioPlayer.play()` fully blocking, TIDAK ADA method `stop()`.** Karena
   itu Voice GUI **sengaja tidak punya tombol Stop Playback** — menambahkannya
   berarti mengarang API yang tidak ada di backend.
4. **`VoiceManager.set_state_listener()` itu single-slot** (`Optional[Callable]`,
   overwrite, bukan daftar subscriber). Pola yang sudah ada: setiap kali
   `VoiceWorker`/`SpeakWorker` baru diinstansiasi, constructor-nya
   register ulang listener. Voice GUI baru **reuse pola yang sama persis**
   (instansiasi `VoiceWorker` baru tiap kali "Stop Recording" diklik),
   bukan bikin mekanisme listener baru.
5. **Tidak ada state granular terpisah untuk "TTS" vs "Audio/Playback"** —
   cuma satu `SPEAKING` yang mencakup keduanya sekaligus di dalam
   `VoiceManager._speak()`.
6. **`Recorder.start()` tidak dibungkus try/except di mana pun** — termasuk
   di mic button Chat page (v1.1) yang sudah ada duluan. Kalau mic tidak
   tersedia, exception mentah dari `sounddevice` akan bocor tanpa
   penanganan.

# Yang sudah diimplementasikan

## 1. `ui/voice.py` — BARU

`VoicePage(QWidget)`:

- Status label: `Status: {VoiceState.value}` — satu baris, bukan dua
  indikator terpisah TTS/Audio (lihat "Deviasi dari mockup" di bawah).
- Error label — tersembunyi default, muncul kalau ada `VoiceError` atau
  exception saat start recording.
- **Satu tombol toggle** `🎙 Start Recording` ⇄ `⏹ Stop Recording` — bukan
  dua tombol terpisah seperti mockup awal. Meniru persis pola mic button
  di Chat page yang sudah terbukti jalan.
- Box "You said:" dan "Arona:" — `QFrame` + `QLabel` read-only, selectable
  text, mirip pola `MemoryDetailView` dari v1.1.
- **Reuse `ui/voice_worker.py::VoiceWorker` apa adanya** — tidak ada worker
  class baru. `VoicePage` cuma instansiasi `VoiceWorker(self._voice_manager)`
  persis seperti yang dilakukan `window.py` untuk mic button Chat.
- `start_recording()` dipanggil langsung di GUI thread (bukan lewat worker)
  — sama seperti pola existing di Chat page, karena `Recorder.start()` cuma
  memulai `InputStream` (cepat, non-blocking). **Dibungkus try/except** di
  level GUI untuk menangani mic tidak tersedia — ini satu-satunya penanganan
  error yang ditambahkan, murni sisi GUI, tidak menyentuh `Recorder`.
- Menerima `voice_manager: VoiceManager` lewat constructor — **instance yang
  SAMA** dengan yang dipakai Chat page, bukan instance baru (lihat §2).

   (tidak ada yang dipanggil di backend).

# Known edge case (bukan bug baru dari v1.2)

Chat page dan Voice page berbagi **satu `VoiceManager` fisik yang sama**.
Kalau Teacher mulai rekam dari Voice page lalu pindah ke Chat page sebelum
menekan Stop, ikon mic di Chat page **tidak otomatis sinkron** — karena
masing-masing page mengelola teks tombolnya sendiri secara lokal (manual
`setText`), bukan derive real-time dari `voice_manager.state`. Ini bukan
regresi v1.2, sudah begitu sejak mic button pertama ada di v1.0/v1.1.
Perbaikannya butuh refactor lebih besar (state listener terpusat di level
`MainWindow`, bukan per-page) — di luar scope "smallest safe change" v1.2,
tidak dikerjakan kecuali diminta eksplisit.

# Instruksi untuk sesi Claude berikutnya

1. v1.2 Voice GUI **selesai dan terverifikasi jalan**. Jangan re-implementasi
   dari nol — baca dulu isi `ui/voice.py`, `ui/navigation.py`, `ui/window.py`
   versi yang sudah di-deploy user (minta upload ulang kalau user bilang sudah
   ada perubahan lanjutan, jangan asumsikan sama persis dengan dokumen ini).
2. Kalau user minta perbaikan edge case mic-icon-sync antar page (lihat
   "Known edge case" di atas): itu perubahan arsitektur (state listener
   terpusat), bukan bug fix kecil — treat sebagai keputusan desain baru,
   tanya dulu sebelum eksekusi.
3. Kalau user minta tombol Cancel Recording atau kontrol lain yang backend-nya
   sudah ada (`cancel_recording()`) tapi belum dipakai GUI: itu penambahan UI
   murni, aman dikerjakan tanpa banyak tanya — tapi tetap konfirmasi UX yang
   diinginkan (mis. apakah Cancel menggantikan atau menambah tombol Stop).
4. **JANGAN PERNAH** bikin `VoiceManager`/`Recorder`/`SpeechToText`/
   `TextToSpeech`/`AudioPlayer` instance baru di `ui/`. Semua halaman yang
   butuh voice HARUS reuse `self._voice_manager` yang sama dari `MainWindow`.
5. Arsitektur v1.0 (Architecture Freeze Policy) **masih berlaku** untuk semua
   subsystem di luar GUI baru yang ditambahkan tiap versi. `Companion` tetap
   satu-satunya orchestrator.
6. Pola yang established sejauh ini (v1.1 + v1.2): boundary tipis non-Qt
   kalau memang perlu (`MemoryService`), reuse worker/manager instance yang
   sama lewat constructor injection, `QStackedWidget` untuk page switching,
   append-only ke `theme.py`. Referensi yang baik untuk v1.3+ kalau menambah
   halaman GUI lain — tapi tetap inspect dulu, jangan copy-paste pola tanpa
   verifikasi ulang konteksnya cocok.
7. User komunikasi Bahasa Indonesia, kode/komentar teknis boleh Inggris.
