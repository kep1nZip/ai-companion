## 3. Alasan Setiap Perubahan

### File baru — `ai/response_calibration.py`
Pola IDENTIK `ai/temporal_signals.py`/`ai/reference_signals.py`: pure function, TIDAK ADA LLM/network/state baru.

- `detect_depth_cues(text)` — return `(depth_cues, explicit_phrases)`. **BEDA PENTING dari v3.0's `detect_style_preference()`**: bisa mengembalikan LEBIH DARI SATU kategori sekaligus (concise DAN detailed), dan `explicit_phrases` membawa teks VERBATIM yang match — bukan cuma label abstrak (pelajaran dari hotfix v3.3 round 2: konkret lebih efektif untuk model lemah).
- `detect_conversation_form(text, reference_signal=..., unresolved_cues=..., completion_cues=...)` — SATU label (question/request/problem_report/progress_update/completion_statement/acknowledgement/reference_followup) atau `None` ("unknown"). Prioritas: question (ada "?" di mana pun dalam pesan) → problem_report → completion_statement → progress_update → request → acknowledgement → reference_followup (fallback paling akhir). `unresolved_cues`/`completion_cues`/`reference_signal` adalah **parameter REUSE**, dihitung pemanggil dari v3.5/v3.3 — modul ini tidak reimplementasi logic itu.
- `ResponseCalibration` (frozen dataclass) — `conversation_form`, `depth_cues` (tuple), `explicit_phrases` (tuple), `step_by_step_requested` (bool), `conflicting_cues` (bool). **Nol field confidence/quality/skor numerik** (Hard Boundary §19/§24).
- `build_response_calibration()` — entrypoint gabungan.

### `ai/context_builder.py`
`build()` dapat parameter opsional `response_calibration`. **Tetap assembly-only** — deteksi dilakukan Companion sebelum `build()` dipanggil (pola identik `temporal_signals`). Section "Response Calibration" HANYA muncul kalau ada evidence. Wording observasional ("Teacher explicitly asked for...") bukan perintah ("You must...").

### `ai/companion.py`
`_build_contents()` menghitung `response_calibration` SETELAH `temporal_signals` (supaya `unresolved_cues`/`completion_cues` bisa di-reuse langsung tanpa hitung ulang), diteruskan ke `ContextBuilder.build()`, di-cache ke `_last_response_calibration` untuk dashboard. **`_build_autonomous_contents()` TIDAK disentuh sama sekali** (Phase 13 — diverifikasi lewat test T17 yang memeriksa source code method itu tidak mengandung kata "response_calibration").

### `developer/developer.py` + `ui/developer.py`
Field `response_calibration_debug` ditambah ke `DeveloperSnapshot`, ditampilkan sebagai section TAMBAHAN di card **"Memory Decisions"** yang sudah ada — bukan card/dashboard baru (spec §19 eksplisit).

## 4. Bug yang Ditemukan & Diperbaiki Selama Implementasi

Draft awal `detect_conversation_form()` mengecek "pesan **diakhiri** tanda tanya" (`stripped.endswith("?")`) untuk form `question`. Test T11 (`"kenapa API error? singkat aja"` → harus `form=question`) gagal karena tanda tanya ada di **tengah** pesan multi-kalimat, bukan di akhir. Diperbaiki jadi cek "mengandung tanda tanya di mana pun" (`"?" in stripped`) — tetap konservatif (tanda tanya jarang false-positive di Bahasa Indonesia sehari-hari) dan sesuai contoh eksplisit spec §20 T11.

## 6. Contoh Konkret

```
Teacher: "kenapa API error? singkat aja"

Response Calibration (section baru):
Bentuk pesan Teacher saat ini tampak seperti: question.
Teacher menyebutkan instruksi gaya jawaban secara eksplisit: "singkat aja".

-> LLM menerima evidence APA ADANYA — form "question" (karena ada "?"),
   PLUS instruksi eksplisit "singkat aja" (verbatim, bukan cuma label
   "concise") — TIDAK ada template jawaban yang dipaksakan, Arona tetap
   bebas menentukan kata-kata & nada.
```

```
Teacher: "jelasin detail tapi singkat aja" (kontradiktif)

Response Calibration:
Teacher menyebutkan instruksi gaya jawaban secara eksplisit: "jelasin detail", "singkat aja".
Catatan: instruksi gaya jawaban di atas tampak saling bertentangan
(diminta detail sekaligus singkat) — gunakan pertimbangan wajar.

-> Aplikasi TIDAK memutuskan mana yang menang — LLM yang menafsirkan
   tradeoff secara natural (spec §12).
```
