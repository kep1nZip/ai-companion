# AI Companion — v0.2 Desktop GUI Design Specification

---

# Current Project Status

Current Version:

v0.1.1 — Core Infrastructure ✅

The backend architecture is considered stable.

Current architecture already includes:

- Gemini Client
- Conversation Manager
- Prompt Loader
- Prompt Builder
- Companion Layer
- Command System
- Logging
- Configuration
- Error Handling

The backend must now remain stable.

v0.2 focuses ONLY on creating a Desktop GUI.

The backend must NOT be rewritten.

---

# Objective

Create a modern desktop application using PySide6.

The GUI should become a presentation layer only.

Business logic must remain inside the backend.

---

# Important Rules

DO NOT modify:

- ai/gemini.py
- ai/personality.py
- ai/prompt_builder.py
- prompts/*
- ai/conversation.py (unless absolutely necessary)
- companion.py architecture

Only modify them if a critical bug exists.

The GUI must consume the existing backend.

---

# GUI Philosophy

The GUI should never communicate directly with Gemini.

Instead:

Window

↓

AICompanion

↓

Conversation

↓

Gemini

↓

Gemini API

The GUI should only know about AICompanion.

---

# Backend Communication

The GUI should only interact with:

AICompanion

Example:

reply = companion.chat(user_input)

Do NOT call Gemini directly.

Do NOT build prompts inside the GUI.

Do NOT manage history inside the GUI.

---

# Threading

Gemini requests must never freeze the GUI.

Use:

QThread

or

QRunnable

or another appropriate Qt threading approach.

Requirements:

User clicks Send

↓

Background thread starts

↓

GUI remains responsive

↓

Response received

↓

Update chat

---

# Error Handling

Never crash the application.
