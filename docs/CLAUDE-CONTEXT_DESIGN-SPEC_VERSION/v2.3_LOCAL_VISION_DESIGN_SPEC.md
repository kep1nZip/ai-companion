## 2. Purpose

v2.3 memindahkan **Vision inference** dari Gemini ke Local Provider sehingga Arona dapat memahami gambar/screenshot menggunakan model lokal.

Target utama:

```text
Gemini
   ↓
Vision Provider

Local
   ↓
Vision Provider
```

Setelah milestone ini, Vision tidak lagi wajib bergantung pada Gemini untuk inference gambar.

Namun:

```text
Gemini Vision
```

tetap dipertahankan sebagai provider alternatif selama belum ada keputusan untuk menghapusnya.

## 3. Current Architecture

Sistem Vision yang sudah ada tetap menjadi dasar:

```text

      ↓
VisionContext
      ↓

      ↓
```

## 7. Configuration Principle

Vision harus memiliki konfigurasi provider yang eksplisit.

Contoh target:

```env
VISION_PROVIDER=local
```

atau:

```env
VISION_PROVIDER=gemini
```

Apabila implementasi konfigurasi yang ada sudah menyediakan mekanisme provider selection yang lebih sesuai, gunakan mekanisme tersebut daripada membuat konfigurasi duplikat.

### Local Vision

Local Vision menggunakan konfigurasi Local Provider yang sudah ada jika kontraknya kompatibel:

```env
LOCAL_PROVIDER_BASE_URL=...
LOCAL_PROVIDER_MODEL_NAME=...
```

Jangan membuat konfigurasi duplikat seperti:

```env
LOCAL_VISION_BASE_URL
LOCAL_VISION_MODEL_NAME
```

kecuali audit kode membuktikan bahwa pemisahan tersebut benar-benar diperlukan.

Prinsip:

```text
Reuse existing provider configuration first.
Add new configuration only when technically justified.
```

## 8. Model Compatibility Check

Sebelum implementasi penuh, lakukan pengecekan bahwa model Local yang digunakan memang dapat menerima input multimodal/image.

Model yang saat ini dipakai dalam environment:

```text

```

Jangan hardcode kemampuan model hanya berdasarkan nama model.

Validation wajib memastikan:

```text
text input      → works
image input     → works
text + image    → works
```

## 10. Phase 1 — Vision Provider Boundary

Apabila boundary provider Vision belum cukup jelas, buat abstraction minimal yang memungkinkan:

```text
Gemini Vision
Local Vision
```

berbagi contract yang sama.

Contoh konseptual:

```python
analyze_image(
    image,
    context=None,
) -> VisionResult
```

Nama class/function **harus mengikuti pola arsitektur yang benar-benar sudah ada**.

Jangan membuat abstraction kedua yang tumpang tindih dengan:

```text
LanguageModelProvider
```

apabila abstraction yang sama masih dapat digunakan secara bersih untuk multimodal input.

## 11. Phase 2 — Local Vision Implementation

Implementasi Local Vision harus:

- Menggunakan endpoint Local yang sudah ada.
- Mengirim image dengan format yang didukung endpoint.
- Menggunakan prompt Vision yang sudah ada apabila masih kompatibel.
- Mempertahankan output normalized result yang sama.
- Menangani provider error tanpa menjatuhkan chat utama.
- Tidak menyimpan screenshot permanen.
- Tidak menulis screenshot ke log.
- Tidak membuat fallback Gemini secara diam-diam.

### No Silent Fallback

Jika:

```env
VISION_PROVIDER=local
```

dan Local gagal:

```text
Vision gagal
```

bukan:

```text
diam-diam pindah ke Gemini
```

Provider switching harus eksplisit.

## 12. Phase 3 — VisionContext Compatibility

Pastikan hasil Local Vision tetap kompatibel dengan:

```text
VisionContext
```

ContextBuilder harus tetap menerima bentuk data yang sama.

Target:

```text
Gemini Vision Result
        ↓
same VisionContext contract
        ↓
ContextBuilder

Local Vision Result
        ↓
same VisionContext contract
        ↓
ContextBuilder
```

Tidak boleh ada:

```text
if provider == local:
    special_context_path
```

di banyak tempat hanya untuk mengakomodasi provider.

Provider-specific behavior harus tetap berada di boundary provider.

---

## 13. Phase 4 — Manual Vision

Uji terlebih dahulu mode:

```text
Vision OFF
Vision MANUAL
Capture Now
```

Test basic:

1. Capture gambar sederhana.
2. Analisis gambar.
3. Pastikan VisionContext terisi.
4. Pastikan ContextBuilder dapat menggunakannya.
5. Pastikan chat menggunakan context tersebut.
6. Pastikan tidak ada screenshot permanen.

Manual mode harus stabil sebelum AUTO diuji.

---

## 14. Phase 5 — AUTO Vision

Setelah Manual Vision stabil:

```text
Vision AUTO
```

Uji:

- Auto refresh.
- Cooldown/scheduler yang sudah ada.
- Context replacement/invalidation.
- Capture Now saat AUTO aktif.
- OFF → context dibersihkan/invalidate.
- AUTO → tidak memulai chat sendiri.

Prinsip yang tetap berlaku:

```text
Vision provides context.
Vision does not generate autonomous conversation.
```

## 23. Decision Gate

v2.3 dapat dianggap **PASS** apabila:

- Local Vision dapat menerima image input.
- Local Vision menghasilkan hasil yang berguna.
- VisionContext tetap kompatibel.
- Manual Vision stabil.
- AUTO Vision stabil.
- GUI tetap responsif.
- Provider failure ditangani dengan benar.
- Tidak ada silent fallback.
- Developer Dashboard menampilkan provider dengan benar.
- Tidak ada regression penting.

### CONDITIONAL PASS

Digunakan apabila:

- Local Vision usable tetapi kualitas belum setara Gemini.
- Ada latency/resource trade-off yang masih dapat diterima.
- Beberapa kasus visual membutuhkan Gemini sebagai alternative provider.

Dalam kondisi ini:

```text
Local Vision available
Gemini Vision retained
```

dan default dapat diputuskan terpisah.

### FAIL

Milestone gagal apabila:

- Local Vision tidak dapat menerima image.
- Vision menghasilkan terlalu banyak hallucination.
- GUI freeze/crash.
- AUTO Vision merusak existing behavior.
- Provider failure menjatuhkan application.
- Silent fallback terjadi.
- ContextBuilder/VisionContext mengalami regression penting.
