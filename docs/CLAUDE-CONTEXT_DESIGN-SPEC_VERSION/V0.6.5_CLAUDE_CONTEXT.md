## 1. Apa Project Ini

AI Waifu Companion desktop app, terinspirasi Arona (Blue Archive). Bukan sekadar chatbot — dirancang modular supaya bisa berkembang jadi companion dengan voice, avatar Live2D, memory, emosi, dll.

**Prinsip pengembangan:** incremental, per-milestone, jangan lompat fitur, jangan overengineering, jangan redesign arsitektur tanpa alasan kuat.

**Filosofi inti:** Desktop GUI **bukan** aplikasinya. Aplikasi sesungguhnya adalah `Companion`. Sejak v0.6.5, `BehaviorEngine` **akhirnya benar-benar terhubung**:

```
Teacher
  ↓
Companion.chat(user_input)
  ↓
Conversation.add_user_message()
  ↓
BehaviorEngine.update(user_input, "") → BehaviorState (emotion + relationship + internal)
  ↓
ContextBuilder.build(behavior_state) → Ephemeral Context (text, TIDAK PERNAH disimpan)
  ↓
GeminiClient.send(system_prompt + ephemeral_context + memori + history) → reply
  ↓
Conversation.add_assistant_message(reply)
  ↓
GUI chat bubble │ TTS → AudioPlayer + Lip Sync │ HaloMapper → Hotkey │ IdleCoordinator.apply_mood(mood_string)
```

**Human-in-the-Loop Memory Policy (v0.3):** Memory milik Teacher. **Avatar Independence Policy (v0.5):** avatar opsional. **Animation Independence Policy (v0.5.1/v0.6.1):** layer animasi digabung `AvatarManager`. **Behavior Engine Policy (v0.6.0):** Behavior Engine cuma menghasilkan state. **Emotion Transition Policy (v0.6.2):** emosi = state machine. **Relationship Base/Current Policy (v0.6.3).** **BehaviorState Single Source of Truth Policy (v0.6.4):** `BehaviorState` = 3 blok (`emotion`/`relationship`/`internal`). **Ephemeral Context Injection Policy (v0.6.5, BARU):** informasi behavior **TIDAK PERNAH** ditulis ke `prompts/*.txt` atau ke Memory — selalu dibangun ulang tiap request, dikirim ke Gemini sebagai konten tambahan sesaat, lalu dibuang. **Context Builder Separation Policy (v0.6.5, BARU, rekomendasi GPT):** `Companion` **tidak boleh** merangkai string context sendiri — semua formatting (waktu, emotion, relationship, internal state) dilakukan `ai/context_builder.py`. `Companion` tetap orchestrator murni; kalau v0.7 (Vision) atau v0.8 (Routine System) butuh menambah info ke context, cukup extend `ContextBuilder`, `Companion` tidak perlu diubah.

## 4. Arsitektur (WAJIB Dipertahankan)

```
Terminal (main.py)     Desktop GUI (main_gui.py + ui/window.py)
        │                              │
        └──────────────┬───────────────┘
                        ↓
                   Companion (ai/companion.py)   ← SEKARANG terhubung ke BehaviorEngine + ContextBuilder
                        ↓
     ┌──────────────────┼──────────────────┬─────────────────────┐
     ↓                  ↓                  ↓                     ↓
Conversation       MemoryManager       GeminiClient          BehaviorEngine
                        ↓                                        ↓
                     memory.db                              (Emotion/Relationship/Internal
                                                               State — TIDAK BERUBAH sejak
                                                               v0.6.2-v0.6.4)

Companion.chat(user_input):
   1. Conversation.add_user_message(user_input)
   2. behavior_state = BehaviorEngine.update(user_input, "")     [reply="" — lihat catatan di bawah]
        ↓ fallback ke DEFAULT_BEHAVIOR_STATE kalau exception (Behavior tidak boleh hentikan chat)
   3. ephemeral_text = ContextBuilder.build(behavior_state)       [ai/context_builder.py — waktu+emotion+relationship+internal]
   4. contents = [ephemeral_context, memori(ephemeral), *history]
   5. reply = GeminiClient.send(contents)                          ← VALIDASI BARU: raise GeminiResponseError kalau reply kosong
   6. Conversation.add_assistant_message(reply)
   7. MemoryExtractor.extract() (tidak berubah, v0.3)

GUI (ui/window.py) setelah dapat reply:
   behavior_state = companion.current_behavior_state()             [API publik BARU, read-only]
   avatar_worker.apply_mood(behavior_state.internal.mood.value)     [STRING mood saja, bukan BehaviorState utuh]
        ↓ (thread-safe via asyncio.run_coroutine_threadsafe, event loop sama dgn idle scheduler)
   IdleCoordinator.apply_mood(mood_name) → ubah timing BlinkAnimator/BreathingAnimator
        (Sleepy -> kedip lebih sering+lama, Cheerful -> napas lebih cepat, dst)

AvatarManager TIDAK PERNAH baca BehaviorState — cuma IdleCoordinator yang boleh, dan cuma terima STRING mood.
```

**Aturan besi (v0.1–v0.6.4, tetap berlaku penuh):** `Companion` satu-satunya koordinator Conversation+Memory+Gemini+**sekarang Behavior**. UI Independence. Conversation vs Memory tidak dicampur. Analyzer Behavior tidak boleh panggil Gemini. Persistence behavior lewat method publik `MemoryManager`. `BehaviorState` cuma 3 field (`emotion`/`relationship`/`internal`).

**Aturan besi BARU v0.6.5 — Behavior Integration:**
- **`Companion` TIDAK BOLEH merangkai string context sendiri** — WAJIB lewat `ContextBuilder`. Kalau ada kebutuhan format context baru (v0.7 Vision dst), tambah method di `ContextBuilder`, bukan di `Companion`.
- **Ephemeral Context TIDAK PERNAH ditulis ke `prompts/*.txt` maupun ke Memory** — dibangun ulang tiap `chat()`, dikirim sebagai `types.Content` tambahan, tidak pernah persisten.
- **`PromptBuilder` TIDAK PERNAH tahu `BehaviorEngine`/`BehaviorState` ada** — nol import baru di `prompt_builder.py`, tetap cuma menggabungkan `prompts/*.txt` seperti sejak v0.1.
- **`BehaviorEngine.update()` dipanggil SEBELUM Gemini membalas** — parameter `reply` dipassing `""` karena tidak ada satu pun subsystem (Emotion/Relationship/Internal State) yang membaca argumen ini (dikonfirmasi dari implementasi v0.6.2–v0.6.4).
- **`AvatarManager` TIDAK PERNAH baca `BehaviorState` langsung** — cuma `IdleCoordinator` yang boleh terima informasi Mood, dan itu pun cuma **string** (`mood.value`), bukan objek `BehaviorState` utuh.
- **GUI baca `BehaviorState` HANYA lewat `Companion.current_behavior_state()`** (API publik read-only baru) — tidak pernah mengakses `BehaviorEngine` langsung.
- **Gemini tetap dipanggil TEPAT SEKALI per `chat()`** — tidak ada Gemini call tambahan untuk behavior.
- **Kalau `BehaviorEngine.update()` gagal, fallback ke `DEFAULT_BEHAVIOR_STATE`** — chat harus tetap lanjut, behavior failure tidak boleh menghentikan aplikasi.
- **`GeminiClient.send()` sekarang WAJIB validasi `response.text` sebelum return** (bug fix, lihat bagian 7) — mencegah `Part` kosong/invalid tersimpan ke `Conversation` yang bikin request berikutnya ditolak API dengan `400 INVALID_ARGUMENT`.

## 7. Bug yang Sudah Diperbaiki (Kumulatif, Jangan Diulang)

1. **Duplikasi instansiasi `VoiceManager`** (v0.5.1) — Fix: pastikan cuma 1 blok `VoiceManager(...)`.
2. **`httpx.ReadError`/`WinError 10054`** saat TTS (v0.5.1) — Fix: retry otomatis.
3. **Nama model TTS salah** (v0.4) — harus `gemini-2.5-flash-preview-tts`.
4. **Stage direction `(...)` ikut terbaca TTS** (v0.4) — di-strip sebelum sintesis.
5. **Arona salah tanggal/jam** (v0.4) — konteks waktu ephemeral (sekarang lewat `ContextBuilder`, bukan `companion.py` langsung).
6. **`TypeError: unexpected keyword argument 'tts_voice_name'`** (v0.4) — parameter benar `voice_name`.
7. **`400 INVALID_ARGUMENT: ... required oneof field 'data' must have one initialized field`** (v0.6.5, BARU) — **Akar masalah:** kalau `response.text` dari Gemini kosong/`None` (mis. diblokir safety filter, atau kebingungan sesaat karena format ephemeral context baru), `Companion.chat()` sebelumnya langsung `add_assistant_message(reply)` **tanpa validasi**, sehingga `Conversation` menyimpan `types.Part` kosong/invalid. Turn berikutnya, history yang mengandung Part rusak itu dikirim lagi ke Gemini → API menolak dengan error 400. **Fix:** `GeminiClient.send()` sekarang validasi `response.text` sebelum return, raise `GeminiResponseError` kalau kosong; `Companion.chat()` menangkap ini dan `rollback_last_message()` (mencegah pesan Teacher yang gagal dibalas nyangkut di history), lalu re-raise sebagai `CompanionError` dengan pesan ramah ke GUI. **Catatan penting:** karena `Conversation` tidak persisten ke disk, restart aplikasi otomatis membersihkan history yang sudah korup di sesi lama — tapi fix ini mencegah masalah terulang di sesi baru.

Semua bug di atas sudah diperbaiki dan dikonfirmasi user di masing-masing milestone-nya.

## 9. Keputusan Desain Kumulatif (Tambahan v0.6.5)

- **`ContextBuilder` sebagai modul terpisah** (bukan method di `Companion`) — rekomendasi eksplisit GPT (Context Builder Separation Policy), supaya `Companion` tetap murni orchestrator dan format context bisa di-unit-test terpisah serta di-extend tanpa menyentuh `Companion` sama sekali.
- **Konsolidasi formatting waktu ke `ContextBuilder`** (dipindah dari `companion.py`, yang sudah punya `_format_current_datetime` sejak v0.4) — konsisten dengan tujuan Separation Policy: satu modul, satu tanggung jawab penuh atas seluruh teks ephemeral, bukan cuma behavior state.
- **Mood diteruskan ke Avatar sebagai STRING, bukan `BehaviorState` object** — implementasi konkret dari batasan spec "Only IdleCoordinator may receive Mood" sambil tetap menjaga `AvatarManager`/`IdleCoordinator` 100% independen dari struktur internal Behavior Engine (mereka cuma perlu tahu satu kata: "sleepy", "cheerful", dst).
- **`reply=""` di pemanggilan `BehaviorEngine.update()`** — bukan kemalasan, tapi refleksi jujur bahwa Core Philosophy spec memang menempatkan Behavior update SEBELUM Gemini membalas, dan implementasi v0.6.2-v0.6.4 memang tidak pernah butuh parameter itu.
- **Validasi response Gemini ditaruh di `GeminiClient`, bukan di `Companion`** — konsisten dengan tanggung jawab modul itu sendiri ("komunikasi dengan Gemini API" termasuk memastikan hasilnya valid), sama pola dengan keputusan v0.5.1 soal retry TTS ditaruh di `speech/tts.py`.
- **`rollback_last_message()` dipakai ulang untuk kasus balasan kosong** — bukan bikin mekanisme baru, method ini sudah ada sejak v0.1.1 untuk kasus serupa (kegagalan Gemini di tengah proses).

## 10. Instruksi Kalau Lanjut Chat Baru

1. **Jangan redesign arsitektur** yang sudah ada (bagian 4–6) tanpa alasan kuat (bug kritis).
2. **Jangan ubah** `ai/prompt_builder.py`, `ai/conversation.py`, `database/memory_manager.py`, `speech/*` inti, `avatar/*` inti (kecuali `blink.py`/`idle.py` yang memang additive di v0.6.5), atau `prompts/*.txt` kecuali diminta eksplisit.
3. **Jangan import PySide6/Qt di luar folder `ui/`.**
4. **Jangan pernah mencampur Memory dan Conversation. Jangan perkenalkan vector DB/RAG.**
5. **`Companion` TIDAK BOLEH merangkai string context sendiri** — semua formatting context (waktu, behavior, dan nanti visual/routine di Phase 3) WAJIB lewat `ContextBuilder`. Kalau ada kebutuhan menambah info ke context, extend `ContextBuilder`, bukan `Companion`.
6. **Ephemeral Context (apa pun isinya nanti) TIDAK BOLEH ditulis ke `prompts/*.txt` atau ke Memory** — harus selalu dibangun ulang tiap request dan dibuang setelahnya.
7. **`PromptBuilder` TIDAK BOLEH tahu `BehaviorEngine`/`BehaviorState` ada** — kalau ada permintaan "biar system prompt-nya include info emosi", ingatkan ini melanggar Ephemeral Context Injection Policy; solusinya tetap lewat `ContextBuilder`+injection ke `contents`, bukan `PromptBuilder`.
8. **`AvatarManager` tidak boleh baca `BehaviorState` langsung** — kalau ada subsystem avatar baru (v0.5.2 lanjutan atau lainnya) yang butuh info behavior, harus lewat parameter sederhana (seperti pola `apply_mood(mood_name: str)`), bukan inject `BehaviorState` utuh ke avatar layer.
9. **GUI baca `BehaviorState` HANYA lewat `Companion.current_behavior_state()`** — tidak pernah `from behavior.behavior_engine import BehaviorEngine` di `ui/`.
10. **`GeminiClient.send()` HARUS tetap validasi response sebelum return** — jangan hapus validasi ini walau kelihatan "jarang kejadian", ini bug nyata yang pernah terjadi.
11. **Analyzer/Coordinator manapun di `behavior/` TIDAK BOLEH memanggil Gemini.**
12. **`BehaviorState` HARUS tetap cuma 3 field state** (`emotion`, `relationship`, `internal`) — dimensi baru masuk ke `InternalState`, bukan field baru di `BehaviorState`.
13. **Persistence data behavior HARUS lewat method publik `MemoryManager`**, kategori `"general"` + marker unik — jangan tabel/kategori baru.
14. **SELALU CEK jumlah instansiasi objek berat** (`VoiceManager`, Whisper, `Companion`) di `ui/window.py` kalau menambah/memindah blok inisialisasi.
15. **Perhatikan penamaan parameter constructor yang benar** — cek signature dulu kalau ragu (`VoiceManager`, `AvatarManager`, `BehaviorEngine`, `EmotionCoordinator`, `RelationshipCoordinator`, `InternalStateCoordinator`, `ContextBuilder`, semuanya).
16. **Gunakan penomoran versi yang benar**: Phase 2 (v0.6.0–v0.6.5) **SUDAH TUNTAS SEPENUHNYA**. Milestone berikutnya adalah **v0.7 Vision**, awal Phase 3 — Intelligence.
17. Kalau user minta fitur baru, cek dulu masuk Phase/versi berapa (tabel bagian 2).
18. Semua modul baru tetap Single Responsibility; logic tidak boleh nyasar antar folder.
19. User berkomunikasi dalam Bahasa Indonesia; kode & komentar teknis boleh Inggris seperlunya, penjelasan ke user pakai Bahasa Indonesia.
20. Kalau butuh tau isi kode file tertentu yang belum di-paste di chat baru, minta user paste isinya dulu — jangan asumsikan berubah dari yang didokumentasikan di sini kecuali dikonfirmasi.
