## 1. Apa Project Ini

AI Waifu Companion desktop app, terinspirasi Arona (Blue Archive). Bukan sekadar chatbot — dirancang modular supaya bisa berkembang jadi companion dengan voice, avatar Live2D, memory, emosi, dll.

**Prinsip pengembangan:** incremental, per-milestone, jangan lompat fitur, jangan overengineering, jangan redesign arsitektur tanpa alasan kuat.

**Filosofi inti:** Desktop GUI **bukan** aplikasinya. Aplikasi sesungguhnya adalah `Companion`. GUI hanyalah salah satu presentation layer. Voice Interface, Discord Bot, atau Web Interface semuanya bisa dipasang di atas `Companion` yang sama tanpa mengubah backend. Setiap modalitas (keyboard, mic) akhirnya jadi teks sebelum mencapai `Companion` — `Companion` tidak pernah tahu dari mana teks itu berasal:

```
Keyboard  → Text ─┐
Mic → STT → Text ─┴→ Companion (+ Memory + waktu) → Gemini → Text → GUI / TTS → Speaker
```

v0.2 dipikirkan sebagai **Desktop Shell** (bukan sekadar Chat Window) — cangkang yang nanti diisi Chat, Memory, Voice, Avatar, Settings, Emotion, Vision, Automation.

**Human-in-the-Loop Memory Policy (sejak v0.3):** Memory adalah milik Teacher. Arsitektur harus siap kapan pun untuk fitur show/edit/delete/forget memori. Arona tidak boleh jadi sistem memori yang tidak bisa dikontrol.

## 4. Arsitektur (WAJIB Dipertahankan)

```
Terminal (main.py)     Desktop GUI (main_gui.py + ui/window.py)
        │                              │
        └──────────────┬───────────────┘
                        ↓
                   Companion (ai/companion.py)
                        ↓
     ┌──────────────────┼──────────────────┐
     ↓                  ↓                  ↓
Conversation       MemoryManager       GeminiClient
(ai/conversation)  (database/          (ai/gemini.py)
                    memory_manager)          ↓
                        ↓                Gemini API (teks)
                     memory.db

Jalur terpisah untuk suara (tidak lewat Companion untuk STT/TTS):

Mic → Recorder → SpeechToText (Faster Whisper)
                        ↓
                  Companion.chat(text)   ← SAMA PERSIS dengan jalur teks
                        ↓
                     reply (str)
                        ↓
              TextToSpeech (Gemini TTS) → AudioPlayer → Speaker
```

**Aturan besi:**
- `Companion` adalah satu-satunya modul yang tahu soal `Conversation`, `MemoryManager`, **dan** `GeminiClient` sekaligus.
- `VoiceManager` adalah satu-satunya modul yang tahu urutan `Recorder → STT → Companion → TTS → Player`. Modul speech lain (`recorder.py`, `whisper.py`, `tts.py`, `player.py`) **saling independen** — tidak saling import, tidak tahu GUI, tidak tahu Gemini chat.
- UI (terminal maupun GUI) **hanya** boleh panggil `Companion.chat()/get_history()/clear_history()/list_memories()/delete_memory()/clear_memories()`, dan `VoiceManager.start_recording()/cancel_recording()/speak()` + method internal yang dipanggil lewat `VoiceWorker`/`SpeakWorker`.
- UI **tidak boleh** import `GeminiClient`, `MemoryManager`, `Recorder`, `SpeechToText`, `TextToSpeech`, `AudioPlayer`, atau `types.Content` secara langsung.
- **UI Independence**: PySide6/Qt **tidak boleh** di-import di luar folder `ui/`. Backend (termasuk seluruh `speech/*`) tidak boleh tahu bahwa GUI itu ada — komunikasi state ke GUI lewat `Callable` biasa yang "diterjemahkan" jadi Qt Signal di `ui/voice_worker.py` / `ui/speak_worker.py`.
- **Conversation vs Memory — TIDAK BOLEH DICAMPUR.** `Conversation` = sementara/per sesi. `Memory` (SQLite) = permanen/lintas sesi. `Conversation` tidak boleh punya method save/search/load memory. `memory.db` tidak boleh menyimpan history chat.
- **`Companion.chat(text) -> str` adalah satu-satunya pintu ke Gemini teks**, dipakai identik oleh jalur keyboard maupun jalur voice (setelah STT) — supaya Memory otomatis ikut berfungsi di kedua jalur tanpa kode tambahan.
- **Konteks waktu real-time** (hari/tanggal/jam WIB) dan **memori** sama-sama di-inject secara **ephemeral** oleh `Companion._build_contents()` — dibangun ulang setiap `chat()` dipanggil, tidak pernah disimpan ke `Conversation`. `PromptBuilder` tetap tidak tahu keduanya ada.
- `ai/gemini.py`, `ai/prompt_builder.py`, `ai/personality.py`, `ai/conversation.py`, dan seluruh `prompts/*.txt` **belum pernah diubah** sejak v0.1.0/v0.1.1 dan seharusnya tetap begitu sampai ada bug kritis.
- Tidak ada vector DB/RAG. Success criteria v0.2–v0.4: kalau `main.py` dihapus, sisanya tetap jalan. Kalau memori atau voice gagal, chat teks tetap jalan (graceful degrade).

- **Framework:** PySide6. **Konsep:** Desktop Shell (mirip Discord/Telegram Desktop/VS Code).
- **Tema:** Dark, aksen biru lembut (`#4a90e2`), `ui/theme.py`. **Window:** default `1000x700`, min `900x600`.
- **Layout:** Menu Bar → Sidebar permanen (170px, semua item masih "Coming Soon" non-fungsional kecuali Chat) → Chat Area (avatar bulat tiap bubble) → **Input box + 🎤 Mic Button + Send button** → Status Bar.
- **Mic Button (baru v0.4):** klik pertama → `voice_manager.start_recording()` langsung di main thread (cepat, cuma buka stream), tombol berubah jadi ⏹. Klik kedua → jalankan `VoiceWorker` (background thread) yang memanggil `stop_recording_and_respond()`; hasil (`user_text`, `reply`) ditambahkan sebagai 2 chat bubble (Teacher lalu Arona), status bar mengikuti `VoiceState` (Listening.../Transcribing.../Thinking.../Speaking...).
- **Balasan chat teks juga bersuara (baru, di luar spec awal v0.4, permintaan tambahan):** setelah `ChatWorker` mengirim balasan teks, `MainWindow._speak_text()` menjalankan `SpeakWorker` yang memanggil `voice_manager.speak(reply)` di background — mic button di-disable sementara Arona "berbicara", biar tidak tabrakan dengan rekaman baru.
- **Command hasil (`/help`, `/history`, dll) sengaja TIDAK diucapkan** — cuma balasan chat asli (`_on_reply_received`) yang memicu `_speak_text()`.
- **Threading:** `ChatWorker`, `VoiceWorker`, `SpeakWorker` — tiga `QThread` terpisah, GUI tidak pernah freeze di jalur mana pun.
- **PENTING:** GUI tetap tidak tahu Memory ada (tidak ada import `MemoryManager`), dan tidak tahu detail internal Voice (tidak import `Recorder`/`SpeechToText`/`TextToSpeech`/`AudioPlayer` — cuma `VoiceManager` via worker).
- **Masih dilarang keras:** avatar besar/Live2D/VTube placeholder (jatah v0.5).

## 7. Memory System (v0.3) — Ringkas (Detail Penuh: Lihat Riwayat v0.3)

- Memory ≠ Conversation. Memory = fakta jangka panjang (preferensi, identitas, relasi, project, jadwal, general). Conversation = dialog sementara.
- `Companion._build_contents()` inject hingga 10 memori terbaru sebagai `types.Content` tambahan (ephemeral), lalu `Companion._remember_if_useful()` panggil `MemoryExtractor.extract()` setelah tiap balasan untuk menyimpan fakta baru (dengan dedup exact-match).
- Voice conversations otomatis update Memory sama seperti chat teks — karena `VoiceManager` memanggil `Companion.chat()` yang identik.

## 8. Voice System (v0.4) — Detail Penting

### Alur Kerja (Klik Mic)
1. Klik 1: `MainWindow._handle_mic_click()` → `voice_manager.start_recording()` (main thread, instan) → `Recorder.start()` buka `InputStream`.
2. Klik 2: `VoiceWorker` dijalankan di background → `stop_recording_and_respond()`:
   - `Recorder.stop()` → audio numpy array.
   - `SpeechToText.transcribe()` (Faster Whisper, model size dari `STT_MODEL_SIZE`) → `user_text`. Kalau kosong → `VoiceError`.
   - `Companion.chat(user_text)` → `reply`. Error Gemini dibungkus jadi `VoiceError`.
   - `_speak(reply)` internal → `TextToSpeech.synthesize()` (buang stage direction dulu) → `AudioPlayer.play()`.
3. Semua kegagalan di titik mana pun → `VoiceError`/exception di-catch, dikembalikan ke `VoiceState.IDLE`, ditampilkan sebagai bubble Arona di GUI (via `VoiceWorker.error_occurred`) — **tidak pernah crash aplikasi**.

### Alur Kerja (Ketik Teks, Ingin Didengar)
1. `ChatWorker` selesai → `MainWindow._on_reply_received(reply)` → tambah bubble teks → panggil `_speak_text(reply)`.
2. `SpeakWorker` (background) → `voice_manager.speak(reply)` → `TextToSpeech.synthesize()` (strip stage direction) → `AudioPlayer.play()`.
3. Mic button di-disable selama proses ini, di-enable lagi setelah `finished_speaking`.

### Konfigurasi Model (`config/constants.py`)
```python
TTS_MODEL_NAME = "gemini-2.5-flash-preview-tts"   # BUKAN "gemini-2.5-flash-tts" — nama ini pernah salah dan bikin TTS gagal diam-diam
TTS_VOICE_NAME = "Zephyr"                          # voice preset Gemini TTS, dipilih user karena "imut"
STT_MODEL_SIZE = "medium"                          # dinaikkan dari "base" — hasil transkripsi lebih akurat
```

### Bug yang Sudah Diperbaiki (Jangan Diulang di Chat Baru)
1. **Nama model TTS salah** (`gemini-2.5-flash-tts` → seharusnya `gemini-2.5-flash-preview-tts`, model masih Preview) — menyebabkan TTS gagal *diam-diam* karena error dibungkus `except Exception` yang cuma log warning. Sudah diperbaiki + logging diperkuat pakai `logger.exception` supaya traceback lengkap kecatat di `logs/app.log`.
2. **Stage direction `(...)` ikut terbaca TTS** — diperbaiki di `speech/tts.py` dengan regex strip sebelum sintesis. Chat bubble GUI tetap menampilkan teks asli apa adanya.
3. **Arona salah tanggal/jam** (LLM tidak tahu waktu real-time) — diperbaiki dengan inject konteks waktu (`_format_current_datetime()`, pakai `ZoneInfo("Asia/Jakarta")`) secara ephemeral di `Companion._build_contents()`, sama pola dengan injeksi Memory.
4. **`TypeError: unexpected keyword argument 'tts_voice_name'`** — parameter constructor `VoiceManager` yang benar adalah **`voice_name`**, bukan `tts_voice_name`. Perhatikan penamaan ini kalau menambah parameter baru ke `VoiceManager`/`TextToSpeech` di masa depan.

### Batasan Sengaja (v0.4)
- Tidak ada continuous listening / wake word — murni klik-klik manual.
- Tidak ada streaming STT/TTS (semua request/response penuh, bukan chunk).
- `Recorder`, `SpeechToText`, `TextToSpeech`, `AudioPlayer` masing-masing **instance dibuat sekali** di `VoiceManager.__init__()` (bukan global, bukan dibuat ulang tiap request) — penting karena load model Whisper berat.
- Model Faster Whisper (`medium`) di-download otomatis sekali di awal (butuh internet saat pertama kali), lalu di-cache lokal oleh `huggingface_hub`.

## 11. Keputusan Desain Kumulatif

- **`GeminiClient` stateless.**
- **`Companion` satu pintu masuk backend** untuk teks (dipakai identik oleh keyboard & voice) — koordinasi Conversation + Memory + waktu.
- **`VoiceManager` satu pintu masuk untuk voice**, modul speech lain saling independen.
- **Command system dipisah dari UI.** **Logging di level backend.** **Avatar chat bubble di-cache.**
- **`main.py` dan `main_gui.py` dipisah total.** **Stylesheet di `ui/theme.py`.** **Sidebar non-fungsional (shell).**
- **Avatar besar/Live2D sengaja tanpa placeholder** — ditunda total sampai v0.5.
- **Memory dipisah total dari Conversation**, injeksi ephemeral (bukan lewat `PromptBuilder`).
- **Keputusan "layak diingat atau tidak" via Gemini call terpisah (`MemoryExtractor`)**, bukan if-statement manual, bukan RAG.
- **Konteks waktu real-time juga diinjeksi ephemeral**, pola sama persis dengan Memory — supaya konsisten dan gampang dipahami.
- **Stage direction `(...)` di-strip sebelum TTS, bukan sebelum ditampilkan di GUI** — teks tampilan dan teks terucap sengaja berbeda representasinya, keduanya sah sesuai konteks masing-masing.
- **`Recorder`/`SpeechToText`/`TextToSpeech`/`AudioPlayer` masing-masing instance sekali pakai selama runtime**, dipegang oleh `VoiceManager` — bukan global, bukan re-instansiasi tiap request (biar model berat kayak Whisper tidak di-load berulang).
- **Balasan chat teks ikut diucapkan lewat `SpeakWorker` yang reuse `VoiceManager.speak()`** — bukan modul TTS terpisah baru, supaya tidak ada duplikasi loading model/instance TTS.
- **Semua kegagalan di pipeline memori maupun voice di-swallow jadi log (`logger.warning`/`logger.exception`)** — chat tidak pernah crash karena SQLite, STT, atau TTS gagal.

## 12. Instruksi Kalau Lanjut Chat Baru

1. **Jangan redesign arsitektur** di bagian 4–8 tanpa alasan kuat (bug kritis).
2. **Jangan ubah** `ai/gemini.py`, `ai/personality.py`, `ai/prompt_builder.py`, `ai/conversation.py`, atau isi `prompts/*.txt` kecuali diminta eksplisit.
3. **Jangan import PySide6/Qt di luar folder `ui/`.**
4. **Jangan tambahkan avatar besar/Live2D/placeholder karakter** ke GUI kecuali sudah eksplisit masuk fase v0.5.
5. **Jangan pernah mencampur Memory dan Conversation.**
6. **Jangan perkenalkan vector DB/RAG.**
7. **Perhatikan penamaan parameter yang benar:** `VoiceManager(..., voice_name=...)` — bukan `tts_voice_name`. Selalu cek signature sebelum manggil constructor kalau ragu.
8. **Kalau menambah fitur voice baru, jangan gabungkan tanggung jawab** `recorder.py`/`whisper.py`/`tts.py`/`player.py` — masing-masing tetap single-purpose, `VoiceManager` tetap satu-satunya orkestrator.
9. **`TTS_MODEL_NAME` dan model TTS Gemini masih berstatus Preview** — kalau ada perubahan/error terkait model ini di masa depan, cek dulu apakah ID model berubah lagi di dokumentasi resmi sebelum asumsi kodenya yang salah.
10. Kalau user minta fitur baru, cek dulu masuk milestone versi berapa (tabel bagian 2) — kalau versi depan, tanya dulu apakah user mau lompat milestone atau cuma nyiapin arsitektur.
11. Semua modul baru tetap Single Responsibility; backend logic tidak boleh nyasar ke `ui/`, dan `MemoryManager`/`Recorder`/`SpeechToText`/`TextToSpeech`/`AudioPlayer` tidak boleh diakses langsung dari `ui/` — harus lewat `Companion`/`VoiceManager`.
12. User berkomunikasi dalam Bahasa Indonesia; kode & komentar teknis boleh Inggris seperlunya, penjelasan ke user pakai Bahasa Indonesia.
13. Kalau butuh tau isi kode file tertentu yang belum di-paste di chat baru, minta user paste isinya dulu — jangan asumsikan berubah dari yang didokumentasikan di sini kecuali dikonfirmasi.
