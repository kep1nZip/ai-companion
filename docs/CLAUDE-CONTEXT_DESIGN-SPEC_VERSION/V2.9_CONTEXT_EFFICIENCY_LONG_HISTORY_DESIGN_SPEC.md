## 1. Milestone Decision

v2.8 membuat Arona lebih memahami percakapan yang sedang berlangsung. Audit v2.8 menemukan bahwa `Conversation` masih mengirim raw history, sedangkan v2.6 sudah menyediakan optional history cap tetapi default masih **unbounded**. Topic-aware selection sengaja ditunda karena belum ada evidence bahwa mekanisme last-N diperlukan.

Karena v2.8 sekarang selesai dan `main_gui.py` sudah divalidasi aman, **v2.9 difokuskan pada efisiensi dan skalabilitas context**, bukan menambah kemampuan companion baru secara besar-besaran.

> **Tujuan v2.9: Arona tetap koheren ketika percakapan semakin panjang, sambil menghindari context yang boros, pemotongan history yang berbahaya, dan optimasi yang belum terbukti dibutuhkan.**

---

## 2. Core Principle

```text
Conversation quality
        +
Context efficiency
        +
Measured limits
        ↓
Stable long conversations
```

Prinsip utama:

```text
Measure before limiting.
Recent context before old context.
Relevant context before irrelevant context.
No arbitrary cap.
No semantic infrastructure without evidence.
```

---

## 3. Goals

v2.9 harus:

1. Mengukur ukuran history dan context yang benar-benar digunakan.
2. Mengukur dampak history terhadap prompt size dan latency.
3. Menentukan secara evidence-based apakah history cap perlu diaktifkan.
4. Bila cap diperlukan, menentukan batas berdasarkan baseline nyata.
5. Mempertahankan recent conversation dan reference resolution.
6. Mengendalikan context lama yang sudah tidak relevan.
7. Menambahkan topic-aware selection sederhana **hanya jika baseline membuktikan last-N tidak cukup**.
8. Tetap provider-agnostic untuk Local dan Gemini.
9. Menjaga Voice, Autonomous, Vision, Memory, Initiative, dan GUI tetap aman.

---

## 4. Non-Goals

v2.9 **tidak boleh** menjadi alasan untuk membuat:

- Plugin System.
- Outfit System.
- Multi-agent architecture.
- Agent planner.
- Second Companion orchestrator.
- Second LLM classification call per turn.
- New conversation database.
- Vector DB / embedding pipeline tanpa evidence.
- RAG framework besar.
- Persistent topic database.
- Separate Voice history.
- Separate Autonomous history.
- Provider-specific Conversation logic.
- Memory schema redesign.
- Vision redesign.
- Initiative/Routine redesign.
- TTS migration.
- Avatar redesign.
- Arbitrary hard-coded history limit.

## 8. Phase 2 — History Budget Decision

**Tidak boleh menetapkan angka cap sebelum baseline tersedia.**

Decision:

```text
IF history remains acceptable
AND context cost remains practical
AND quality is stable
    → keep existing behavior
```

Sebaliknya:

```text
IF history materially increases context cost
AND older context provides low value
AND quality can be preserved
    → introduce bounded history
```

Cap harus:

- configurable lewat configuration mechanism yang sudah ada;
- mudah dimatikan;
- observable;
- tidak memangkas recent turns secara berbahaya.

Jika evidence belum cukup:

```text
DO NOT activate a new default cap.
```

---

## 9. Phase 3 — Safe History Window

Jika Phase 2 membuktikan cap diperlukan, **reuse mekanisme v2.6**.

Prioritas:

```text
Current Teacher message
        ↓
Immediate previous turns
        ↓
Current conversation turns
        ↓
Recent conversation
        ↓
Older conversation
```

Jangan melakukan random truncation.

Idealnya pertahankan pasangan:

```text
user turn
   +
assistant response
```

agar history tidak rusak secara semantik.

---

## 10. Phase 4 — Topic-Aware Selection (Conditional)

Phase ini **hanya dieksekusi jika baseline menunjukkan last-N tidak cukup**.

Implementasi pertama harus sederhana:

```text
recency
+
lexical overlap
+
explicit follow-up markers
+
current position
```

Contoh:

```text
History:

A1 A2 A3
B1 B2
C1
D1 D2

Current:
"Kalau yang tadi B2 gimana?"
```

Selection dapat menjadi:

```text
B1
B2
+
recent turns
+
current message
```

**Jangan langsung membuat:** embeddings, vector DB, semantic index, RAG, atau second LLM classifier.

---

## 11. Phase 5 — Reference Safety

History selection tidak boleh merusak reference resolution.

Test:

```text
Teacher:
"Kenapa API-ku error 500?"

Arona:
...

Teacher:
"Kalau yang tadi pakai async gimana?"
```

Expected: reference tetap dapat di-resolve.

Ambiguous:

```text
"Yang itu gimana?"
```

Expected: clarification bila retained context memang tidak cukup.

Tidak boleh confident guessing dari context yang sudah terpotong.

## 12. Phase 6 — Relevance vs Recency

## 18. Memory Boundary

Memory dan Conversation tetap berbeda:

```text
Memory
→ persistent fact

Conversation
→ immediate discussion context
```

History optimization tidak boleh:

- memindahkan conversation turns menjadi memory;
- mengubah memory schema;
- memakai superseded memory sebagai replacement history;
- menghapus active memory karena history cap.

---

## 19. Vision Boundary

Vision tetap mengikuti freshness rules yang sudah ada.

Tetap:

```text
Vision ≠ conversation authority
```

History optimization tidak boleh membuat stale vision terlihat current hanya karena context lama masih tersedia.

## 23. Decision Gate

### PASS

v2.9 PASS apabila:

- context size terukur;
- history behavior dipahami;
- cap baru evidence-based atau tidak diaktifkan karena belum perlu;
- tidak ada truncation berbahaya;
- recent conversation tetap coherent;
- reference resolution tetap stabil;
- topic shift tetap natural;
- closure/repetition v2.8 tidak regress;
- Local bekerja;
- Gemini bekerja;
- Voice/Text continuity intact;
- Autonomous intact;
- Memory intact;
- Vision freshness intact;
- Developer observability truthful;
- GUI responsive;
- tidak ada critical regression.

### CONDITIONAL PASS

Boleh bila:

- topic-aware selection ditunda karena belum ada evidence;
- cap tetap unbounded karena measurement belum menunjukkan masalah berarti;
- optimasi ada tetapi gain kecil dan arsitektur tervalidasi.

Limitasi harus didokumentasikan.

### FAIL

FAIL apabila:

- recent context sistematis hilang;
- references menjadi lebih buruk;
- old irrelevant history mendominasi;
- context optimization memperburuk behavior;
- arbitrary cap diterapkan tanpa evidence;
- second LLM classifier muncul tanpa approval;
- boundary v2.8 rusak;
- critical regression muncul.
