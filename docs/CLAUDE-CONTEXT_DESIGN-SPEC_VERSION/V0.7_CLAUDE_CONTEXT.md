## 1. Apa Project Ini

AI Waifu Companion desktop app, terinspirasi Arona (Blue Archive). Bukan sekadar chatbot — dirancang modular supaya bisa berkembang jadi companion dengan voice, avatar Live2D, memory, emosi, vision, dll.

**Prinsip pengembangan:** incremental, per-milestone, jangan lompat fitur, jangan overengineering, jangan redesign arsitektur tanpa alasan kuat.

**Filosofi inti:** Desktop GUI **bukan** aplikasinya. Aplikasi sesungguhnya adalah `Companion`. Sejak v0.7, `ContextBuilder` menggabungkan **2 sumber context opsional**:

```
Teacher
  ↓
Companion.chat(user_input)
  ↓
Conversation.add_user_message()
  ↓
BehaviorEngine.update() → BehaviorState (WAJIB ada, selalu di-generate)
Vision.get_context() → VisionContext (OPSIONAL — reuse kalau masih fresh, None kalau Vision mati/belum capture)
  ↓
ContextBuilder.build(behavior_state, vision_context) → Ephemeral Context (text, TIDAK PERNAH disimpan)
  ↓
GeminiClient.send(system_prompt + ephemeral_context + memori + history) → reply
  ↓
Conversation.add_assistant_message(reply)
  ↓
GUI chat bubble │ TTS → AudioPlayer + Lip Sync │ HaloMapper → Hotkey │ IdleCoordinator.apply_mood(mood_string)
```

**Human-in-the-Loop Memory Policy (v0.3).** **Avatar Independence Policy (v0.5).** **Animation Independence Policy (v0.5.1/v0.6.1).** **Behavior Engine Policy (v0.6.0).** **Emotion Transition Policy (v0.6.2).** **Relationship Base/Current Policy (v0.6.3).** **BehaviorState Single Source of Truth Policy (v0.6.4).** **Ephemeral Context Injection Policy & Context Builder Separation Policy (v0.6.5).** **Vision Independence Policy (v0.7, BARU):** `vision/*` **tidak boleh** tahu Behavior/Avatar/Voice/GUI/Memory/PromptBuilder ada — Vision cuma komunikasi lewat `Companion`. **Vision Context Injection Policy (v0.7, BARU):** `VisionContext` tidak pernah masuk prompt file, tidak pernah persisten — ephemeral sama seperti `BehaviorState`, digabung `ContextBuilder`, **opsional** (rekomendasi GPT — pipeline harus tetap jalan normal walau Vision mati). **Vision Freshness Policy (v0.7, BARU):** `VisionContext` punya TTL; kalau masih fresh, **reuse**, jangan capture ulang. Capture cuma manual, tidak ada polling otomatis.

## 4. Arsitektur (WAJIB Dipertahankan)

```
Terminal (main.py)     Desktop GUI (main_gui.py + ui/window.py)
        │                              │
        └──────────────┬───────────────┘
                        ↓
                   Companion (ai/companion.py)   ← vision: Optional[Vision] = None
                        ↓
     ┌──────────────────┼──────────────────┬──────────────┬─────────────┐
     ↓                  ↓                  ↓              ↓             ↓
Conversation       MemoryManager       GeminiClient   BehaviorEngine   Vision (OPSIONAL)
                        ↓                                   ↓              ↓
                     memory.db                     (Emotion/Relationship/  screen_capture.py
                                                      Internal State)       image_analyzer.py
                                                                            vision_context.py

Companion.chat(user_input):
   1. Conversation.add_user_message(user_input)
   2. behavior_state = BehaviorEngine.update(user_input, "")           [WAJIB, selalu ada]
   3. vision_context = Vision.get_context() if self._vision else None  [OPSIONAL — REUSE SAJA, TIDAK capture baru]
   4. ephemeral_text = ContextBuilder.build(behavior_state, vision_context)
   5. contents = [ephemeral_context, memori(ephemeral), *history]
   6. reply = GeminiClient.send(contents)
   7. Conversation.add_assistant_message(reply)
   8. MemoryExtractor.extract()

Companion.capture_vision():   ← trigger MANUAL EKSPLISIT (mis. tombol GUI masa depan), TIDAK PERNAH dipanggil dari chat()
   Vision.refresh() → ScreenCapture.capture() → ImageAnalyzer.analyze() → parse_vision_context() → VisionContext baru

Vision.analyze(image=None, source="screen"):   ← GENERIC, siap multimodal (webcam/upload nanti tanpa ubah arsitektur)
```

**Aturan besi (v0.1–v0.6.5, tetap berlaku penuh):** `Companion` satu-satunya koordinator Conversation+Memory+Gemini+Behavior+**sekarang Vision**. UI Independence. `BehaviorState` cuma 3 field. `Companion` tidak boleh merangkai string context sendiri — lewat `ContextBuilder`.

**Aturan besi BARU v0.7 — Vision System:**
- **`vision/*` tidak boleh import apa pun dari `behavior/`, `avatar/`, `speech/`, `ui/`, `database/`, atau `ai/prompt_builder.py`** — satu-satunya "tetangga" yang boleh diketahui Vision adalah `config/` (constants, logger, settings) dan `google.genai`/`PIL`/`mss` (dependency eksternal).
- **`ScreenCapture` adalah abstract base class** — `Vision`/`Companion` cuma kenal interface `capture() -> Image`, tidak pernah tahu implementasi konkretnya (`MssScreenCapture` sekarang, bisa diganti implementasi lain nanti tanpa ubah kode pemanggil).
- **`Vision.analyze()` menerima `image` sebagai parameter generik** (`Optional[Image.Image] = None`, fallback ke capture terakhir kalau `None`) — **BUKAN** `analyze_screen()`. Ini yang bikin webcam/upload gambar user bisa ditambah nanti tanpa mengubah method signature.
- **`VisionContext` adalah dataclass immutable** (pola sama persis `BehaviorState`/`EmotionState`) — `summary`, `application`, `timestamp`, `ttl`, `source`. `ContextBuilder` yang mengubahnya jadi teks, `vision_context.py` sendiri tidak pernah menghasilkan string akhir untuk Gemini.
- **`ContextBuilder.build()` menerima `vision_context` sebagai parameter OPSIONAL** (`Optional[VisionContext] = None`) — kalau `None`/Vision tidak aktif, `ContextBuilder` skip section Visual Context, pipeline tetap jalan normal 100%.
- **Capture HANYA manual, tidak ada polling/automatic screenshot** — `Companion.chat()` **tidak pernah** memicu capture baru, cuma `get_context()` (reuse pasif). Capture baru cuma lewat `Companion.capture_vision()` yang harus dipanggil eksplisit dari luar (nanti tombol GUI).
- **Vision Context TIDAK PERNAH disimpan ke disk/SQLite/Conversation** — cuma `Vision._current_context` (in-memory, 1 objek, di-overwrite tiap capture baru) dan `_last_captured_image` (in-memory, PIL Image, tidak pernah di-save ke file).
- **`ImageAnalyzer` tidak pernah return/expose JSON mentah** — parsing dari teks natural Gemini Vision via regex sederhana (`parse_vision_context`), bukan structured output/JSON schema.
- **Avatar dan Voice mengabaikan Vision sepenuhnya** — tidak ada ekspresi/animasi/perubahan suara berdasarkan Vision di milestone ini (eksplisit "Current milestone does not" di spec).
- **Behavior Engine tidak diupdate oleh Vision** — `Vision` read-only terhadap konteks, tidak pernah memanggil `BehaviorEngine.update()` atau method lain yang mengubah Emotion/Relationship/Internal State.

### `vision/screen_capture.py` — `ScreenCapture` (ABC) + `MssScreenCapture` (BARU v0.7)
```python
class ScreenCapture(ABC):
    @abstractmethod
    def capture(self) -> Image.Image: ...

class MssScreenCapture(ScreenCapture):
    def __init__(self, monitor_index: int = 1)
    def capture(self) -> Image.Image   # via library `mss`, cross-platform
```

### `vision/image_analyzer.py` — `ImageAnalyzer` (BARU v0.7)
```python

```

### `vision/vision_context.py` — `VisionContext` (dataclass immutable) + `parse_vision_context` (BARU v0.7)
```python
@dataclass(frozen=True)
class VisionContext:
    summary: str
    application: Optional[str] = None
    timestamp: datetime
    ttl: float = 30.0
    source: str = "screen"   # "screen" | "webcam" | "upload" (siap multimodal)
    age_seconds() -> float
    is_fresh() -> bool       # age_seconds() <= ttl

parse_vision_context(raw_text: str, source: str = "screen", ttl: float = 30.0) -> VisionContext
```

### `vision/vision.py` — `Vision` (BARU v0.7, public API)
```python
Vision(screen_capture: ScreenCapture, image_analyzer: ImageAnalyzer, default_ttl: float = 30.0)

get_context() -> Optional[VisionContext]                           # REUSE kalau fresh, TIDAK capture baru
refresh(source: str = "screen") -> Optional[VisionContext]         # paksa capture+analyze baru; capture gagal → context LAMA dipertahankan
```

## 9. Keputusan Desain Kumulatif (Tambahan v0.7)

- **`ScreenCapture` sebagai ABC sejak hari pertama** — rekomendasi eksplisit GPT #1, menghindari platform lock-in. Implementasi `mss` dipilih karena native cross-platform (Windows/Linux/macOS) tanpa perlu percabangan kode per-OS di dalam Vision sendiri.
- **`VisionContext` sebagai dataclass immutable, bukan string** — rekomendasi GPT #2, konsisten dengan pola arsitektur yang sudah mapan sejak `BehaviorState`/`EmotionState`/`RelationshipState` (v0.6.x): representasi terstruktur dulu, baru `ContextBuilder` yang mengubahnya jadi teks di titik paling akhir.
- **`Vision.analyze(image)` generik, bukan `analyze_screen()`** — rekomendasi GPT #3, secara sengaja "over-engineer" API-nya sedikit di awal supaya webcam/upload gambar user bisa ditambah di masa depan tanpa breaking change ke signature method.
- **`VisionContext` opsional di `ContextBuilder.build()`** — rekomendasi GPT #4, memastikan Vision benar-benar independen: mati total tanpa Vision terpasang, `Companion`/`ContextBuilder` tidak pernah error atau berubah perilaku selain kehilangan 1 section context.
- **`ImageAnalyzer` dan `vision_context.py` dipisah tegas** (kirim+terima teks vs parsing jadi struktur) — cermin dari pemisahan `RelationshipAnalyzer`/`relationship_rules.py` di v0.6.3: satu modul bicara ke API eksternal, modul lain menerjemahkan hasilnya jadi domain object.
- **`Vision.get_context()` reuse-only, `refresh()` paksa capture baru** — dua method terpisah secara sengaja supaya `Companion.chat()` (dipanggil sangat sering) tidak pernah memicu biaya capture+Gemini Vision call tambahan, sementara ada jalur eksplisit (`capture_vision()`) untuk trigger manual yang jelas kapan dipanggilnya.

## 10. Instruksi Kalau Lanjut Chat Baru

1. **Jangan redesign arsitektur** yang sudah ada (bagian 4–6) tanpa alasan kuat (bug kritis).
2. **Jangan ubah** `ai/prompt_builder.py`, `ai/conversation.py`, `database/memory_manager.py`, `speech/*` inti, `avatar/*` inti, `behavior/*` inti, atau `prompts/*.txt` kecuali diminta eksplisit.
3. **Jangan import PySide6/Qt di luar folder `ui/`.**
4. **Jangan pernah mencampur Memory dan Conversation. Jangan perkenalkan vector DB/RAG.**
5. **`vision/*` TIDAK BOLEH import dari `behavior/`, `avatar/`, `speech/`, `ui/`, `database/`, atau `ai/prompt_builder.py`** — Vision Independence Policy, cuma boleh komunikasi lewat `Companion`.
6. **Jangan implementasikan OCR/object detection/face recognition/window hooks/continuous capture/automatic monitoring** — Vision cuma "1 screenshot manual → 1 Gemini call → 1 VisionContext", sesuai spec eksplisit.

8. **`ScreenCapture` harus tetap abstract** — kalau nanti nambah implementasi baru (Linux-specific, macOS-specific, dll), buat class baru yang extend `ScreenCapture`, jangan ubah interface yang sudah ada.
9. **`Vision.analyze()` harus tetap generik (`image` sebagai parameter)** — kalau nanti nambah sumber gambar baru (webcam, upload user), jangan bikin method baru (`analyze_webcam()` dst), cukup panggil `analyze(image, source="webcam")`.
10. **`ContextBuilder.build()` harus tetap terima `vision_context` sebagai parameter OPSIONAL** — jangan pernah membuat Vision jadi requirement wajib untuk `ContextBuilder`/`Companion` bekerja.
11. **`Companion` tidak boleh capture Vision otomatis di `chat()`** — cuma `get_context()` (reuse pasif). Capture baru cuma lewat `capture_vision()` yang dipanggil eksplisit dari luar.
12. **`Companion` TIDAK BOLEH merangkai string context sendiri** — semua formatting (termasuk Vision) lewat `ContextBuilder`.
13. **Ephemeral Context (Behavior + Vision) TIDAK BOLEH ditulis ke `prompts/*.txt` atau ke Memory.**
14. **`AvatarManager`/`VoiceManager` tidak boleh baca Vision langsung** — Avatar/Voice ignores Vision di milestone ini; kalau nanti ada permintaan menyambungkan, itu perluasan eksplisit di luar v0.7.
15. **GUI baca Vision HANYA lewat `Companion.capture_vision()`/`current_vision_context()`** — tidak pernah `from vision.vision import Vision` di `ui/`.
16. **Bug/isu #8 (error TTS "should only be used for TTS") BELUM di-root-cause** — kalau muncul lagi dan user minta diperbaiki sungguhan, mulai investigasi dari `speech/tts.py` (pola stage-direction stripping), JANGAN asumsikan sudah pernah diperbaiki.
17. **SELALU CEK jumlah instansiasi objek berat** (`VoiceManager`, Whisper, `Companion`) di `ui/window.py`/`main_gui.py` kalau menambah/memindah blok inisialisasi.
18. **Perhatikan penamaan parameter constructor yang benar** — cek signature dulu kalau ragu (`Companion(vision=...)`, `Vision(screen_capture=..., image_analyzer=..., default_ttl=...)`, dan semua constructor dari milestone sebelumnya).
19. **Gunakan penomoran versi yang benar**: Phase 2 (v0.6.0–v0.6.5) tuntas. **v0.7 Vision System SELESAI** — milestone berikutnya **v0.8 Routine System**.
