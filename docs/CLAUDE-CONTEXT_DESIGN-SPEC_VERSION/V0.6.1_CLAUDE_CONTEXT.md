## 1. Apa Project Ini

AI Waifu Companion desktop app, terinspirasi Arona (Blue Archive). Bukan sekadar chatbot — dirancang modular supaya bisa berkembang jadi companion dengan voice, avatar Live2D, memory, emosi, dll.

**Prinsip pengembangan:** incremental, per-milestone, jangan lompat fitur, jangan overengineering, jangan redesign arsitektur tanpa alasan kuat.

**Filosofi inti:** Desktop GUI **bukan** aplikasinya. Aplikasi sesungguhnya adalah `Companion`. GUI, Voice, Avatar (+animasinya), dan Behavior Engine hanyalah layer di sekitar `Companion`:

```
Teacher
  ↓
Conversation
  ↓
Behavior Engine (skeleton sejak v0.6.0 — BELUM terhubung)  →  BehaviorState
  ↓ (rencana v0.6.5)
Companion (+ Memory + waktu + nanti BehaviorState) → Gemini → reply (str)
  ↓
GUI chat bubble │ TTS → AudioPlayer + Lip Sync │ HaloMapper → Hotkey ekspresi │ Idle Animation (blink+breathing, independen dari reply)
```

**Human-in-the-Loop Memory Policy (v0.3):** Memory milik Teacher. **Avatar Independence Policy (v0.5):** avatar cuma me-render reaksi visual, opsional. **Animation Independence Policy (v0.5.1, diperluas v0.6.1):** sistem animasi avatar terdiri dari layer independen — Lip Sync (mulut), Expression (wajah/hotkey), dan sekarang **Idle** (mata + napas) — tiap layer cuma kontrol parameternya sendiri, `AvatarManager` yang menggabungkan semua layer aktif sebelum kirim ke VTube Studio. **Behavior Engine Policy (v0.6.0):** Behavior Engine cuma menghasilkan state (context), tidak pernah menghasilkan bahasa atau mengontrol animasi langsung.

## 4. Arsitektur (WAJIB Dipertahankan)

```
Terminal (main.py)     Desktop GUI (main_gui.py + ui/window.py)
        │                              │
        └──────────────┬───────────────┘
                        ↓
                   Companion (ai/companion.py)   ← BELUM terhubung ke BehaviorEngine
                        ↓
     ┌──────────────────┼──────────────────┐
     ↓                  ↓                  ↓
Conversation       MemoryManager       GeminiClient
                        ↓
                     memory.db

Voice → TTS → PCM (SAMA, tidak digenerate ulang) ─┬→ AudioPlayer (dengar)
                                                    └→ Lip Sync → AvatarManager.update_parameter_layer("lipsync", "MouthOpen", v)

Reply → HaloMapper → Expression → AvatarManager.react_to_reply() → trigger_hotkey()

Idle Animation (BARU v0.6.1, jalan TERUS-MENERUS selama app hidup, independen dari reply/voice):
AvatarWorker._run_all()
        ↓
IdleCoordinator.start() ────────────────┐
        ↓                               │  (jalan paralel dengan)
IdleScheduler (asyncio task)            │
    ├─ blink loop (interval 4-9s acak)  │  AvatarManager.run_forever()
    └─ breathing loop (tick 0.2s)       │  (connect/auth/reconnect VTS)
        ↓                               │
AvatarManager.update_parameter_layer("blink"/"breathing", "EyeOpen"/"BreathParam", v)
        ↓
ParameterMapper.get_parameter_id() → VTubeStudioClient.set_parameter()

Behavior Engine (v0.6.0, TERISOLASI, belum terhubung ke apa pun — TERMASUK belum ke Idle Animation):
BehaviorEngine(memory_manager=None) → .current -> BehaviorState │ .update() NO-OP │ .reset()
```

**Aturan besi (v0.1–v0.6.0, tetap berlaku penuh):** `Companion` satu-satunya koordinator Conversation+Memory+Gemini. `VoiceManager` satu-satunya koordinator voice pipeline. `AvatarManager` satu-satunya yang boleh bicara ke `VTubeStudioClient`. UI Independence (Qt cuma di `ui/`). Conversation vs Memory tidak boleh dicampur. `BehaviorEngine` tidak boleh bicara ke Gemini/Avatar/Voice/GUI langsung, tidak boleh akses SQLite langsung, `BehaviorState` immutable.

**Aturan besi BARU v0.6.1 — Idle Animation:**
- **Idle Animation adalah layer animasi independen ke-3** (setelah Expression dan Lip Sync) — `layer_name` unik (`"blink"`, `"breathing"`) di `AvatarManager._parameter_layers`, `logical_parameter` unik (`"EyeOpen"`, `"BreathParam"`), sehingga **tidak pernah bentrok** dengan `"lipsync"`/`"MouthOpen"` atau ekspresi wajah (hotkey).
- **Idle Animation TIDAK PERNAH bicara ke `VTubeStudioClient` langsung** — semua update lewat `AvatarManager.update_parameter_layer()`, sama pola dengan Lip Sync.
- **Idle Animation adalah murni layer VISUAL** — tidak menghasilkan balasan, tidak mengubah Memory, tidak memengaruhi logic AI apa pun.
- **`IdleCoordinator.apply_mood()` sudah ada sebagai titik ekstensi tapi BELUM dipanggil dari mana pun** — Behavior Engine (v0.6.0 skeleton) masih 100% terisolasi, belum ada baris kode yang menghubungkan `BehaviorEngine` ke `IdleCoordinator`. Koneksi nyata baru terjadi di **v0.6.5 Behavior Integration**.
- **Idle Animation berjalan terus-menerus selama `AvatarWorker` hidup** (bukan dipicu per-event seperti reaksi ekspresi/lip sync) — tapi otomatis diam kalau avatar belum `READY` (state check yang sudah ada sejak v0.5), jadi tetap sesuai Avatar Independence Policy: aman walau VTube Studio belum/tidak terbuka.
- **Tidak ada busy loop** — semua pakai `asyncio.sleep()`; breathing tick tiap 0.2 detik dengan logging di-throttle (~tiap 5 detik) supaya tidak spam log/CPU.

## 9. Keputusan Desain Kumulatif (Tambahan v0.6.1)

- **Idle Animation dipecah jadi 5 file kecil** (`blink.py`, `breathing.py`, `idle.py`, `idle_scheduler.py`, `animation_state.py`) — masing-masing Single Responsibility: `BlinkAnimator`/`BreathingAnimator` = pure logic nilai (tidak tahu asyncio/scheduling), `IdleScheduler` = orkestrasi timing (tidak tahu logic animasi), `IdleCoordinator` = lifecycle start/stop (tidak tahu detail scheduling), `AnimationState` = snapshot read-only.
- **`layer_name` dan `logical_parameter` yang berbeda untuk tiap layer** (`"lipsync"`/`"MouthOpen"` vs `"blink"`/`"EyeOpen"` vs `"breathing"`/`"BreathParam"`) — inilah yang secara konkret mewujudkan Animation Independence Policy: `AvatarManager._parameter_layers` dict menampung semuanya tanpa saling timpa, karena key-nya memang didesain tidak pernah collide.
- **Idle Animation dijalankan sebagai task asyncio yang hidup selama `AvatarWorker` hidup** (lewat `_run_all()`), bukan dipicu on-demand seperti Lip Sync/Expression — karena sifatnya memang "selalu ada" (idle), bukan reaksi terhadap event tertentu.
- **`apply_mood()` disiapkan sebagai hook kosong sejak v0.6.1** (bukan ditambah nanti di v0.6.5) — supaya integrasi Behavior Engine nanti tinggal isi logic di titik yang sudah jelas, tanpa perlu redesign `IdleCoordinator`.
- **Breathing punya fallback graceful untuk model tanpa parameter napas** — kalau `"BreathParam"` tidak ada di `vtube_model_config.json` atau modelnya tidak punya parameter yang cocok, `ParameterMapper.get_parameter_id()` return `None`, dan `AvatarManager.update_parameter_layer()` (sejak v0.5.1) sudah otomatis skip dengan log info, bukan error.
- **Roadmap direstrukturisasi jadi 4 Phase** (Foundation, Behavior, Intelligence, Release) — rekomendasi GPT yang disetujui, supaya dokumentasi/changelog/roadmap lebih mudah dibaca sekilas berdasarkan tujuan besar tiap kelompok milestone, bukan cuma urutan angka linear.
- **Nomor versi Idle Animation digeser dari rencana awal "v0.5.2" (sisipan di Phase 1) ke "v0.6.1" (bagian resmi Phase 2 Behavior)** — konsekuensi dari restrukturisasi Phase; Emotion System yang sebelumnya akan jadi "v0.6.1" sekarang bergeser ke **v0.6.2**, dan rencana "Mood System" + "Energy & Curiosity" yang sempat dipisah 2 versi sekarang **digabung jadi v0.6.4 (Mood & Energy)**.

## 10. Instruksi Kalau Lanjut Chat Baru

1. **Jangan redesign arsitektur** yang sudah ada (bagian 4–6) tanpa alasan kuat (bug kritis).
2. **Jangan ubah** `ai/gemini.py`, `ai/personality.py`, `ai/prompt_builder.py`, `ai/conversation.py`, `speech/*` inti, `avatar/vtube.py`/`expression.py`/`lipsync.py`/`avatar_manager.py` (kecuali penambahan additive), atau `prompts/*.txt` kecuali diminta eksplisit.
3. **Jangan import PySide6/Qt di luar folder `ui/`** — termasuk `behavior/` dan seluruh `avatar/*` termasuk yang baru (`blink.py`, `breathing.py`, `idle.py`, `idle_scheduler.py`, `animation_state.py`).
4. **Jangan pernah mencampur Memory dan Conversation. Jangan perkenalkan vector DB/RAG.**
5. **Jangan biarkan layer animasi apa pun (Idle, Lip Sync, atau layer baru nanti) memanggil `VTubeStudioClient` langsung** — semua HARUS lewat `AvatarManager.update_parameter_layer()` atau `react_to_reply()`.
6. **Kalau menambah layer animasi baru** (mis. head movement/body sway yang disebut sebagai "Future" di spec v0.6.1), pakai `layer_name` dan `logical_parameter` BARU yang unik, jangan reuse `"blink"`/`"breathing"`/`"lipsync"` — dan tetap lewat `update_parameter_layer()` yang sudah generic, jangan bikin method baru per layer di `AvatarManager`.
7. **`BehaviorEngine` tidak boleh bicara langsung ke Gemini/AvatarManager/VoiceManager/GUI/Idle Animation** — integrasi nyata (termasuk `IdleCoordinator.apply_mood()`) ditunda sampai **v0.6.5 Behavior Integration**. Jangan buru-buru sambungkan di v0.6.2–v0.6.4 kecuali user eksplisit minta lompat urutan.
8. **`BehaviorState` harus tetap immutable (`frozen=True`)** di semua sub-versi berikutnya.
9. **SELALU CEK jumlah instansiasi objek berat** (`VoiceManager`, Whisper, `Companion`) di `ui/window.py` kalau menambah/memindah blok inisialisasi — pernah jadi bug nyata di v0.5.1.
10. **Perhatikan penamaan parameter constructor yang benar** — `VoiceManager(..., voice_name=..., on_audio_ready=...)`, `AvatarManager(vtube_client=..., halo_mapper=..., parameter_mapper=..., reconnect_interval=..., on_state_change=...)`, `BehaviorEngine(memory_manager=...)`, `IdleCoordinator(on_update, blink=..., breathing=...)`. Cek signature dulu kalau ragu.
11. **Gunakan penomoran versi Phase 2 yang SUDAH DIGESER**: v0.6.0 Behavior Engine skeleton, v0.6.1 Idle Animation (SELESAI), v0.6.2 Emotion System, v0.6.3 Relationship System, v0.6.4 Mood & Energy, v0.6.5 Behavior Integration. Jangan pakai nomor dari rencana lama (jangan sebut "v0.5.2 Idle Animation" atau "v0.6.1 Emotion System" — itu sudah digeser).

14. User berkomunikasi dalam Bahasa Indonesia; kode & komentar teknis boleh Inggris seperlunya, penjelasan ke user pakai Bahasa Indonesia.

## 11. Roadmap Selanjutnya (Detail Phase 2 & Seterusnya)

- **v0.6.2 — Emotion System:** isi logic penentuan `Emotion` dari `user_input`+`reply`. Masih terisolasi di `behavior/`, belum tersambung ke `Companion` maupun `IdleCoordinator.apply_mood()`.
- **v0.6.3 — Relationship System:** logic pertumbuhan `RelationshipState`, mulai membaca/menulis lewat `MemoryManager` (Dependency Injection yang sudah disiapkan di `BehaviorEngine.__init__`).

- **v0.6.5 — Behavior Integration:** `BehaviorEngine` disambungkan ke `Companion` secara ephemeral (pola sama Memory/waktu), DAN `IdleCoordinator.apply_mood()` mulai benar-benar dipanggil (mis. Mood Sleepy → blink lebih sering & lebih lama, Excited → napas lebih cepat, sesuai contoh di spec v0.6.1) — kemungkinan juga mulai memengaruhi gaya bicara Voice kalau API-nya sudah mendukung.
