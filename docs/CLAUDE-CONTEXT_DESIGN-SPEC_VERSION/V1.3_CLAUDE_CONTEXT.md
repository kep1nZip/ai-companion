# Temuan penting dari inspeksi (`avatar/avatar_manager.py`, `avatar/vtube.py`, dkk)

Ini bukan asumsi — dikonfirmasi baca source langsung sebelum implementasi.
**Temuan ini mengubah scope halaman secara signifikan dari mockup awal**
(bukan gagal memenuhi spec — mockup memang mengasumsikan API yang ternyata
tidak ada di backend real):

1. **`AvatarManager` TIDAK punya `connect()`/`disconnect()` manual.** Semua
   koneksi + auto-reconnect ada di dalam `run_forever()`: loop
   `CONNECTING → (connect+authenticate) → READY`, kalau gagal
   `→ DISCONNECTED → sleep(reconnect_interval) → ulang`. Loop ini **sudah
   berjalan otomatis sejak `MainWindow.__init__`** (`self._avatar_worker.start()`
   dipanggil di constructor `MainWindow`), jauh sebelum Avatar page pernah
   dibuka.
2. **`AvatarManager.stop()` BUKAN "Disconnect" yang aman untuk tombol GUI.**
   Method ini permanent shutdown yang dipakai `MainWindow.closeEvent()`.
   Kalau dipanggil dari tombol GUI: `run_forever()` return →
   `finally: await self._idle.stop()` di `AvatarWorker._run_all()` ikut
   jalan → **idle animation (blink/breathing) mati permanen**, dan
   `AvatarWorker` QThread selesai (`run()` habis) tanpa cara restart selain
   restart aplikasi. **Ini akan melanggar aturan "jangan merusak idle
   animation" secara langsung** — karena itu Avatar GUI **tidak punya
   tombol Disconnect sama sekali.**
3. **Tidak ada `trigger_expression()`/`trigger_hotkey()` publik yang aman
   dipanggil manual.** Satu-satunya jalur ke ekspresi adalah
   `react_to_reply(reply_text: str)` — method ini menerima TEKS BALASAN
   ASLI dari Companion, lalu meregex pola halo di dalamnya
   (`HaloMapper.map()`). Memanggilnya manual dari GUI berarti mensimulasikan
   balasan Companion palsu untuk memicu ekspresi tertentu — itu bukan
   kontrol GUI, itu mengarang alur AI. **Tidak diimplementasikan.**
4. **`AvatarManager` tidak menyimpan "expression/halo terakhir" atau "nama
   model VTS saat ini" sebagai state yang bisa dibaca.** `react_to_reply()`
   menghitung `expression` secara lokal lalu langsung dipakai untuk
   `trigger_hotkey()`, tidak disimpan sebagai instance attribute yang bisa
   dibaca ulang. Baris **"Emotion: Happy" / "Halo: Pink Heart Halo" /
   "Model: [nama]" di mockup awal TIDAK ditampilkan** — data itu tidak ada,
   menampilkannya berarti data palsu.
5. **`AvatarState` enum: `DISCONNECTED, CONNECTING, AUTHENTICATED, READY,
   BUSY`** — 5 nilai real. Catatan: `AUTHENTICATED` didefinisikan tapi
   **tidak pernah benar-benar di-set** di alur `run_forever()` saat ini
   (loop langsung CONNECTING → READY setelah connect+authenticate sukses,
   tidak pernah singgah di state AUTHENTICATED secara terpisah). Ini bukan
   bug yang saya perbaiki — di luar scope v1.3, cuma dicatat sebagai
   observasi.
6. **`AvatarManager.set_state_listener()` itu single-slot** (sama seperti
   `VoiceManager` di v1.2), dan slot itu **sudah dipakai `AvatarWorker`**
   sejak `AvatarWorker.__init__()`
   (`self._avatar_manager.set_state_listener(self._emit_state)`), untuk
   menyalakan status bar `MainWindow`. Kalau Avatar GUI mendaftar ulang
   listener langsung ke `AvatarManager`, itu akan **membajak registrasi
   milik `AvatarWorker` dan merusak status bar existing** — regresi nyata.
   Karena itu Avatar GUI **subscribe ke `AvatarWorker.state_changed` (Qt
   Signal, multi-subscriber-friendly)**, bukan ke `AvatarManager` langsung.
7. **Kegagalan koneksi VTube Studio sudah sepenuhnya ditangani backend** —
   `run_forever()` membungkus `connect()`/`authenticate()` dengan
   `try/except Exception`, log warning, set state `DISCONNECTED`, lalu retry
   otomatis. Tidak ada exception yang bocor ke GUI, tidak ada pesan error
   spesifik yang tersedia untuk ditampilkan (cuma perubahan state). Karena
   itu Avatar GUI tidak butuh error-handling khusus — cukup menampilkan
   state apa adanya + catatan bantuan statis saat `DISCONNECTED`.

# Yang sudah diimplementasikan

## 1. `ui/avatar.py` — BARU

`AvatarPage(QWidget)`:

- Judul "Avatar" + subjudul "Avatar System".
- `Status: {AvatarState.value}` — live-update lewat
  `avatar_worker.state_changed.connect(self._on_state_changed)`.
- Catatan bantuan (`avatarErrorLabel`, warna amber `#e0b054` — bukan merah
  seperti error di Voice, karena ini kondisi normal/expected, bukan error
  aplikasi): *"If Avatar shows Disconnected, please check whether VTube
  Studio is running."* — otomatis muncul/hilang mengikuti state
  `DISCONNECTED`.
- Kartu "Animation Layers" (`avatarStateCard`) — menampilkan
  `avatar_manager.animation_state.active_layers` (mis. "blink, breathing"
  atau "None"). Ini data teknis tapi real, sekaligus memberi sinyal halus
  bahwa idle animation memang jalan.
- Tombol "Refresh" — baca ulang `avatar_manager.state` +
  `animation_state.active_layers` secara **sinkron** (property read biasa,
  sama seperti `developer/avatar_debug.py` sudah lakukan sejak v1.0; tidak
  ada I/O blocking, tidak perlu worker).
- Catatan statis: *"No manual avatar controls are currently supported by
  the backend."* — transparansi eksplisit kenapa tidak ada tombol
  Connect/Disconnect/Trigger Expression, bukan halaman yang "belum selesai".
- `showEvent()` juga trigger `_refresh()` untuk sinkronisasi
  `animation_state` (satu-satunya bagian yang tidak di-push live), mirip
  pola `MemoryPage` v1.1.
- Constructor: `AvatarPage(avatar_manager, avatar_worker)` — **dua
  parameter**, deviasi dari contoh kontrak awal `AvatarPage(avatar_manager)`
  di design spec. Alasan: `avatar_worker` dibutuhkan untuk `state_changed`
  Qt Signal (lihat temuan §6 di atas). `avatar_manager` tetap dipakai untuk
  baca `.state`/`.animation_state` sinkron di `_refresh()`.

# Deviasi dari mockup (disengaja, didokumentasikan)

Semua deviasi di bawah ini adalah **konsekuensi langsung dari inspeksi
source**, bukan keputusan sepihak Claude:

1. **Tidak ada tombol Connect/Reconnect** — API-nya tidak ada (koneksi
   otomatis di `run_forever()`).
2. **Tidak ada tombol Disconnect** — `stop()` yang ada bersifat permanent
   shutdown, memakainya sebagai tombol GUI akan merusak idle animation
   secara permanen.
3. **Tidak ada tombol Trigger Expression** — tidak ada API untuk memicu
   ekspresi manual tanpa mensimulasikan balasan Companion palsu.
4. **Baris "Emotion"/"Halo"/"Model" dihapus dari status display** — data
   itu tidak pernah disimpan sebagai state yang bisa dibaca oleh siapa pun
   di luar `react_to_reply()` itu sendiri.
5. **Kontrak constructor `AvatarPage(avatar_manager, avatar_worker)`**,
   bukan `AvatarPage(avatar_manager)` saja — dibutuhkan untuk reuse
   `AvatarWorker.state_changed` Qt Signal alih-alih membajak listener slot
   `AvatarManager` yang sudah dipakai status bar.

# Known limitation (bukan bug, konsekuensi dari API asli)

- Halaman Avatar **hanya bisa menampilkan status**, tidak ada kontrol
  interaktif apa pun terhadap avatar. Ini bukan implementasi yang kurang —
  ini batas jujur dari API `AvatarManager` yang ada saat ini. Kalau user
  ingin fitur seperti Connect/Disconnect manual atau Trigger Expression
  manual di masa depan, itu **butuh penambahan API baru di `AvatarManager`
  itu sendiri** (backend change), bukan sekadar tombol GUI — treat sebagai
  keputusan arsitektur v1.4+ yang butuh diskusi eksplisit, bukan hal yang
  bisa diam-diam ditambahkan Claude di sesi berikutnya.
- `AvatarState.AUTHENTICATED` ada di enum tapi tidak pernah benar-benar
  tercapai di alur `run_forever()` saat ini — Avatar GUI tetap memetakan
  semua 5 nilai enum dengan benar (tidak fatal, cuma satu state yang secara
  praktik tidak pernah muncul).

# Instruksi untuk sesi Claude berikutnya

1. v1.3 Avatar GUI **selesai dan terverifikasi jalan**. Jangan
   re-implementasi dari nol — baca dulu isi `ui/avatar.py`, `ui/navigation.py`,
   `ui/window.py` versi yang sudah di-deploy user (minta upload ulang kalau
   user bilang sudah ada perubahan lanjutan, jangan asumsikan sama persis
   dengan dokumen ini).
2. **Kalau user minta tombol Connect/Disconnect/Trigger Expression manual**:
   ini BUKAN pekerjaan GUI kecil. `AvatarManager` perlu API baru
   (misalnya `manual_reconnect()` yang tidak mematikan idle animation, atau
   `trigger_expression(Expression)` publik yang tidak melalui
   `react_to_reply`). Itu perubahan ke subsystem Avatar yang dibekukan —
   **wajib didiskusikan eksplisit dengan user sebelum eksekusi**, bukan
   diasumsikan sebagai kelanjutan alami dari v1.3.
3. **JANGAN PERNAH** memanggil `avatar_manager.stop()` dari kode GUI mana
   pun kecuali `MainWindow.closeEvent()` (satu-satunya tempat yang sudah
   benar sejak v1.0/v1.1). Ini akan mematikan idle animation permanen.
4. **JANGAN PERNAH** membuat instance `AvatarManager`/`VTubeStudioClient`
   baru di `ui/`. Semua halaman yang butuh avatar HARUS reuse
   `self._avatar_manager` + `self._avatar_worker` yang sama dari
   `MainWindow`.
5. Kalau menambah halaman GUI baru yang butuh live state update dari
   subsystem manapun: **cek dulu apakah slot listener subsystem itu sudah
   dipakai worker lain** (pola yang sama berlaku untuk `VoiceManager` di
   v1.2). Kalau sudah, subscribe ke Qt Signal milik worker tersebut, jangan
   mendaftar ulang listener mentah — itu akan membajak registrasi yang ada.
6. Arsitektur v1.0 (Architecture Freeze Policy) **masih berlaku** untuk
   semua subsystem di luar GUI baru yang ditambahkan tiap versi. `Companion`
   tetap satu-satunya orchestrator.
7. Pola yang established sejauh ini (v1.1 → v1.3): boundary tipis non-Qt
   kalau memang perlu (`MemoryService`), reuse manager/worker instance yang
   sama lewat constructor injection, `QStackedWidget` untuk page switching,
   append-only ke `theme.py`, dan **selalu tampilkan hanya data yang benar-
   benar ada di backend** — kalau mockup minta data yang tidak ada, itu
   sinyal untuk stop & inspect lebih dalam, bukan mengarang.
8. User komunikasi Bahasa Indonesia, kode/komentar teknis boleh Inggris.
