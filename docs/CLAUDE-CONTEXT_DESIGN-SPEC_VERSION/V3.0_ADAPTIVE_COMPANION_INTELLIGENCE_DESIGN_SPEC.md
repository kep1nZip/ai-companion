# 2. Core Principle

```text
Personalization
+
State coherence
+
Existing intelligence
        ↓
More natural companion
```

Bukan:

```text
More automation
+
More agents
+
More databases
=
Better companion
```

Prinsip utama:

```text
Existing state > duplicate state
Persistent facts > invented preferences
Gradual adaptation > sudden personality changes
Context relevance > personalization everywhere
Coherence > complexity
Teacher experience > feature count
```

# 3. Primary Goal

Setelah v3.0, Arona seharusnya bisa:

```text
1. Mengenali preferensi Teacher yang memang sudah memiliki evidence.
2. Menyesuaikan gaya respons berdasarkan context dan preference.
3. Membiarkan Relationship memengaruhi interaction tone secara natural.
4. Menjaga Emotion + Energy + Relationship tetap koheren.
5. Memakai state yang sudah ada untuk memilih perilaku yang lebih sesuai.
6. Membuat autonomous interaction lebih personal ketika memang relevan.
7. Menjelaskan alasan adaptasi melalui observability developer.
```

Contoh behavioral target:

```text
Teacher sering meminta jawaban singkat
→ Arona cenderung lebih ringkas.

Teacher sedang debugging serius
→ Arona lebih fokus daripada bercanda.

Teacher sedang santai
→ Arona lebih bebas menggunakan playful tone.

Relationship meningkat
→ interaksi terasa sedikit lebih akrab,
  tanpa mengubah identity/personality secara ekstrem.

Energy rendah
→ respons tidak terlalu hiper.

Teacher pernah menyukai suatu topik
→ autonomous interaction dapat memanfaatkannya
  ketika context memang relevan.
```

# 7. Phase 1 — Preference Evidence

Tujuan:

```text
Arona dapat membedakan:
fact
vs
preference
vs
temporary statement
vs
uncertain statement
```

Gunakan memory yang sudah ada.

Contoh:

```text
"aku suka game X"
→ evidence preference

"lagi pengen belajar Rust"
→ temporary/current intent
```

Jangan otomatis menyimpan semua sebagai preference.

Memory extraction rules v2.2+ dan supersession v2.5 tetap menjadi source behavior.

---

# 8. Phase 2 — Preference Relevance

Preference tidak boleh memengaruhi semua respons.

Contoh:

```text
Preference:
Teacher suka game X
```

Tidak berarti:

```text
Setiap respons harus membahas game X.
```

Gunakan:

```text
Preference
+
Current conversation relevance
+
Current context
        ↓
Possible personalization
```

Prioritas:

```text
Current user intent
>
Current conversation
>
Relevant preference
>
Older preference
```

---

# 9. Phase 3 — Interaction Style Adaptation

Target:

```text
Current context
+
Teacher preference
+
Relationship
+
Emotion / energy
        ↓
Response style guidance
```

Contoh:

```text
Teacher:
"jelasin singkat aja"

→ response lebih concise
```

Kemudian:

```text
Teacher:
"jelasin detail dong, aku pengen ngerti"
```

→ response lebih detail.

Adaptation harus bersifat **soft guidance**, bukan hard-coded output templates.

Jangan membuat rule seperti:

```text
if teacher_prefers_short:
    max_tokens = 100
```

kecuali audit/measurement membuktikan ada alasan kuat.

Lebih baik:

```text
response_style = concise
```

sebagai context signal yang diberikan ke LLM.

---

# 10. Phase 4 — Relationship-Aware Interaction

Relationship system sudah memiliki state.

v3.0 harus mengevaluasi:

```text
Apakah current relationship state
sebenarnya terasa di interaction?
```

Target bukan:

```text
Relationship = 80
→ selalu bicara romantis / intens
```

Tetapi:

```text
higher familiarity
→ sedikit lebih natural

higher trust
→ sedikit lebih supportive

lower familiarity
→ lebih reserved
```

Gunakan relationship sebagai **context signal**, bukan personality replacement.

# 11. Phase 5 — State-Coherent Response

Integrasikan:

```text
Emotion
Energy
Relationship
Behavior
Conversation
```

untuk menghindari contradiction.

Contoh:

```text
Energy = very low
Emotion = calm
Relationship = high
Teacher = joking
```

Expected:

```text
Arona tetap bisa bercanda,
tetapi tidak tiba-tiba menjadi hiperaktif.
```

Contoh lain:

```text
Emotion = sad
Teacher = serious technical debugging
```

Expected:

```text
Technical help tetap kompeten,
emotion hanya memengaruhi tone secukupnya.
```

Priority:

```text
User intent / task
>
Conversation context
>
State tone
>
Optional personalization
```

# 13. Phase 7 — Personalization in Autonomous Conversation

Autonomous interaction harus terasa:

```text
context-aware
```

bukan:

```text
randomly personalized
```

Contoh buruk:

> "Teacher masih suka game X kan?"

padahal tidak ada context bahwa topik itu relevan.

Contoh lebih baik:

```text
Teacher idle
+
Vision menunjukkan game X
+
Memory punya preference game X
```

→ personalization menjadi relevan.

Autonomous tetap menggunakan:

```text
same Conversation
same Companion
same Initiative
```

Tidak membuat autonomous subsystem baru.

# 21. Stop Conditions

Claude **MUST stop and report** instead of improvising if:

1. A new database is needed for personalization.
2. A second LLM classifier is proposed.
3. A new autonomous orchestrator is proposed.
4. Memory schema must change.
5. Relationship ownership must move.
6. Emotion ownership must move.
7. ContextBuilder must become an orchestrator.
8. Provider-specific personalization logic becomes necessary.
9. Preference inference becomes too ambiguous to perform safely.
10. Existing memory semantics cannot distinguish persistent fact from temporary intent.
11. Personalization starts overriding current user intent.
12. A large personality prompt rewrite becomes necessary.
13. GUI architecture must be redesigned.
14. Feature quality cannot be validated through observable behavior.
15. A proposed change turns Arona into a general autonomous agent rather than a companion.

# 22. Decision Gate

## PASS

v3.0 PASS apabila:

- existing intelligence signals are successfully reused;
- personalization is evidence-based;
- irrelevant memories do not dominate;
- current user intent remains highest priority;
- relationship influence feels natural;
- emotion/energy/relationship remain coherent;
- autonomous interaction can personalize when relevant;
- no duplicate state is introduced;
- Local works;
- Gemini works;
- Voice/Text continuity remains intact;
- Vision/Memories remain correct;
- v2.5–v2.9 behavior remains intact;
- Developer observability is truthful;
- GUI remains responsive;
- no critical regression exists.

## CONDITIONAL PASS

Allowed when:

- some personalization cases still need tuning;
- some preference categories are deferred;
- adaptation remains conservative because evidence is insufficient;
- autonomous personalization remains limited.

Document limitations.

## FAIL

FAIL apabila:

- Arona frequently forces irrelevant personalization;
- current user intent is overridden by old preferences;
- relationship/emotion causes incoherent behavior;
- superseded memories influence current behavior;
- a new persistence layer is introduced without explicit design;
- second-agent / second-LLM architecture appears;
- major v2.x regression occurs.
