# V3.1 — Adaptive Presence & Natural Conversation

## Status

**Planned**

V3.1 melanjutkan fondasi v3.0 dengan fokus pada kehadiran yang lebih natural, kontinuitas percakapan, kualitas keputusan Initiative, perilaku yang sedikit lebih adaptif terhadap hubungan dengan Teacher, serta penerapan model bahasa baru melalui restart otomatis.

> Reuse existing systems > create new systems.

---

# 1. Tujuan Utama

Setelah v3.0, Arona sudah memiliki memory relevance, preference awareness, relationship state, emotion/energy state, conversation closure, initiative scoring, vision relevance, autonomous response, provider selection, dan personalization observability.

Target v3.1:

> Membuat Arona terasa lebih natural ketika memulai, melanjutkan, dan kembali ke percakapan tanpa menjadi terlalu cerewet atau terlalu scripted.

Evolusi:

```text
v2.9 → Arona memahami konteks.
v3.0 → Arona memahami Teacher.
v3.1 → Arona memahami bagaimana hadir dan berinteraksi dengan Teacher.
```

---

# 2. Scope V3.1

## Phase 0 — Architecture Audit

Wajib dilakukan terlebih dahulu.

Claude harus:

1. Inspect repository aktual.
2. Inspect Conversation, Initiative, ContextBuilder, Companion, Relationship, Memory, Settings, dan Developer Dashboard.
3. Cari mekanisme idle/timestamp yang sudah ada.
4. Cari session/startup lifecycle.
5. Cari bagaimana Settings menyimpan dan menerapkan perubahan provider/model.
6. Cari mekanisme restart/relaunch yang aman bila sudah ada.
7. Tentukan lokasi perubahan paling kecil.
8. Jangan mengubah kode sebelum audit selesai.

Audit wajib menyebut file relevan, method/class yang dipakai ulang, dependency flow, risiko regresi, dan perubahan minimum.

## Phase 1 — Conversation Continuity

### Tujuan

Membuat Arona dapat mempertahankan konteks percakapan yang masih relevan setelah jeda tanpa membuat sistem conversation kedua.

Contoh:

```text
Teacher:
"Besok aku mau lanjut bikin backend."

Arona:
"Semangat, Teacher. Besok lanjut backend-nya ya."

--- beberapa waktu kemudian ---

Teacher:
"aku balik"

Arona dapat memahami bahwa ada thread percakapan
yang baru saja ditinggalkan dan merespons secara natural.
```

### Constraint

Gunakan existing:

- Conversation history
- ContextBuilder
- Companion orchestration
- timestamp/state bila tersedia

Jangan membuat:

- ConversationManager2
- database conversation baru
- vector DB
- RAG
- topic database baru
- second LLM
- agent planner

Continuity adalah context signal, bukan autonomous planner.

---

## Phase 2 — Return-from-Idle Awareness

### Tujuan

Membedakan kondisi:

```text
ACTIVE
RETURNING_AFTER_SHORT_GAP
RETURNING_AFTER_LONG_GAP
```

Gunakan mekanisme idle/timestamp yang sudah tersedia bila memungkinkan.

**Jangan membuat timer kedua atau cooldown system baru.**

Arona tidak otomatis berbicara hanya karena Teacher lama idle. Idle awareness terutama digunakan ketika Teacher kembali berinteraksi.

Jeda harus terasa natural, bukan telemetry dump.

---

## Phase 3 — Adaptive Initiative Quality

### Tujuan

Meningkatkan kualitas keputusan Initiative tanpa mengubah Initiative menjadi LLM planner.

```text
Candidate signal
    ↓
Priority
    ↓
Context relevance
    ↓
Conversation continuity
    ↓
Personalization
    ↓
Existing suppression rules
    ↓
Decision
```

Target:

> Bukan hanya "ada sesuatu yang bisa dibicarakan", tetapi "ada sesuatu yang masuk akal untuk dibicarakan sekarang".

Pertahankan:

- existing DecisionRule architecture
- EventPriority
- RecentInteractionPenaltyRule
- existing suppression rules
- existing routine/vision signals

Jangan membuat scoring formula besar tanpa evidence, LLM call tambahan untuk initiative, second timer, atau menghapus rule lama yang masih valid.

Measure before optimize.

---

## Phase 4 — Relationship-aware Interaction

Gunakan relationship state yang sudah ada:

```text
Trust
Comfort
Affection
Respect
Familiarity
```

Guidance:

```text
Relationship rendah
→ reserved / sedikit formal

Relationship menengah
→ lebih familiar

Relationship tinggi
→ lebih comfortable dan playful secara natural
```

Relationship hanya memengaruhi **cara berinteraksi**, bukan menggantikan personality.

### Batas keras

Jangan membuat:

- romance engine
- dating mechanic
- affection point gameplay
- scripted girlfriend behavior
- sudden romantic behavior
- relationship reward loop

Kenaikan angka kecil tidak boleh menghasilkan perubahan kepribadian ekstrem.

---

## Phase 5 — Context / Prompt Integration

Gunakan prompt dan signal yang sudah ada.

Prioritas:

```text
task correctness / user intent
        >
emotion / energy tone
        >
relationship nuance
        >
default speaking style
```

Pastikan:

- permintaan teknis tetap dijawab benar;
- emotion/energy hanya memengaruhi tone;
- relationship memengaruhi familiarity secara ringan;
- explicit user request tetap menjadi prioritas;
- response style tetap conditional seperti v3.0.

Tidak boleh ada prompt overhaul besar.

# 3. Phase 6 — Language Model Change Auto-Restart

## Tujuan

Ketika Teacher mengubah **language model/provider model** di Settings lalu menekan **Apply**, Arona harus otomatis melakukan restart/relaunch sehingga konfigurasi baru langsung aktif.

Target:

```text
Settings
   ↓
ubah Language Model
   ↓
Apply
   ↓
persist configuration
   ↓
inform Teacher
   ↓
graceful shutdown
   ↓
automatic relaunch
   ↓
Arona hidup kembali dengan model baru
```

Teacher **tidak perlu Exit manual dan menjalankan `main_gui.py` lagi**.

## Scope

Fokus pada perubahan model bahasa/provider yang memang memerlukan startup configuration baru.

Jangan otomatis restart untuk setiap setting bila setting tersebut tidak membutuhkan restart.

## Wajib diaudit sebelum implementasi

Claude harus mencari:

- entry point aplikasi
- `main_gui.py`
- Settings persistence
- provider/model loading lifecycle
- startup initialization
- QApplication lifecycle
- shutdown/cleanup
- VoiceManager ownership
- AvatarManager ownership
- worker/thread lifecycle

## Requirement

Restart harus:

1. menyimpan konfigurasi baru terlebih dahulu;
2. memberi kesempatan worker/thread relevan melakukan cleanup;
3. menutup aplikasi dengan aman;
4. menjalankan kembali entry point aplikasi secara fresh;
5. memakai konfigurasi/model terbaru;
6. tidak membuat duplicate manager/provider instance;
7. tidak merusak VoiceManager atau AvatarManager shutdown behavior;
8. tidak meninggalkan child process/thread yang menggantung;
9. tidak membutuhkan user menjalankan ulang manual.

UX tidak boleh terasa seperti crash.

Contoh:

```text
Language model updated.
Arona will restart to apply the new model.
```

Bila restart gagal, harus ada UX yang jelas dan tidak silent.

### Constraint keras

Jangan:

- membuat provider khusus restart;
- mengubah provider abstraction secara besar;
- mengubah model loading architecture tanpa kebutuhan;
- memaksa restart untuk setting yang tidak perlu;
- membuat AvatarManager baru hanya untuk restart;
- membuat duplicate VoiceManager;
- memakai hardcoded path yang hanya bekerja pada satu mesin;
- memakai `os.system("start ...")` tanpa audit lifecycle;
- membuat infinite restart loop.

Prefer restart melalui entry point existing, menggunakan executable/interpreter yang sedang menjalankan aplikasi, mempertahankan environment/working directory, dan pass-through arguments bila diperlukan.

# 4. Phase 7 — Developer Observability

Tambahkan observability hanya untuk state yang benar-benar tersedia.

Signal yang dapat dipertimbangkan:

```text
Conversation Continuity Signal
Return-from-Idle State
Initiative Context Signal
Relationship Influence Signal
```

Gunakan istilah jujur, misalnya:

```text
Continuity Signal: available
Return State: returning_after_short_gap
Relationship Influence: warm
```

Jangan mengklaim bahwa LLM pasti menggunakan signal bila yang tersedia hanya input/signal ke model.

Pertahankan prinsip v3.0:

> Bedakan "signal tersedia" dari "LLM benar-benar menggunakan signal".

# 6. Definition of Done

V3.1 hanya boleh dinyatakan **PASS** apabila:

1. Phase 0 audit selesai.
2. Conversation continuity bekerja tanpa conversation architecture baru.
3. Return-from-idle awareness bekerja tanpa second timer.
4. Initiative menjadi lebih context-aware tanpa LLM planner.
5. Relationship memengaruhi interaction tone secara ringan dan natural.
6. Prompt integration tidak menurunkan technical correctness.
7. Pengubahan language model melalui Settings + Apply melakukan restart otomatis.
8. Restart menggunakan konfigurasi baru.
9. Tidak ada duplicate manager/provider instance.
10. Existing v1.0-v3.0 behavior tetap aman.
11. Teacher menjalankan `main_gui.py` secara nyata.
12. Teacher memvalidasi bahwa aplikasi restart otomatis setelah perubahan model.
13. Tidak ada klaim PASS yang hanya berasal dari simulasi atau static inspection.

# 8. Architecture Boundaries

Pertahankan ownership:

```text
Companion
→ single orchestrator

ContextBuilder
→ context assembly only
→ not orchestrator
→ not LLM caller

Memory
→ persistent facts

Conversation
→ immediate conversation history / continuity signals

Emotion
→ emotion state

Relationship
→ relationship state

Initiative
→ speak / don't speak decision

Routine
→ reactive opportunity detection

Voice / Avatar
→ presentation / delivery

Settings
→ configuration persistence and provider/model selection

Developer Dashboard
→ read-only observability
```

Do not move ownership between these systems.

# 9. Implementation Rules for Claude

Sebelum setiap perubahan:

```text
INSPECT
→ IDENTIFY EXISTING PATH
→ MAKE SMALLEST SAFE CHANGE
→ TEST
→ REPORT
```

- tidak membuat destructive migration;

Untuk auto-restart, audit lifecycle terlebih dahulu karena perubahan menyentuh process lifecycle.
