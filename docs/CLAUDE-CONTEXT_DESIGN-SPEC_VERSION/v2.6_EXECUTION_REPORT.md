# v2.6 — Context Intelligence & Context Hygiene — Laporan Eksekusi

**Scope dieksekusi (sesuai instruksi eksplisit):** Phase 1 (Context Hygiene) + fix regresi Memory GUI + Phase 6 (Context Budget, baseline-first) + Phase 10 (Observability).
**Sengaja TIDAK dikerjakan:** Phase 3, 4, 7, 8 (sesuai instruksi eksplisit — audit Phase 0 juga tidak menemukan bukti nyata bahwa ini dibutuhkan).
**Tidak ada perubahan arsitektur ContextBuilder** — `ai/context_builder.py` **tidak disentuh sama sekali** di seluruh eksekusi ini.

---

## 1. Phase 1 — Context Hygiene ✅

**Masalah:** `Companion._select_relevant_memories()` (dipakai untuk chat context) tidak memfilter marker internal (`__ARONA_INTERNAL_STATE__`, dst) — beda dengan versi ekstraksi v2.5 yang sudah difilter.

**Fix diterapkan di 2 titik** (`ai/companion.py`):
1. Jalur keyword search — tambah `not m.content.startswith("__ARONA_")`.
2. Jalur fallback recency — **ditemukan lebih rawan dari yang saya duga sebelumnya**: marker internal di-refresh `updated_at`-nya sangat sering (tiap kali Routine/Initiative/InternalState/Relationship update), jadi berpotensi mendominasi "N-terbaru" kalau tidak difilter. Ditambah buffer (`limit * 2`) sebelum filter supaya tetap dapat cukup hasil legit.

**Terverifikasi nyata:** marker tidak lolos di kedua jalur, memory sah yang kebetulan mengandung kata sama ("Arona") tetap lolos — filter presisi.

---

## 2. Fix Regresi Memory GUI ✅

**Masalah (ditemukan baru lewat audit v2.6, bukan dilaporkan sebelumnya):** perubahan default v2.5 (`active-only`) tanpa sengaja ikut membuat `Companion.list_memories()`/`search_memories()` — dipakai Memory GUI Teacher-facing — menyembunyikan semua memory yang sudah di-supersede. Teacher jadi tidak bisa lihat riwayatnya sendiri.

**Fix:** kedua method sekarang eksplisit `include_superseded=True`. Chat context (`_select_relevant_memories`) **tetap active-only, tidak diubah** — cuma jalur GUI yang diperbaiki.

**Tambahan kecil (bukan redesign GUI):** `ui/memory.py` — label "· Superseded" ditambahkan di card list dan detail view, supaya Teacher tidak bingung melihat 2 entri amerciano tanpa tahu mana yang masih berlaku.

**Terverifikasi nyata:** setelah `supersede_memory()`, `list_memories()` tetap menampilkan KEDUANYA (status `active` dan `superseded`) — regresi teratasi. Chat context tetap hanya menampilkan yang `active` — semantics v2.5 utuh, tidak rusak.

## 3. Phase 6 — Context Budget (Baseline-First, TANPA Angka Arbitrer) ✅

**Temuan:** `Conversation.get_history()` sebelumnya tidak dibatasi sama sekali.

**Yang saya BUKAN lakukan (sesuai instruksi):** saya **tidak menebak angka cap**. Tidak ada "50 turn" atau "20 pesan" yang saya putuskan sendiri.

**Yang saya lakukan:**
1. `Conversation.get_history(max_messages=None)` — parameter baru, **default `None` = unbounded, perilaku identik 100% dengan sebelum v2.6** kalau tidak diaktifkan.
2. `config/settings.py::CONVERSATION_HISTORY_MAX_MESSAGES` — env var baru, **default kosong = tidak aktif**. Teacher yang menentukan angkanya sendiri, kapan pun siap, berdasarkan data nyata (lihat Phase 10 di bawah).
3. `Conversation.message_count()` — untuk observability, supaya Teacher bisa LIHAT angka aktualnya dulu sebelum memutuskan.

**Terverifikasi nyata:** default tetap unbounded (40 pesan tetap 40 pesan, tidak terpotong). Saat `max_messages` diisi eksplisit, pemotongan mengambil N pesan **paling baru** (paling relevan), bukan yang lama — dites dengan assertion isi pesan persis.

**Cara Teacher mengaktifkan nanti:** tambahkan `CONVERSATION_HISTORY_MAX_MESSAGES=<angka>` ke `.env` setelah melihat baseline nyata di Developer Dashboard selama beberapa sesi pemakaian normal.

## 4. Phase 10 — Observability ✅

**Ditambahkan** (read-only, tidak memicu apa pun): `Companion.get_context_debug_snapshot()` →
```python
{
    "history_message_count": ...,   # angka aktual saat ini, dari Conversation.message_count()
    "history_cap": ...,              # None (unbounded) atau angka kalau Teacher sudah set
    "vision_fresh": True/False,      # reuse Vision.get_context() yang SUDAH freshness-gated sejak v1.5.2
    "active_memory_count": ...,      # total memory aktif di DB
}
```

Diwire ke `DeveloperSnapshot` (field baru `context_debug`), ditampilkan di:
- **Developer Dashboard GUI** — card baru "Context", ditaruh tepat setelah card "Providers".
- **Markdown export** (`export_markdown()`) — section baru "## Context".

**Keputusan scope yang sengaja saya batasi** (sesuai instruksi "jangan ubah arsitektur ContextBuilder secara besar" dan guardrail "no unrelated refactor"): saya **tidak** membangun state-tracking baru untuk "berapa memory persis dipakai di pesan terakhir" atau "berapa item ter-filter di pesan terakhir" — itu butuh alur data baru yang mengalir dari `_build_contents()` ke Dashboard, sebuah perubahan arsitektur yang lebih besar dari yang diminta. Yang saya tampilkan adalah **angka yang sudah tersedia murah** (total pesan history saat ini, total memory aktif di DB, status freshness vision saat ini) — cukup untuk Teacher mulai mengumpulkan baseline Phase 6, tanpa membangun pipa observability baru yang rumit.

## 5. Verifikasi yang Dilakukan (Real, Bukan Simulasi Cerita)

Semua dijalankan nyata di sandbox dengan temporary DB:

1. **Phase 1**: marker tidak bocor di jalur keyword search maupun fallback recency; memory sah tetap lolos.
2. **Fix GUI**: `list_memories()` menampilkan active + superseded setelah `supersede_memory()`; chat context tetap hanya active.
3. **Phase 6**: default `get_history()` unbounded (40/40 pesan, tidak berubah); `max_messages=6` mengambil 6 pesan **paling baru** dengan tepat (diverifikasi isi pesannya, bukan cuma jumlahnya).
4. **Phase 10**: `DeveloperService.get_snapshot().context_debug` terisi benar; markdown export menampilkan section "Context" dengan format yang benar.
5. **Backward-compat**: `Companion()` konstruktor lama (tanpa parameter apa pun, persis `test_developer_snapshot.py`) tetap jalan normal — `get_context_debug_snapshot()` juga langsung berfungsi di atasnya tanpa perlu perubahan lain.
6. Semua file (`ai/companion.py`, `ai/conversation.py`, `config/settings.py`, `developer/developer.py`, `ui/developer.py`, `ui/memory.py`) lolos `py_compile`, termasuk file test lama (`test_memory_quality_validation.py`, `test_developer_snapshot.py`) — tidak ada yang patah oleh perubahan ini.
