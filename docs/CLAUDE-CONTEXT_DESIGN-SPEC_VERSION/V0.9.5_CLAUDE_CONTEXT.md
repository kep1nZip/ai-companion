## 1. Apa Project Ini

AI Waifu Companion desktop app, terinspirasi Arona (Blue Archive). Bukan sekadar chatbot — dirancang modular supaya bisa berkembang jadi companion dengan voice, avatar Live2D, memory, emosi, vision, routine, initiative, developer tools, dll.

**Prinsip pengembangan:** incremental, per-milestone, jangan lompat fitur, jangan overengineering, jangan redesign arsitektur tanpa alasan kuat.

**Filosofi inti:** Desktop GUI **bukan** aplikasinya. Aplikasi sesungguhnya adalah `Companion`. Sejak v0.9.5, ada **layer observasi terpisah** yang cuma membaca, tidak pernah mengontrol:

```
Teacher
  ↓
Companion.chat(user_input)
  ↓ (menulis, via PerformanceTracker.timer())
BehaviorEngine + Vision + Routine + Initiative + Gemini + Memory  → PerformanceTracker mencatat durasi tiap tahap
  ↓
ContextBuilder.build(...) → Ephemeral Context
  ↓
GeminiClient.send(...) → reply
  ↓
GUI chat bubble │ TTS+LipSync │ HaloMapper │ IdleCoordinator

                              ═══════════════════════════════
                              DeveloperService (READ-ONLY, terpisah)
                              ═══════════════════════════════
                              → get_behavior()/get_vision()/get_routine()/
                                get_initiative()/get_memory()/get_avatar()/
                                get_performance()/get_logs()
                              → get_snapshot() (facade, 1 object gabungan)
                              → get_health() (System Health)
                              → export_json()/export_markdown()
```

**Human-in-the-Loop Memory Policy (v0.3).** **Avatar Independence Policy (v0.5).** **Animation Independence Policy (v0.5.1/v0.6.1).** **Behavior Engine Policy (v0.6.0).** **Emotion Transition Policy (v0.6.2).** **Relationship Base/Current Policy (v0.6.3).** **BehaviorState Single Source of Truth Policy (v0.6.4).** **Ephemeral Context Injection Policy & Context Builder Separation Policy (v0.6.5).** **Vision Independence/Injection/Freshness Policy (v0.7).** **Routine Independence/Decision/Cooldown/Suppression Policy (v0.8).** **Autonomous Independence/Permission Policy (v0.9).** **Read Only Policy & Developer Tools Independence Policy (v0.9.5, BARU, PALING PENTING):** `developer/*` **TIDAK PERNAH mengubah state apa pun** — tidak menulis Memory, tidak mengubah Behavior, tidak kirim request Gemini, tidak memanipulasi Avatar/Voice. Developer Tools adalah **Observability Layer** murni (istilah dari GPT) — dia cuma "mata", tidak pernah "tangan". Semua data diambil lewat **public API yang sudah ada**, tidak pernah manipulasi attribute internal.

## 4. Arsitektur (WAJIB Dipertahankan)

```
Terminal (main.py)     Desktop GUI (main_gui.py + ui/window.py)
        │                              │
        └──────────────┬───────────────┘
                        ↓
                   Companion (ai/companion.py)   ← performance_tracker: Optional[PerformanceTracker]=None
                        ↓
     ┌─────────┬─────────┬─────────┬─────────┬─────────┬─────────┐
     ↓         ↓         ↓         ↓         ↓         ↓         ↓
Conversation Memory   Gemini   Behavior   Vision   Routine   Initiative
                                                                     ↑
                                            (semua di atas: Companion._timed()
                                             mencatat durasi via PerformanceTracker,
                                             kalau performance_tracker != None)

DeveloperService (ui/window.py, TERPISAH dari Companion, dependency externally-injected):
    __init__(companion, avatar_manager=None, voice_manager=None, performance_tracker=None)
        ↓
    get_behavior()      -> companion.current_behavior_state()          -> BehaviorSnapshot
    get_vision()         -> companion.current_vision_context()          -> VisionSnapshot
    get_routine()         -> companion.get_pending_routine_events()/     -> RoutineSnapshot
                              get_last_routine_event()/get_next_routine_schedule()
    get_initiative()       -> companion.get_last_initiative_result()/     -> InitiativeSnapshot
                                get_initiative_budget()/get_initiative_cooldowns()
    get_memory()             -> companion.list_memories()                  -> MemorySnapshot (filter __ARONA_* internal marker)
    get_avatar()               -> avatar_manager.state/.animation_state +   -> AvatarSnapshot
                                    voice_manager.state
    get_performance()            -> performance_tracker.snapshot()           -> dict[str, MetricSnapshot]
    get_logs()                     -> baca logs/app.log langsung               -> list[LogEntry]
    get_health()                     -> agregasi semua di atas                   -> HealthStatus
    get_snapshot()                     -> panggil SEMUA get_xxx() sekali             -> DeveloperSnapshot (facade)
    export_json()/export_markdown()      -> serialize get_snapshot()
```

**Aturan besi (v0.1–v0.9, tetap berlaku penuh):** `Companion` satu-satunya koordinator semua subsystem. UI Independence. `BehaviorState` cuma 3 field. `Companion` tidak boleh merangkai string context sendiri. Semua Independence Policy (Vision/Routine/Autonomous) tetap berlaku — Developer Tools **tidak mengubah satu pun** dari aturan ini.

**Aturan besi BARU v0.9.5 — Developer Tools:**
- **`developer/*` TIDAK PERNAH memanggil method yang memodifikasi state** — dilarang keras memanggil `manual_override()`, `clear_routine_queue()`, `trigger_hotkey()`, `start_recording()`, `save_memory()`/`delete_memory()`, atau method mutating apa pun dari subsystem manapun. Cuma getter/property.
- **Snapshot Model wajib immutable (`frozen=True`)** untuk semua `*Snapshot` dataclass — rekomendasi GPT #1, GUI (nanti) baca snapshot ini, **tidak pernah** baca objek runtime (`BehaviorState`, `AvatarManager`, dst) langsung, menghindari race condition antara thread GUI dan thread background.
- **`AvatarManager`/`VoiceManager` di-inject terpisah ke `DeveloperService`, BUKAN lewat `Companion`** — karena secara arsitektur sejak v0.5, keduanya memang bukan milik `Companion` (Avatar Independence Policy). Memaksakan mereka lewat `Companion` akan jadi redesign yang dilarang.
- **`PerformanceTracker` ditulis oleh `Companion` (subject yang diukur), dibaca oleh `DeveloperService`** — ini BUKAN pelanggaran Read Only Policy, karena yang "menulis" state performa adalah kode yang sedang diukur itu sendiri (analog Task Manager: dia nggak menulis CPU usage, CPU usage yang menulis sendiri).
- **`DeveloperService.get_snapshot()` adalah facade tunggal** (rekomendasi GPT #3) — GUI (nanti, v1.0 atau setelahnya) cukup panggil 1 method, bukan 8 method terpisah; semua logic agregasi ada di `developer.py`, bukan di GUI.
- **`export_json()`/`export_markdown()` sudah siap sejak v0.9.5** (rekomendasi GPT #4) walau belum ada tombol GUI — berguna untuk bug report / perbandingan versi kapan pun dibutuhkan.
- **Belum ada GUI/tombol/panel Developer Tools apa pun** — sesuai spec eksplisit "Current milestone implements backend support only. No redesign of Main Window." `ui/window.py` cuma menyimpan instance `DeveloperService`, tidak ada elemen visual baru.

## 7. Bug yang Sudah Diperbaiki (Kumulatif, Jangan Diulang)

1. **Duplikasi instansiasi `VoiceManager`** (v0.5.1) — Fix: pastikan cuma 1 blok `VoiceManager(...)`.
2. **`httpx.ReadError`/`WinError 10054`** saat TTS (v0.5.1) — Fix: retry otomatis.
3. **Nama model TTS salah** (v0.4) — harus `gemini-2.5-flash-preview-tts`.
4. **Stage direction `(...)` ikut terbaca TTS** (v0.4) — di-strip sebelum sintesis.
5. **Arona salah tanggal/jam** (v0.4) — konteks waktu ephemeral.
6. **`TypeError: unexpected keyword argument 'tts_voice_name'`** (v0.4) — parameter benar `voice_name`.
7. **`400 INVALID_ARGUMENT: required oneof field 'data'`** (v0.6.5) — balasan Gemini kosong. Fix: `GeminiResponseError` + validasi.
8. **`400 INVALID_ARGUMENT: "Model tried to generate text, but it should only be used for TTS"`** (v0.7-v0.8) — **DIPERBAIKI FINAL di v0.8** dengan `_SPEECH_INSTRUCTION` eksplisit.
9. **Duplikasi definisi method `_build_contents()` di `ai/companion.py`** (v0.9.5, BARU) — **Akar masalah:** selama edit bertahap v0.7 (tambah Vision) → v0.8 (tambah Routine) → v0.9 (tambah Initiative), tiap kali instruksi bilang "tambahkan parameter baru ke `_build_contents()`", implementasi user menambahkan **method baru** alih-alih **mengedit method yang sudah ada** — hasilnya 3 definisi `_build_contents()` menumpuk di 1 file. Python tidak error untuk ini (class body cuma nyimpen reference terakhir per nama), jadi aplikasi **tetap jalan** (cuma definisi TERAKHIR yang kepakai, yang untungnya sudah paling lengkap) — tapi 2 definisi awal jadi kode mati yang membingungkan. **Fix:** konsolidasi jadi 1 definisi `_build_contents()` saja, method-method lain dirapikan urutannya per kategori. **Pelajaran untuk chat baru:** kalau diminta "tambahkan parameter ke method X", SELALU edit definisi yang sudah ada (pakai `str_replace` yang presisi), JANGAN pernah menambahkan definisi method baru dengan nama sama.
10. **Internal marker bookkeeping (`__ARONA_ROUTINE_HISTORY__`, `__ARONA_INTERNAL_STATE__`, `__ARONA_RELATIONSHIP_STATE__`) bocor ke tampilan Memory Inspector** (v0.9.5, BARU) — **Akar masalah:** `RoutineHistory`/`InternalStateCoordinator`/`RelationshipCoordinator` semuanya menyimpan bookkeeping persistence lewat kategori `"general"` + marker teks unik di `MemoryManager` (pola resmi sejak v0.6.3) — ini benar secara arsitektur, tapi `build_memory_snapshot()` awalnya menampilkan SEMUA memori kategori general apa adanya, termasuk marker JSON mentah yang bukan untuk dibaca manusia. **Fix:** `memory_debug.py` sekarang filter entry yang `content`-nya berawalan `__ARONA_` dari daftar `recent`, tapi tetap dihitung di `total_count` dan field baru `internal_marker_count` untuk transparansi. **Dikonfirmasi user via `test_developer_snapshot.py` — sekarang `recent` cuma nampilin memori Teacher yang asli.**

Semua bug di atas sudah diperbaiki dan dikonfirmasi user. **Tidak ada bug terbuka per v0.9.5.**

## 10. Instruksi Kalau Lanjut Chat Baru

1. **Jangan redesign arsitektur** yang sudah ada (bagian 4–6) tanpa alasan kuat (bug kritis).
2. **Jangan ubah** `ai/prompt_builder.py`, `ai/conversation.py`, `database/memory_manager.py`, `avatar/*` inti, `behavior/*` inti, `vision/*` inti, `routine/*` inti, `initiative/*` inti, atau `prompts/*.txt` kecuali diminta eksplisit.
3. **Jangan import PySide6/Qt di luar folder `ui/`.**
4. **Jangan pernah mencampur Memory dan Conversation. Jangan perkenalkan vector DB/RAG.**
5. **`developer/*` TIDAK BOLEH memanggil method mutating APA PUN** dari subsystem manapun (`manual_override`, `clear_routine_queue`, `trigger_hotkey`, `save_memory`, `start_recording`, dst) — cuma getter/property. Ini pelanggaran paling gampang terjadi kalau developer tools "ditambah fitur" tanpa hati-hati.
6. **Semua `*Snapshot` dataclass di `developer/*` HARUS tetap `frozen=True`** — Snapshot Model immutable adalah pola wajib.
7. **`AvatarManager`/`VoiceManager` tetap di-inject terpisah ke `DeveloperService`, JANGAN dipaksa lewat `Companion`** — itu akan melanggar Avatar Independence Policy.
8. **KALAU DIMINTA "tambah parameter ke method X yang sudah ada" — SELALU edit definisi yang ada (`str_replace` presisi), JANGAN PERNAH tambah method baru dengan nama sama.** Ini pernah jadi bug nyata (`_build_contents()` terduplikasi 3x) — pastikan tidak terulang di modul manapun.
9. **Filter `__ARONA_*` internal marker di `memory_debug.py` WAJIB dipertahankan** — jangan hapus filter ini walau kelihatan "cuma nge-skip data", ini fix nyata untuk masalah UX Memory Inspector.
10. **`PerformanceTracker` ditulis oleh `Companion`, dibaca oleh `DeveloperService`** — kalau menambah subsystem baru yang butuh diukur performanya, tambahkan `self._timed("nama_baru", lambda: ...)` di `Companion`, jangan bikin mekanisme timing terpisah.
11. **Ephemeral Context (Behavior+Vision+Routine+Initiative) TIDAK BOLEH ditulis ke `prompts/*.txt` atau ke Memory** (tetap berlaku, tidak berubah).
12. **Kalau kirim teks ke Gemini TTS, WAJIB tetap prepend instruksi eksplisit** (`_SPEECH_INSTRUCTION` di `speech/tts.py`).
13. **SELALU CEK jumlah instansiasi objek berat** di `ui/window.py`/`main_gui.py` kalau menambah/memindah blok inisialisasi.
14. **Perhatikan penamaan parameter constructor yang benar** — cek signature dulu kalau ragu, termasuk `DeveloperService(companion=..., avatar_manager=..., voice_manager=..., performance_tracker=...)`.
15. **Fase project sekarang: Phase 3 TUNTAS SEPENUHNYA (v0.7–v0.9.5 selesai semua). Phase 4 — Release DIMULAI. Milestone berikutnya: v1.0 Stable Release.**
16. **v1.0 BUKAN tentang fitur baru** — sesuai rekomendasi GPT: audit arsitektur, bug fixing, optimasi performa/startup, test coverage (unit/integration/smoke test), packaging (installer Windows + portable build), dokumentasi user+developer, Settings lengkap (model AI, memory, voice, avatar, developer mode), validasi modularitas semua subsystem sesuai kontrak API sejak v0.1. Kalau user minta fitur baru di luar ini saat masuk v1.0, itu di luar filosofi Phase 4 — boleh diingatkan, tapi tetap ikuti keinginan user kalau tetap mau.
17. Semua modul baru tetap Single Responsibility; logic tidak boleh nyasar antar folder.
18. User berkomunikasi dalam Bahasa Indonesia; kode & komentar teknis boleh Inggris seperlunya, penjelasan ke user pakai Bahasa Indonesia.
19. Kalau butuh tau isi kode file tertentu yang belum di-paste di chat baru, minta user paste isinya dulu — jangan asumsikan berubah dari yang didokumentasikan di sini kecuali dikonfirmasi.

## 11. Roadmap Selanjutnya

- **v1.0 — Stable Release (Phase 4, satu-satunya milestone tersisa):**
  - Audit seluruh arsitektur — validasi tiap subsystem (`ai/`, `avatar/`, `behavior/`, `database/`, `developer/`, `initiative/`, `routine/`, `speech/`, `vision/`) masih mengikuti kontrak Independence Policy masing-masing sejak pertama dibuat.
  - Bug fixing menyeluruh (cek kembali semua "Catatan untuk chat baru" di bagian 7 kalau ada yang perlu di-follow-up).
  - Optimasi performa & startup — `DeveloperService.get_performance()` sudah siap dipakai untuk mengidentifikasi bottleneck nyata (mis. Whisper load time, Gemini response time).
  - Test coverage: unit test per subsystem kecil (`behavior/`, `routine/`, `initiative/` sangat cocok karena pure-function/dataclass-heavy), integration test alur `Companion.chat()`, smoke test startup end-to-end.
  - Packaging: installer Windows + portable build.
  - Dokumentasi user (cara pakai) + developer (arsitektur, kontrak API — dokumen master context ini bisa jadi basis).
  - Settings GUI lebih lengkap: pilihan model AI, konfigurasi memory, voice, avatar, DAN toggle Developer Mode (mengaktifkan GUI Developer Tools yang backend-nya sudah lengkap sejak v0.9.5).
- **Fitur lanjutan/eksperimental di luar roadmap resmi (kalau diminta eksplisit):** GUI Developer Tools panel (dockable, refresh button, search/filter log, export button — backend 100% siap), infrastruktur timer/scheduler background untuk Arona benar-benar mengirim pesan pertama tanpa Teacher mengetik (`Initiative.should_start()` sudah ada, butuh komponen baru di `ui/`), tombol GUI Vision (capture/refresh/preview), dukungan webcam/upload gambar, UI show/edit/delete memori, command `/memory`, ganti model Live2D via `vtube_model_config.json`.
