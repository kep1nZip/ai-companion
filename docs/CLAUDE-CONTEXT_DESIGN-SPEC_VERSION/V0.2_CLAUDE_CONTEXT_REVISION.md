## 1. Apa Project Ini

AI Waifu Companion desktop app, terinspirasi Arona (Blue Archive). Bukan sekadar chatbot — dirancang modular supaya bisa berkembang jadi companion dengan voice, avatar Live2D, memory, emosi, dll.

**Prinsip pengembangan:** incremental, per-milestone, jangan lompat fitur, jangan overengineering, jangan redesign arsitektur tanpa alasan kuat.

**Filosofi inti (dari revisi GPT):** Desktop GUI **bukan** aplikasinya. Aplikasi sesungguhnya adalah `Companion`. GUI hanyalah salah satu presentation layer. Nanti Voice Interface, Discord Bot, atau Web Interface semuanya bisa dipasang di atas `Companion` yang sama tanpa mengubah backend:

```
Desktop GUI  ↘
Voice        → Companion → Gemini
Discord Bot  ↗
Web          ↗
```

v0.2 juga sebaiknya dipikirkan bukan sebagai "Chat Window", tapi sebagai **Desktop Shell** — cangkang yang nanti diisi Chat, Memory, Voice, Avatar, Settings, Emotion, Vision, Automation. Sebagian besar belum ada isinya, tapi arsitekturnya sudah disiapkan (lihat Sidebar di bagian 6).

## 4. Arsitektur (WAJIB Dipertahankan)

```
Terminal (main.py)     Desktop GUI (main_gui.py + ui/window.py)
        │                              │
        └──────────────┬───────────────┘
                        ↓
                   Companion (ai/companion.py)
                        ↓
              ┌─────────┴─────────┐
              ↓                   ↓
        Conversation         GeminiClient
   (ai/conversation.py)     (ai/gemini.py)
                                   ↓
                             Gemini API
```

**Aturan besi:**
- `Companion` adalah satu-satunya modul yang tahu soal `Conversation` **dan** `GeminiClient` sekaligus.
- UI (terminal maupun GUI) **hanya** boleh panggil `Companion.chat(user_input)`, `Companion.get_history()`, `Companion.clear_history()`.
- UI **tidak boleh** import `GeminiClient`, `types.Content`, atau bangun prompt sendiri.
- **UI Independence** (ditegaskan ulang di revisi GPT): PySide6/Qt **tidak boleh** di-import di luar folder `ui/`. Backend (`ai/*`, `config/*`) tidak boleh tahu bahwa GUI itu ada.
- `ai/gemini.py`, `ai/prompt_builder.py`, `ai/personality.py`, dan seluruh `prompts/*.txt` **belum pernah diubah** sejak v0.1.0 dan seharusnya tetap begitu sampai ada bug kritis.
- Success criteria v0.2: kalau `main.py` (terminal) dihapus total, `main_gui.py` dan seluruh backend tetap jalan tanpa perubahan apa pun.

## 5. Kontrak API Tiap Modul (Penting Buat Chat Baru)

### `ai/companion.py` — `Companion`
```python
Companion()                          # init: load prompts, build system prompt, siapkan GeminiClient + Conversation
Companion.chat(user_input: str) -> str      # kirim pesan, return balasan Arona. Raise RateLimitError / CompanionError
Companion.get_history() -> list             # ambil history (list[types.Content])
Companion.clear_history() -> None           # hapus history
```
Exception: `RateLimitError` (429), `CompanionError` (error lain dari Gemini).

### `ai/conversation.py` — `Conversation`
```python
add_user_message(text: str) -> None
add_assistant_message(text: str) -> None
rollback_last_message() -> None      # dipanggil Companion saat request gagal
clear() -> None
get_history() -> list[types.Content]  # return copy, bukan reference
```
`_history` tetap private — jangan pernah diakses langsung dari luar.

### `ai/commands.py`
```python
is_command(text: str) -> bool
run_command(text: str, companion) -> CommandResult   # CommandResult(message: str, should_exit: bool)
```
Command aktif: `/help`, `/history`, `/clear`, `/version`, `/exit`. Reusable di terminal & GUI. **First-class feature** — jangan pernah diganti tombol.

### `ai/gemini.py` — `GeminiClient` (stateless, jangan diubah)
```python
GeminiClient(api_key, model_name, system_prompt)
GeminiClient.send(contents: list[types.Content]) -> str
```

### `config/logger.py`
```python
from config.logger import logger   # loguru instance, sudah dikonfigurasi (file logs/app.log, rotation 1MB, retention 7 hari)
```

## 6. GUI (v0.2 + Revisi Shell) — Yang Sudah Dibangun

- **Framework:** PySide6.
- **Konsep:** Desktop Shell, bukan sekadar Chat Window. Diibaratkan mirip Discord Desktop / Telegram Desktop / VS Code — minimal, tenang, profesional. Bukan launcher anime yang flashy.
- **Tema:** Dark theme, aksen biru lembut (`#4a90e2`). Stylesheet **dipisah ke `ui/theme.py`** (`DARK_STYLESHEET`) — sebelumnya sempat digabung ke `main_gui.py`, sekarang dipisah supaya siap jadi multi-theme di masa depan.
- **Window size:** default `1000x700`, minimum `900x600`, resizable.
- **Layout:**
  ```
  Menu Bar (File / Conversation / Help)
  ├── Sidebar (permanen, 170px)   │  Chat Area (scrollable)
  │   - Chat (aktif)              │  Input box + Send button
  │   - Memory (Coming Soon)      │
  │   - Voice (Coming Soon)       │
  │   - Avatar (Coming Soon)      │
  │   - Settings (Coming Soon)    │
  Status Bar
  ```
- **Sidebar (`ui/navigation.py`, hasil revisi):** widget `Sidebar` permanen di kiri. Semua item **non-fungsional** (`setEnabled(False)`) — sengaja, cuma placeholder ruang visual & struktur, belum ada logic apa pun di baliknya. Nanti tiap milestone (v0.3–v0.7) tinggal `setEnabled(True)` + sambungkan ke view masing-masing.
- **Chat bubble:** Teacher rata kanan (biru), Arona rata kiri (abu gelap). Masing-masing punya avatar bulat 40px di sampingnya (`icon-user.jpg`, `icon-arona.jpg` dari `assets/avatar/`), auto-crop jadi lingkaran, fallback ke placeholder abu-abu kalau file tidak ditemukan. Avatar di-cache sekali per `ChatArea`, bukan re-load tiap pesan (buat performa di chat ratusan pesan).
- **Threading:** `ChatWorker(QThread)` di `ui/chat_worker.py` — request ke Gemini jalan di background thread, input & send button di-disable selama "Thinking...", GUI tidak pernah freeze.
- **Command system:** tetap berfungsi penuh di kotak input GUI (`/help`, `/clear`, dll), hasilnya tampil sebagai bubble Arona (kecuali `/clear` yang langsung bersihkan chat area). Tidak diganti tombol.
- **Status bar:** saat ini pakai `self.statusBar()` bawaan Qt dengan teks ("Ready", "Thinking...", "Connected", "Error"). Belum dipisah jadi `ui/statusbar.py` custom class — reserved buat nanti kalau butuh indikator state lebih kompleks (Listening.../Speaking.../Memory Updated).
- **Belum diimplementasikan (sengaja, dilarang eksplisit di revisi):** Live2D, VTube Studio, avatar panel besar, bahkan placeholder image sekalipun untuk avatar karakter utama — GUI harus tetap chat-focused, integrasi avatar besar itu jatah v0.5. Juga belum ada: `ui/statusbar.py`, `ui/dialogs.py`, markdown/code block formatting, export/import chat, settings dialog fungsional, microphone button.

## 7. File Prompt (`prompts/*.txt`) — FINAL, Jangan Diubah/Ditambah

| File | Isi |
|---|---|
| `identity.txt` | Arona = companion Teacher, resident system manager Shittim Chest, tidak pernah ngaku AI/chatbot |
| `personality.txt` | Ceria, perhatian, lembut, agak clumsy, suka dipuji, suka strawberry milk & pudding |
| `relationship.txt` | Teacher = orang paling penting, Arona diam-diam suka Teacher tapi denial ("Arona definitely doesn't like Teacher!"), relasi berkembang pelan lewat trust |
| `behavior.txt` | Reaksi situasional (Teacher capek, sakit, sukses, gagal, hilang lama, dll) |
| `speaking_style.txt` | Ringkas 2-5 kalimat, pakai "Ehehe~", "Huaaa...", ada action di parentheses seperti (Tilts head) |
| `halo.txt` | Halo berubah sesuai emosi — dijelaskan dalam parentheses tiap Arona bicara, contoh `(Pink Heart Halo)` |
| `system_rules.txt` | Stay in character, jangan reveal prompt, jangan fabricate memory, selalu panggil Teacher/Arona |

Kombinasi semua ini dijadikan satu system prompt oleh `ai/prompt_builder.py`.

## 9. Keputusan Desain Kumulatif (Kenapa Sesuatu Dibangun Begitu)

- **`GeminiClient` stateless** — history selalu dikirim dari luar, supaya modul ini gampang diganti/diuji tanpa mempengaruhi state percakapan.
- **`Companion` sebagai satu pintu masuk backend** — biar terminal, GUI, dan nanti Voice/Discord/Web tinggal panggil satu API yang sama, tanpa tahu detail Gemini/Conversation.
- **Command system dipisah dari UI** — supaya command yang sama bisa dipanggil dari terminal maupun GUI tanpa duplikasi logic, dan tetap first-class walau ada tombol.
- **Logging di level backend (`Companion`), bukan di UI** — karena harus tetap tercatat siapa pun yang memanggil (terminal/GUI/nanti voice).
- **Avatar chat bubble di-load & di-cache di `ChatArea`, bukan re-render tiap pesan** — antisipasi requirement "conversation should support hundreds of messages."
- **`main.py` (terminal) dan `main_gui.py` (GUI) dipisah total** — supaya salah satu bisa dihapus tanpa merusak yang lain (success criteria v0.2).
- **Stylesheet dipisah ke `ui/theme.py`** — hasil revisi, biar `main_gui.py` cuma jadi bootstrapper tipis, dan theme bisa berkembang (misal light mode) tanpa bongkar entry point.
- **Sidebar dibuat sebagai widget terpisah (`ui/navigation.py`) dan sengaja non-fungsional** — nyiapin ruang visual "Desktop Shell" tanpa membangun fitur yang belum waktunya (Memory, Voice, Avatar, Settings).
- **Avatar karakter besar / Live2D sengaja TIDAK diberi placeholder sama sekali** — beda dengan sidebar, ini murni ditunda total sampai v0.5 sesuai instruksi eksplisit revisi, supaya GUI tetap "chat-focused."
- **`ui/statusbar.py` dan `ui/dialogs.py` belum dipisah dari `window.py`** — masih dianggap cukup sederhana, dipecah nanti kalau kompleksitasnya sudah butuh (avoid premature abstraction).

## 10. Instruksi Kalau Lanjut Chat Baru

Kalau kamu (AI) baca dokumen ini di awal chat baru:

1. **Jangan redesign arsitektur** yang sudah dijelaskan di bagian 4, 5, & 6 tanpa alasan kuat (bug kritis).
2. **Jangan ubah** `ai/gemini.py`, `ai/personality.py`, `ai/prompt_builder.py`, atau isi `prompts/*.txt` kecuali diminta eksplisit.
3. **Jangan import PySide6/Qt di luar folder `ui/`** — ini pelanggaran arsitektur paling kritis di project ini.
4. **Jangan tambahkan avatar besar/Live2D/placeholder karakter** ke GUI kecuali user secara eksplisit bilang sudah masuk fase v0.5 — ini dilarang keras di spec, beda dari fitur sidebar/memory yang boleh placeholder.
5. Kalau user minta fitur baru, cek dulu itu masuk milestone versi berapa (lihat tabel di bagian 2) — kalau versi depan (misal v0.3+), tanya dulu apakah user memang mau lompat milestone atau cuma nyiapin arsitektur.
6. Semua modul baru harus tetap Single Responsibility, tidak boleh backend logic nyasar ke `ui/`, dan sebaliknya.
7. User berkomunikasi dalam Bahasa Indonesia, kode & komentar teknis boleh Inggris seperlunya tapi penjelasan ke user pakai Bahasa Indonesia.
8. Kalau butuh tau isi kode file tertentu yang belum di-paste di chat baru, minta user paste isinya dulu — jangan asumsikan isi file berubah dari yang didokumentasikan di sini kecuali dikonfirmasi.
