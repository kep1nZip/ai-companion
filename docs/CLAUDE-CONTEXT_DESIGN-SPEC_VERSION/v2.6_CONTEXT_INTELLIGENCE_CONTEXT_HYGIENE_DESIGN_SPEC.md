# 3. Core Goals

## Goal A — Context Hygiene

Context internal tidak boleh bocor ke percakapan normal.

Contoh internal:

```text
__ARONA_INTERNAL_STATE__
__ARONA_ROUTINE_HISTORY__
__ARONA_RELATIONSHIP_STATE__
__ARONA_INITIATIVE_STATE__
```

harus tetap menjadi data internal.

Model percakapan hanya menerima representasi yang memang dibutuhkan.

---

## Goal B — Context Relevance

Hanya context yang relevan terhadap input Teacher yang diprioritaskan.

Contoh:

```text
Teacher:
"Apa ya nama game yang kemarin aku mainkan?"
```

Relevant:

```text
memory terkait game
conversation context
vision jika baru menangkap game tersebut
```

Tidak harus membawa:

```text
routine history
old unrelated preferences
internal scheduler state
```

---

## Goal C — Context Priority

Tidak semua context memiliki bobot yang sama.

Target konseptual:

```text
Current Teacher Message
        ↓ highest relevance

Current Conversation
        ↓

Current Emotion / State
        ↓

Relevant Memory
        ↓

Fresh Vision
        ↓

Relationship Context
        ↓

Routine / Initiative context
        ↓

Older / weaker context
```

Urutan final tidak boleh di-hardcode tanpa audit terlebih dahulu.

---

## Goal D — Context Freshness

Context yang berubah cepat harus memiliki freshness.

Contoh Vision:

```text
Vision captured 5 seconds ago
```

berbeda dengan:

```text
Vision captured 30 minutes ago
```

Context yang terlalu lama tidak otomatis dianggap false, tetapi relevansinya dapat turun.

---

## Goal E — Context Validity

Memory yang sudah:

```text
status = superseded
```

tidak boleh masuk sebagai current memory.

Target:

```text
Active Memory
    → eligible

Superseded Memory
    → history only
```

---

## Goal F — Context Budget

Jumlah context harus terkontrol.

Target:

```text
More context
≠
Better answer
```

ContextBuilder harus menghindari memasukkan data berlebihan hanya karena data tersebut tersedia.

# 8. Phase 2 — Current vs Historical Memory

v2.5 telah memperkenalkan:

```text
active
superseded
```

ContextBuilder harus memahami lifecycle ini.

Default chat context:

```text
active only
```

Superseded memory:

```text
history/debug context
```

bukan current factual context.

Tujuan:

```text
Teacher says:
"Sekarang aku tidak suka americano."

↓

ContextBuilder
    ↓
does not also tell model:
"Teacher likes americano."
```

kecuali history tersebut memang secara eksplisit diperlukan.

# 9. Phase 3 — Context Relevance

Context harus dipilih berdasarkan relevansi.

Gunakan mekanisme yang sudah ada terlebih dahulu:

```text

category
recency
existing relevance selection
```

Jangan langsung membuat:

```text
embedding database
vector store
semantic search service
```

hanya karena nama tersebut populer.

Prinsip:

```text
Reuse first.
Measure second.
Expand only when necessary.
```

# 10. Phase 4 — Context Priority

Buat model priority yang sederhana dan dapat dijelaskan.

Conceptual:

```text

=

+

+

+
```

Jangan membuat sistem scoring kompleks tanpa kebutuhan.

Priority bukan berarti:

```text

```

Priority hanya membantu menentukan context mana yang masuk budget.

# 11. Phase 5 — Vision Freshness

Vision context adalah context yang paling cepat menjadi stale.

Contoh:

```text
Screenshot at T1:
VS Code opened
```

Beberapa menit kemudian:

```text
Teacher switched to browser
```

Vision lama tidak boleh diperlakukan sebagai kondisi layar saat ini.

Minimal model:

```text
VisionContext
 ├── captured_at
 ├── summary
 └── freshness state
```

Jika field timestamp sudah tersedia, reuse.

Jangan menambah field duplicate.

---

# 12. Phase 6 — Context Budget

Tetapkan budget secara praktis.

Budget dapat mempertimbangkan:

```text
message length
memory count
vision size
conversation history
model capability
```

Jangan menetapkan angka arbitrer sebagai kebenaran universal.

Awali dengan baseline aktual.

Contoh konseptual:

```text
Current message
+
recent conversation
+
top relevant memories
+
fresh vision
+
minimal behavior state
```

daripada:

```text
entire database
+
all history
+
all state
```

---

# 13. Phase 7 — Context Deduplication

Cari context yang menyampaikan fakta sama berkali-kali.

Contoh:

```text
Memory:
"Teacher suka kopi americano."

Relationship:
"Teacher has a preference for americano."

Conversation:
"Teacher bilang suka americano."
```

Model tidak perlu menerima tiga representasi identik jika satu sudah cukup.

Deduplication harus:

```text
conservative
```

Jangan menghapus context hanya karena memiliki kata yang sama.

---

# 14. Phase 8 — Context Conflict Check

Sebelum final context dibuat:

```text
Current candidate context
        ↓
Conflict check
```

Pastikan:

```text
superseded memory
```

tidak hidup sebagai current fact.

Jika ada dua context yang benar-benar bertentangan:

```text
prefer newer valid state
```

jika hubungan tersebut sudah dapat dibuktikan dari memory lifecycle.

Jangan membuat LLM menebak sendiri konflik yang sebenarnya dapat diselesaikan sebelum prompt dibuat.

# 23. Decision Gate

## PASS

v2.6 PASS apabila:

- [ ] Internal context leakage tidak terjadi.
- [ ] Superseded memory tidak dipakai sebagai current fact.
- [ ] Relevant memory tetap tersedia.
- [ ] Unrelated memory berkurang.
- [ ] Vision freshness diperhitungkan.
- [ ] Duplicate context berkurang tanpa false filtering besar.
- [ ] Context budget bekerja.
- [ ] Local AI tetap bekerja.
- [ ] Gemini AI tetap bekerja.
- [ ] GUI tetap responsif.
- [ ] Async memory tetap stabil.
- [ ] Vision OFF/MANUAL/AUTO tetap stabil.
- [ ] Tidak ada regression penting.

## CONDITIONAL PASS

Gunakan apabila:

- context ranking belum sempurna,
- beberapa edge case relevansi masih ambigu,
- budget perlu tuning lebih lanjut,
- kualitas jawaban tetap acceptable.

Semua limitation harus didokumentasikan.

## FAIL

FAIL apabila:

- Internal data bocor ke user-facing prompt secara material.
- Memory aktif yang benar terbuang secara sistematis.
- Superseded memory kembali dianggap current.
- Vision stale menyebabkan behavior salah secara signifikan.
- ContextBuilder menyebabkan GUI/runtime regression.
- Local/Gemini provider mengalami regression.
- Async worker rusak.
- ContextBuilder menjadi orchestrator baru.

# 26. Known Issues yang Dibawa dari Milestone Sebelumnya

### Memory Contradiction

v2.5 sudah memperbaiki primary contradiction:

```text
old → superseded
new → active
```

Jangan mengubah semantics ini dalam v2.6.

### Internal Marker Contamination

Known issue dari milestone sebelumnya:

```text
internal marker dapat masuk ke chat context
```

v2.6 menjadikan **Context Hygiene** sebagai tempat yang tepat untuk menyelesaikan hal ini.

Namun solusi harus dilakukan di context boundary, bukan dengan menghapus memory internal.
