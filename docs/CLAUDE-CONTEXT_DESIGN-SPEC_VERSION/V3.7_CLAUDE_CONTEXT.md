## 3. Alasan Setiap Perubahan

### File baru — `ai/conversation_feedback.py`
Pola IDENTIK `ai/response_calibration.py` (v3.6): pure function, TIDAK ADA LLM/network/state baru.

- 9 kategori: `confusion`, `correction`, `negative_length_feedback`, `negative_complexity_feedback`, `repeat_request`, `simplification_request`, `expansion_request`, `positive_acknowledgement`, `closure`. SEMUA bisa muncul bersamaan (spec §8 "Multi-Cue Feedback") — berbeda dari pendekatan v3.5/v3.6 yang pakai non-overlap bookkeeping per kategori, di sini overlap antar KATEGORI justru diharapkan (cuma dalam SATU kategori yang di-dedup kalau ada >1 pola match persis sama).
- `closure_detected = detect_closure(text) or <pola tambahan lokal>` — REUSE LANGSUNG fungsi v2.8, pola tambahan ("udah cukup", dst) ditambah LOKAL di modul ini (bukan mengedit `conversation_signals.py`) untuk menjaga zero-risk terhadap Initiative/Routine yang sudah stabil.
- **Keputusan konservatif eksplisit:** kata "salah" berdiri sendiri TIDAK dijadikan trigger correction (terlalu ambigu — bisa berarti "kode saya salah di baris X", problem_report biasa, bukan koreksi ke Arona). Kata "lanjut" berdiri sendiri TIDAK dijadikan trigger expansion_request (bentrok dengan "lanjut yang tadi" v3.3, akan mendominasi false-positive).
- `ConversationFeedback` (frozen dataclass) — **nol field** `previous_response_quality`/`misunderstanding_score`/`assistant_error_score` (Hard Boundary §4.2), nol confidence buatan.

### `ai/context_builder.py`
**Keputusan arsitektur penting:** BEDA dari `_format_temporal`/`_format_response_calibration` (v3.5/v3.6, dipanggil DARI DALAM `build()`, selalu di awal ephemeral block) — v3.7 dapat method PUBLIK TERPISAH `build_feedback_section()`. Alasan: spec §16 eksplisit minta evidence feedback "tetap dekat titik generasi, mengikuti pelajaran arsitektur yang sama dipakai milestone sebelumnya" — merujuk pola reinforcement note hotfix v3.3 (ditaruh di PALING AKHIR `contents`, bukan di awal ephemeral block). `ContextBuilder` TETAP satu-satunya yang merangkai teks (prinsip assembly-only tidak dilanggar) — Companion cuma memutuskan DI MANA menaruh potongan teks ini.

### `ai/companion.py`
`_build_contents()` menghitung `conversation_feedback` dari `user_input`, ditaruh sebagai `Content` TERPISAH di PALING AKHIR `contents` (setelah riwayat, setelah note referensi v3.3) lewat `ContextBuilder.build_feedback_section()`. Di-cache ke `_last_conversation_feedback` untuk dashboard. **`_build_autonomous_contents()` TIDAK disentuh sama sekali** (diverifikasi test T19 yang memeriksa source code method itu).

### `developer/developer.py` + `ui/developer.py`
Field `conversation_feedback_debug` ditambah ke `DeveloperSnapshot`, ditampilkan sebagai section TAMBAHAN di card **"Memory Decisions"** — bukan dashboard baru (spec §23 eksplisit).

## 4. Bug yang Ditemukan & Diperbaiki Selama Implementasi

Tiga bug ketahuan sendiri lewat test (T10, T13, T14), semua diperbaiki sebelum laporan ini ditulis:

1. **T10 (Multi-Cue Feedback):** pattern `\byang\s+gampang\b` tidak match "ulang dari awal yang **lebih** gampang" (ada kata "lebih" di tengah). Diperbaiki jadi `\byang\s+(?:lebih\s+)?gampang\b`.
2. **T14 (v3.3 Integration):** pattern correction `\bbukan\s+(?:yang\s+)?itu\b` tidak match "bukan **yang tadi** itu" (dua kata sisipan). Diperbaiki jadi mengizinkan SATU kata sisipan opsional antara "yang" dan "itu" (`\bbukan\s+(?:yang\s+(?:\w+\s+)?)?itu\b`) — tetap dibatasi satu kata, bukan wildcard bebas, supaya tidak jadi terlalu longgar.
3. **T13:** bukan bug kode, tapi kesalahan konstruksi test saya sendiri — teks uji "jelasin singkat dan gampang" memang tidak match pola v3.6 manapun (v3.6 adalah modul yang DILINDUNGI, tidak boleh diubah tanpa bukti bug konkret di SITU). Diperbaiki dengan mengganti teks test jadi "singkat aja" yang memang sudah dikenali v3.6 sejak awal.

```
   satu "pemenang" — Arona bebas merespons secara natural (mis. minta

```
