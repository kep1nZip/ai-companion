## 1. Apa Project Ini

AI Waifu Companion desktop app, terinspirasi Arona (Blue Archive). Bukan sekadar chatbot — dirancang modular supaya bisa berkembang jadi companion dengan voice, avatar Live2D, memory, emosi, dll.

**Prinsip pengembangan:** incremental, per-milestone, jangan lompat fitur, jangan overengineering, jangan redesign arsitektur tanpa alasan kuat.

**Filosofi inti:** Desktop GUI **bukan** aplikasinya. Aplikasi sesungguhnya adalah `Companion`. GUI, Voice, Avatar (+animasinya), dan sekarang **Behavior Engine** hanyalah layer di sekitar `Companion`:

```
Teacher
  ↓
Conversation
  ↓
Behavior Engine (BARU v0.6.0, skeleton — BELUM terhubung)  →  BehaviorState
  ↓ (rencana v0.6.5)
Companion (+ Memory + waktu + nanti BehaviorState) → Gemini → reply (str)
  ↓
GUI chat bubble │ TTS → AudioPlayer + Lip Sync │ HaloMapper → Hotkey ekspresi
```

**Human-in-the-Loop Memory Policy (v0.3):** Memory milik Teacher. **Avatar Independence Policy (v0.5):** avatar cuma me-render reaksi visual, opsional. **Animation Independence Policy (v0.5.1):** layer animasi (Lip Sync, nanti Eye Blink/Breathing) digabung oleh `AvatarManager`, tidak saling menimpa. **Behavior Engine Policy (v0.6.0, BARU):** Behavior Engine **cuma menghasilkan state (context), tidak pernah menghasilkan bahasa** — Gemini tetap satu-satunya yang membuat kalimat. Behavior Engine tidak pernah bicara langsung ke Gemini/Avatar/Voice/GUI, semuanya lewat `Companion` (nanti) sebagai perantara tunggal.

## 4. Arsitektur (WAJIB Dipertahankan)

```
Terminal (main.py)     Desktop GUI (main_gui.py + ui/window.py)
        │                              │
        └──────────────┬───────────────┘
                        ↓
                   Companion (ai/companion.py)   ← BELUM terhubung ke BehaviorEngine di v0.6.0
                        ↓
     ┌──────────────────┼──────────────────┐
     ↓                  ↓                  ↓
Conversation       MemoryManager       GeminiClient
                        ↓
                     memory.db

Voice, Avatar, Lip Sync: TIDAK BERUBAH sejak v0.5.1 (lihat riwayat kalau butuh detail lengkap).

Behavior Engine (BARU v0.6.0, TERISOLASI, belum terhubung ke apa pun):
BehaviorEngine(memory_manager: Optional[MemoryManager] = None)
        ↓
   .current -> BehaviorState (selalu ada, immutable, snapshot terakhir)
   .update(user_input, reply) -> BehaviorState (v0.6.0: NO-OP, return state yang sama)
   .reset() -> None
```

**Aturan besi (v0.1–v0.5.1, tetap berlaku penuh):**
- `Companion` satu-satunya koordinator Conversation + MemoryManager + GeminiClient.
- `VoiceManager` satu-satunya koordinator Recorder→STT→Companion→TTS→Player.
- `AvatarManager` satu-satunya koordinator yang boleh bicara ke `VTubeStudioClient`, termasuk Animation Independence Policy (`update_parameter_layer`).
- UI tidak boleh import backend/speech/avatar langsung. UI Independence: Qt cuma di `ui/`.
- Conversation vs Memory tidak boleh dicampur. Tidak ada vector DB/RAG.

**Aturan besi BARU v0.6.0 — Behavior Engine:**
- `BehaviorEngine` **TIDAK PERNAH** berkomunikasi dengan Gemini, `AvatarManager`, `VoiceManager`, atau GUI secara langsung. Dia **cuma menghasilkan `BehaviorState`** — perantara ke sistem lain (kalau nanti ada) selalu lewat `Companion`.
- `BehaviorEngine` **TIDAK PERNAH** akses SQLite langsung — kalau butuh data memori (v0.6.3), harus lewat `MemoryManager` yang di-inject via constructor (Dependency Injection), sama seperti `MemoryExtractor` menerima `api_key`/`model_name` dari luar.
- `BehaviorState` **immutable** (`frozen=True`) — perubahan state selalu berupa **objek baru**, tidak pernah mutasi in-place. Ini pola yang harus dipertahankan di v0.6.1–v0.6.5.
- **v0.6.0–v0.6.4: `behavior/` sepenuhnya terisolasi** — tidak diimpor dari `ai/companion.py`, `ui/window.py`, atau modul manapun yang sudah ada. Baru di **v0.6.5** boleh disambungkan, dan bahkan saat itu, injeksinya harus **ephemeral** (dibangun ulang tiap `chat()`, sama pola dengan Memory/konteks waktu) — `PromptBuilder` tetap tidak boleh tahu `BehaviorState` ada.
- **Behavior failures tidak boleh pernah mengganggu conversation** — `BehaviorEngine.update()` sudah dibungkus try/except sejak v0.6.0 meski isinya masih no-op, supaya kontrak ini konsisten sejak awal dibuat, bukan ditambah belakangan.

## 9. Keputusan Desain Kumulatif (Tambahan v0.6.0)

- **v0.6 dipecah jadi 6 sub-milestone (v0.6.0–v0.6.5)**, bukan satu "Emotion Engine" besar — rekomendasi GPT yang disetujui, supaya tiap subsystem behavior (Emotion, Mood, Relationship, Energy, Curiosity, Initiative) bisa dirancang/ditest/didokumentasikan terpisah tanpa mengganggu fondasi v0.1–v0.5.1.
- **v0.6.0 murni "Design Only"** — semua modul di `behavior/` cuma dataclass/enum + docstring rencana per sub-versi (ditulis sebagai komentar `TODO(v0.6.x)` di `behavior_engine.py`), TIDAK ADA logic perhitungan apa pun, TIDAK dipanggil dari modul manapun yang sudah ada. Ini memastikan "compiles successfully, no existing functionality changes" (Success Criteria spec) benar-benar terpenuhi.
- **`BehaviorState` dibuat immutable (`frozen=True`)** sejak awal — konsisten dengan spec eksplisit, dan memudahkan debugging (`old_state != new_state` bisa langsung dipakai untuk deteksi perubahan) begitu logic beneran mulai diisi di v0.6.1+.
- **`BehaviorEngine.update()` sudah dibungkus try/except sejak v0.6.0** meski isinya no-op — kontrak "Behavior failures must never interrupt conversation" ditegakkan dari baris pertama, bukan ditambah belakangan setelah ada logic asli.
- **`RelationshipState` direncanakan disimpan lewat `MemoryManager`, bukan tabel SQLite baru** — konsisten dengan prinsip v0.3 bahwa `MemoryManager` tetap satu-satunya sumber kebenaran untuk data persisten tentang Teacher, menghindari "Memory kedua" yang bakal melanggar aturan Conversation-vs-Memory.
- **Integrasi nyata ke `Companion` ditunda sampai v0.6.5** — bukan kemalasan, tapi supaya tiap subsystem individual (v0.6.1–v0.6.4) punya kesempatan diuji sendiri-sendiri dulu sebelum "otak kedua" ini benar-benar memengaruhi balasan Arona.

## 10. Instruksi Kalau Lanjut Chat Baru

1. **Jangan redesign arsitektur** yang sudah ada (bagian 4–6) tanpa alasan kuat (bug kritis).
2. **Jangan ubah** `ai/gemini.py`, `ai/personality.py`, `ai/prompt_builder.py`, `ai/conversation.py`, `speech/*` inti, `avatar/*` inti, atau `prompts/*.txt` kecuali diminta eksplisit.
3. **Jangan import PySide6/Qt di luar folder `ui/`** — termasuk `behavior/`.
4. **Jangan pernah mencampur Memory dan Conversation. Jangan perkenalkan vector DB/RAG.**
5. **Jangan gabungkan `HaloMapper`+`ParameterMapper`. Jangan biarkan layer animasi panggil `VTubeStudioClient` langsung.**
6. **`BehaviorEngine` tidak boleh bicara langsung ke Gemini/AvatarManager/VoiceManager/GUI** — kalau nanti (v0.6.5) butuh memengaruhi balasan, HARUS lewat `Companion` sebagai perantara, dengan pola ephemeral yang sama seperti Memory/konteks waktu.
7. **`BehaviorEngine` tidak boleh akses SQLite langsung** — kalau butuh data persisten (v0.6.3 Relationship), harus lewat `MemoryManager` yang di-inject, bukan `sqlite3` baru.
8. **`BehaviorState` harus tetap immutable (`frozen=True`)** di semua sub-versi berikutnya — perubahan state selalu berupa objek baru.
9. **Sebelum v0.6.5, `behavior/` harus tetap 100% terisolasi** — jangan buru-buru sambungkan ke `Companion`/`ui/window.py` di v0.6.1–v0.6.4 kecuali user eksplisit minta lompat urutan.
10. **SELALU CEK jumlah instansiasi objek berat** (`VoiceManager`, Whisper, `Companion`) di `ui/window.py` kalau menambah/memindah blok inisialisasi — pernah jadi bug nyata di v0.5.1 (lihat bagian 7 poin 1).
11. **Perhatikan penamaan parameter constructor yang benar** — `VoiceManager(..., voice_name=..., on_audio_ready=...)`, `AvatarManager(vtube_client=..., halo_mapper=..., parameter_mapper=..., reconnect_interval=..., on_state_change=...)`, `BehaviorEngine(memory_manager=...)`. Cek signature dulu kalau ragu.
12. Kalau user minta fitur baru, cek dulu masuk milestone versi berapa (tabel bagian 2) — ingatkan urutan v0.6.0→v0.6.5 kalau user mau lompat, tapi tetap ikuti keinginan user kalau tetap mau lompat.
13. Semua modul baru tetap Single Responsibility; logic tidak boleh nyasar antar folder (`behavior/` ↔ `ai/` ↔ `avatar/` ↔ `speech/` ↔ `ui/`).
14. User berkomunikasi dalam Bahasa Indonesia; kode & komentar teknis boleh Inggris seperlunya, penjelasan ke user pakai Bahasa Indonesia.
15. Kalau butuh tau isi kode file tertentu yang belum di-paste di chat baru, minta user paste isinya dulu — jangan asumsikan berubah dari yang didokumentasikan di sini kecuali dikonfirmasi.

## 11. Roadmap Selanjutnya

- **v0.6.1 — Emotion System:** isi logic penentuan `Emotion` dari `user_input`+`reply` (kemungkinan reuse pola mirip `HaloMapper` — parsing dari teks/halo balasan, atau logic baru). Masih terisolasi di `behavior/`, belum tersambung ke `Companion`.
- **v0.6.2 — Mood System:** logic `Mood` dari tren `Emotion` antar waktu (butuh riwayat emosi, kemungkinan disimpan sementara di `BehaviorEngine` sendiri, bukan `Conversation`/`MemoryManager`).
- **v0.6.3 — Relationship System:** logic pertumbuhan `RelationshipState`, mulai membaca/menulis lewat `MemoryManager` (Dependency Injection yang sudah disiapkan di `BehaviorEngine.__init__`).
- **v0.6.4 — Energy & Curiosity System:** logic `EnergyState`/`CuriosityState`.
- **v0.6.5 — Behavior Integration:** BARU di titik ini `BehaviorEngine` disambungkan ke `Companion` secara ephemeral (pola sama dengan Memory/konteks waktu di `_build_contents()`), kemungkinan juga mulai memengaruhi Avatar (lewat `BehaviorState` bukan kontrol langsung) dan gaya bicara Voice kalau API-nya sudah mendukung.
- **v0.5.2 — Idle Animation:** masih direkomendasikan dikerjakan sebelum v0.6 penuh selesai (independen dari urutan v0.6.x, bisa diselang-seling).
- **v0.7 — Vision.**
- **Fitur lanjutan lain (tidak terikat versi tertentu):** UI show/edit/delete memori, command `/memory`, toggle mute/unmute suara, ganti model Live2D via `vtube_model_config.json`.
