# v2.2.2 — Local Memory Quality Validation — STATUS: 🚧 TOOLING SIAP, MENUNGGU HASIL TEST NYATA TEACHER

## Ringkasan

Spec v2.2.2 pada dasarnya adalah **protokol pengujian nyata** — butuh
LM Studio & Gemini API sungguhan, plus observasi visual GUI langsung.
Sandbox eksekusi saya **tidak punya akses jaringan**, jadi saya **tidak
bisa menjalankan test T01–T10 sendiri**. Yang saya buat sebagai gantinya:
**`test_memory_quality_validation.py`** — harness otomatis yang Teacher
jalankan sendiri di mesinnya, yang mengeksekusi T01–T08 langsung terhadap
`MemoryExtractor` sungguhan (Gemini & Local), lalu **menulis laporan `.md`
sesuai format Validation Log Template (spec §10) secara otomatis** —
bukan Teacher mengetik ulang tiap hasil test satu-satu ke dokumen.

T09 (GUI responsiveness) dan T10 (Developer Dashboard) **sengaja tidak
diotomatisasi** — keduanya butuh observasi visual manusia (freeze/lag,
render dashboard) yang tidak jujur diukur lewat script headless. Instruksi
manual untuk keduanya otomatis tercetak di akhir laporan yang dihasilkan.

## Cara Pakai (untuk Teacher)

```bash
# Test kedua provider sekaligus (default)
python test_memory_quality_validation.py

# Cuma Gemini
python test_memory_quality_validation.py --provider gemini

# Cuma Local (pakai LOCAL_PROVIDER_MODEL_NAME/BASE_URL dari .env)
python test_memory_quality_validation.py --provider local

# Override model/base-url Local secara manual
python test_memory_quality_validation.py --provider local --model "qwen/qwen3-vl-8b" --base-url "http://localhost:1234/v1"

# Custom nama file laporan
python test_memory_quality_validation.py --output hasil_validasi_2sept.md
```

**Prasyarat:** sama seperti `test_local_provider.py` yang sudah ada —
Gemini butuh `GEMINI_API_KEY` di `.env`, Local butuh LM Studio sudah
jalan & model sudah di-load.

**Yang dijalankan otomatis** (persis Test Matrix spec §6, T01–T08):
- 1× explicit fact ("Aku suka kopi americano.")
- 2× noise (kedua contoh dari spec, dites ke KEDUA provider — bukan cuma
  satu contoh per provider seperti di teks spec, supaya cakupan lebih
  menyeluruh)
- 9× variasi hedging (SEMUA variasi yang disebut spec §7 T03+T07 digabung,
  dites ke KEDUA provider — total cakupan lebih luas dari spec literal)
- 2× contradiction sequence ("Aku suka americano." → "Sekarang aku sudah
  tidak suka americano."), berurutan, tidak diacak

**Yang TIDAK disentuh sama sekali:** `memory.db` asli Arona. Semua
penyimpanan test pakai SQLite **temporary** yang dibuang otomatis setelah
proses selesai (`tempfile.TemporaryDirectory`) — supaya "Aku suka
americano" dkk dari test **tidak** mencemari memori jangka panjang Arona
yang sungguhan. Path file temp dicetak ke layar kalau Teacher ingin
inspeksi manual sebelum proses selesai.

## Apa yang Dihasilkan Laporan `.md`-nya

1. **Test Matrix** — tabel per test case (ID, provider, kategori, input,
   expected, actual, status ✅/❌/📝/⚠️), format sesuai spec §6.
2. **Validation Log** — satu blok per test case, format PERSIS sesuai
   template spec §10 (Date/Provider/Model/Input/Expected/Actual/Memory
   Saved/GUI Responsive/Error/Notes), siap copy-paste.
3. **Quality Evaluation** per provider — False Positive Rate (noise/hedging
   yang salah tersimpan), False Negative Rate (explicit fact yang gagal
   tersimpan), jumlah error/crash, plus **saran** label kualitas
   (Excellent/Good/Acceptable/Weak/Fail) — **eksplisit ditandai sebagai
   saran otomatis, bukan keputusan Decision Gate final** (spec §12 jelas
   itu tetap penilaian kualitatif Teacher/GPT, bukan skor mentah).
4. **Known Issue — Contradiction** — kondisi PERSIS memori yang tersisa di
   database temporary setelah kedua pesan contradiction dikirim, per
   provider. Kalau ternyata 2 entri kontradiktif hidup berdampingan,
   laporan otomatis menandainya dengan jelas sebagai known issue
   terverifikasi (bukan diselesaikan, cuma dicatat — sesuai instruksi
   eksplisit spec §7 T04/T08: *"Jangan melakukan implementasi supersession
   hanya untuk membuat test ini terlihat lulus"* — harness ini TIDAK
   mencoba memperbaiki apa pun, murni mengamati & mencatat).
5. Instruksi manual untuk T09/T10.

## Verifikasi yang Sudah Saya Lakukan (Offline, Terhadap Harness Itu Sendiri)

Karena tidak bisa memanggil Gemini/LM Studio sungguhan, saya uji
**harness-nya sendiri** dengan provider skenario palsu (`ScriptedProvider`,
meniru model yang sudah patuh hedging tapi contradiction tetap coexist):

✅ Pipa lengkap (extract → save ke temp DB → build report) jalan tanpa
error, laporan `.md` terbentuk dengan seluruh section yang diharapkan.

✅ Explicit fact case terklasifikasi PASS dengan benar.

✅ Semua 11 kasus noise/hedging terklasifikasi PASS dengan benar (provider
skenario memang didesain mengembalikan `[]` untuk semuanya).

✅ **Menemukan & memperbaiki bug di harness saya sendiri**: deteksi
"kondisi akhir contradiction" awalnya pakai pencarian substring
`"americano" in content`, yang salah tangkap entri dari test explicit-fact
lain yang kebetulan juga menyebut kata "americano" (dataset test saya
sendiri kebetulan bikin tabrakan ini). Diperbaiki dengan melacak **ID
persis** yang dikembalikan `save_memory()` khusus untuk kedua kasus
contradiction — dikonfirmasi lewat re-test, sekarang tepat 2 entri
(bukan 3) yang tertangkap di bagian Known Issue.

✅ Kegagalan setup provider (mis. `GEMINI_API_KEY` kosong, atau
`LocalProvider` tidak bisa dikonstruksi) tertangani dengan baik — tidak
meng-crash seluruh test run, provider lain tetap lanjut, laporan tetap
terbentuk dengan bagian "GAGAL SETUP" yang jelas.

**Yang TIDAK bisa saya verifikasi dari sandbox ini:** apakah model Local
(`qwen3-vl-8b`) SUNGGUHAN benar-benar patuh instruksi anti-hedging v2.2.1
saat menerima 9 variasi kalimat ragu-ragu, atau apakah GUI sungguhan
freeze saat extraction Local jalan di background. Ini **hanya bisa
dijawab lewat run sungguhan Teacher**.

   provider sekaligus) di mesinnya.

   `MEMORY_PROVIDER=local`, amati responsivitas GUI selagi chat) dan T10

   CONDITIONAL PASS / FAIL) — saya sengaja tidak mengklaim otoritas
   membuat keputusan ini sendiri, cuma menyediakan datanya.
5. Kalau hasilnya cukup baik → keputusan `MEMORY_PROVIDER=local` sebagai
   default baru bisa dipertimbangkan (bukan otomatis dari script ini).
6. v2.3 (Local Vision) **tidak dimulai** sampai poin di atas selesai,
   sesuai urutan yang GPT tetapkan.

## Larangan yang Dipatuhi

Tidak ada perubahan arsitektur, tidak ada provider abstraction baru, tidak
ada perubahan besar `MemoryManager` (harness cuma pakai parameter
`db_path` yang **sudah ada** sejak awal), tidak ada kategori memori baru,

diimpor, tidak diduplikasi/ditulis ulang), tidak ada percobaan
menyelesaikan contradiction/supersession (harness murni **mengamati dan
mencatat**, sesuai instruksi eksplisit spec). Satu file baru
(`test_memory_quality_validation.py`) mengikuti pola standalone test
script yang sudah ada di root project (`test_local_provider.py`,
`test_developer_snapshot.py`) — bukan struktur folder baru.
