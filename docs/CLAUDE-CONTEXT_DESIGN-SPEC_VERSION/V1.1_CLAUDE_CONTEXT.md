# Yang sudah diimplementasikan

## 1. `ai/companion.py` — 1 method baru

```python
def search_memories(self, query: str, limit: int = 50) -> list[Memory]:
    """Passthrough read-only ke MemoryManager.search_memory."""
    return self._memory_manager.search_memory(query, limit=limit)
```

Ditaruh persis di sebelah `list_memories()` yang sudah ada sejak v1.0
(dipakai `DeveloperService.get_memory()`). Ini **satu-satunya** perubahan di
`ai/companion.py`. Tidak ada method lain, tidak ada perubahan constructor,
tidak ada dependency baru.

`MemoryManager.search_memory()` sendiri **tidak diubah** — sudah ada sejak
v1.0, tinggal dipanggil.

## 2. `ui/memory_service.py` — BARU (non-Qt)

Boundary tipis antara GUI dan `Companion`. Isinya:

- `MemoryService(companion)` — wrapper dengan 2 method: `list_recent(limit=50)`
  dan `search(query, limit=50)`.
- Filter internal marker (`__ARONA_` prefix) — dipakai RoutineHistory/
  InitiativeHistory/RelationshipState/InternalState lewat
  `persistence_helper.save_by_marker()` untuk bookkeeping di kategori
  `general`. Konstanta `_INTERNAL_MARKER_PREFIX` **didefinisikan ulang** di
  sini (bukan di-import dari `developer/memory_debug.py`) supaya `ui/` tidak
  coupled ke `developer/` — dua konsumen kebetulan butuh filter yang sama
  untuk alasan berbeda (devtools = inspeksi teknis, di sini = Teacher-facing
  UX). Ini duplikasi 1 baris konstanta yang disengaja & didokumentasikan,
  bukan oversight.
- `MemoryReadError` — exception khusus, dilempar kalau Companion call gagal,
  ditangkap GUI untuk state error.
- **HANYA** memanggil `companion.list_memories()` /
  `companion.search_memories()`. Tidak pernah memanggil
  `save_memory/update_memory/delete_memory/clear_all/clear_memories`.

## 3. `ui/memory.py` — BARU (Qt)

`MemoryPage(QWidget)` — halaman Memory penuh:

- `MemoryListView` — search box + tombol Search + tombol Refresh + scroll
  area kartu memori (`MemoryCard`) + state label (loading/empty/error).
- `MemoryDetailView` — tampilan penuh 1 memori (kategori, isi lengkap,
  created_at, updated_at) + tombol Back. **Tidak ada tombol edit/hapus.**
- `MemoryCard` — kartu clickable (custom `mousePressEvent`, bukan
  `QPushButton`) menampilkan snippet (≤140 char) + kategori + tanggal.
- Internal pakai `QStackedWidget` (list ⇄ detail).
- **Baca sinkron di GUI thread** — SQLite lokal, dataset kecil (17 baris),
  tidak ada bukti butuh worker thread. Keputusan desain eksplisit, ada di
  docstring `MemoryPage`. Kalau nanti dataset jadi besar/lag beneran baru
  layak upgrade ke `QThread` mengikuti pola `ChatWorker`/`VoiceWorker`.
- `showEvent()` trigger load pertama kali halaman dibuka; setelah itu data
  di-cache sampai user klik Refresh (atau search).
- Refresh: kalau ada query aktif di search box, refresh me-re-run search;
  kalau kosong, refresh reload `list_recent()`.
- Format tanggal: `datetime.fromisoformat(...).strftime("%d %B %Y")` →
  `"17 August 2026"`.

# Yang SENGAJA tidak dikerjakan (scope minimal by design)

- **Filter kategori (dropdown)** — disebut opsional di design spec, di-skip
  supaya scope v1.1 tetap kecil. Gampang ditambah nanti kalau diminta:
  tinggal tambah `QComboBox` di `MemoryListView` + `MemoryService` method
  filter-by-category (atau filter client-side dari hasil `list_recent`).
- **Worker thread untuk Memory read** — dinilai tidak perlu (SQLite lokal,
  17 baris, sub-milidetik). Kalau dataset besar di masa depan, ini titik
  yang paling gampang di-upgrade tanpa mengubah `MemoryService`.
- **Edit/hapus dari GUI** — di luar scope by design (Read-Only Policy v1.1).
  Kalau mau ditambah di v1.2+, itu perubahan kebijakan besar (butuh
  konfirmasi user eksplisit dulu, bukan asumsi Claude).

# Instruksi untuk sesi Claude berikutnya

1. v1.1 Memory GUI **selesai dan terverifikasi jalan**. Jangan re-implementasi
   dari nol kalau user minta lanjut/perbaikan kecil — baca dulu isi
   `ui/memory.py`, `ui/memory_service.py`, `ui/navigation.py`, `ui/window.py`
   versi yang sudah di-deploy user (minta di-upload ulang kalau perlu, jangan
   asumsikan isinya sama persis dengan dokumen ini kalau user bilang sudah
   ada perubahan lanjutan).
2. Kalau user minta fitur baru di Memory GUI (filter kategori, edit, dsb):
   itu perubahan scope — treat sebagai keputusan desain baru, bukan bug fix.
   Tanya dulu kalau menyangkut write-access ke memori (breaking Read-Only
   Policy v1.1).
3. Arsitektur v1.0 (Architecture Freeze Policy) **masih berlaku** untuk
   subsystem di luar Memory GUI. `Companion` tetap satu-satunya orchestrator,
   `MemoryManager` tetap satu-satunya yang boleh sentuh `memory.db`.
4. Pola yang sudah established di v1.1 (boundary tipis non-Qt seperti
   `MemoryService`, sinkron read untuk data lokal kecil, QStackedWidget untuk
   page switching) bisa dijadikan referensi kalau v1.2+ menambah halaman GUI
   lain (mis. Voice/Avatar settings page) — tapi tetap inspect dulu, jangan
   copy-paste pola tanpa verifikasi ulang konteksnya cocok.
5. User komunikasi Bahasa Indonesia, kode/komentar teknis boleh Inggris.
