# Temuan penting dari inspeksi (`config/constants.py`, `config/settings.py`)

Ini bukan asumsi — dikonfirmasi baca source langsung sebelum implementasi.
**Temuan ini adalah alasan kenapa halaman Settings v1.4 jauh lebih sedikit
field editable dibanding mockup awal:**

1. **`config/settings.py`** memuat `GEMINI_API_KEY` SATU KALI saat import,
   lewat `load_dotenv()` + `os.getenv()`, disimpan sebagai **module-level
   constant** (bukan class dengan setter). Nilai ini di-*copy* ke dalam
   `GeminiClient`, `VoiceManager`, `MemoryExtractor`, `ImageAnalyzer` saat
   masing-masing di-construct — **tidak ada live reference**, jadi mengubah
   `config.settings.GEMINI_API_KEY` di memori setelah startup **tidak
   berefek apa pun** ke client yang sudah jalan. Karena itu API Key
   diklasifikasikan **Startup Editable**, bukan Runtime Editable — perubahan
   cuma berlaku setelah restart aplikasi.
2. **`GEMINI_API_KEY` adalah SATU-SATUNYA field yang punya mekanisme
   persistence nyata** (`.env`, lewat `python-dotenv` — dependency yang
   sudah ada di project). Semua field lain (`MODEL_NAME`, `TTS_MODEL_NAME`,
   `TTS_VOICE_NAME`, `STT_MODEL_SIZE`, `VTUBE_STUDIO_URL`,
   `VTUBE_MODEL_CONFIG_PATH`) adalah **konstanta murni di `constants.py`**,
   dipakai SEKALI saat construct object masing-masing subsystem
   (`GeminiClient.__init__`, `VoiceManager.__init__`), **tidak ada setter
   publik, tidak ada entry `.env`, tidak ada reload mechanism** untuk field
   apa pun selain API key. Karena itu semuanya diklasifikasikan
   **Read Only**.
3. **`DEVELOPER_MODE` TIDAK ADA di `constants.py` sama sekali** — sudah
   dicek langsung, bukan tebakan. Ini persis sesuai peringatan eksplisit di
   design spec §18 ("Claude WAJIB inspect dahulu... jika belum ada kontrak,
   STOP"). Karena itu **kategori Developer di-skip total dari Settings
   v1.4** — bukan STOP global untuk seluruh v1.4, cuma satu kategori yang
   memang kosong tidak dipaksa dibuat (sesuai §8: "kategori yang kosong...
   jangan dipaksa dibuat").
4. **`ui/theme.py` cuma punya SATU tema** (`DARK_STYLESHEET`, hardcoded,
   diterapkan sekali di `main_gui.py`). Tidak ada light theme, tidak ada
   mekanisme switching. Dropdown "Theme: Dark ▼" di mockup awal **fiktif**
   relatif terhadap kode aktual — Theme ditampilkan **Read Only** dengan
   catatan eksplisit "(only theme currently available)".
5. **`gemini.py`'s `GenerateContentConfig` cuma diisi `system_instruction`**
   — tidak ada `temperature`/`top_p`/`max_output_tokens` yang dikonfigurasi
   sama sekali di kontrak aktual project ini. Menambahkannya ke Settings
   berarti mengarang field yang tidak eksis di backend (dilarang §12) —
   **tidak ditambahkan sama sekali**, walau Gemini API secara umum punya
   parameter itu.
6. **`LOG_LEVEL` dipakai sekali saat import `config/logger.py`** (di dalam
   `logger.add(..., level=LOG_LEVEL, ...)`), tidak ada reload mechanism di
   `logger.py`. Membuatnya editable berarti menambah kode baru ke
   `config/logger.py` — di luar "minimal change" untuk v1.4, jadi **tidak
   ditampilkan sama sekali** (bukan cuma di-Read-Only-kan, memang di-drop).

# Yang sudah diimplementasikan

## 1. `ui/settings_service.py` — BARU (non-Qt)

- `SettingsSnapshot` (frozen dataclass) — **SENGAJA tidak menyimpan nilai
  mentah API key**, cuma `api_key_configured: bool`. Field lain: `version`,
  `theme`, `model_name`, `tts_model_name`, `tts_voice_name`,
  `stt_model_size`, `vtube_studio_url`, `vtube_model_config_path`,
  `vtube_token_present: bool`.
- `vtube_token_present` dihitung lewat `Path(VTUBE_TOKEN_PATH).exists()` —
  **file-existence check lokal di dalam `ui/settings_service.py` sendiri**,
  TIDAK import apa pun dari `avatar/`/`vtube.py`. Cuma menunjukkan status
  ada/tidaknya file, tidak pernah membaca isi token.
- `reveal_api_key()` — return nilai asli API key, **hanya dipanggil saat
  Teacher eksplisit klik tombol "Show"** di GUI, tidak pernah otomatis,
  tidak pernah masuk `SettingsSnapshot`.
- `validate_api_key(value)` — validasi non-empty. Ini BUKAN aturan yang
  dikarang — `config/settings.py` sendiri sudah `raise RuntimeError` kalau
  `GEMINI_API_KEY` kosong saat startup, jadi validasi ini konsisten dengan
  kontrak yang sudah ada.
- `save_api_key(value)` — cari `.env` lewat `dotenv.find_dotenv(usecwd=True)`
  (bukan path ditebak/hardcode), tulis lewat `dotenv.set_key()`. **TIDAK**
  mengubah `config.settings.GEMINI_API_KEY` di memori (lihat temuan §1 di
  atas — percuma, client sudah construct duluan). Error apa pun (`.env`
  tidak ketemu, gagal tulis) dibungkus `SettingsSaveError` dengan pesan user-
  facing yang aman (`"Unable to save settings. Your previous configuration
  is still active."`), detail teknis cuma masuk logger.

## 2. `ui/settings.py` — BARU (Qt)

`SettingsPage(QWidget)`:

- **General**: Version (Read Only), Theme (Read Only + catatan "only theme
  currently available").
- **AI**: Model (Read Only), **API Key** (satu-satunya field editable —
  `QLineEdit` mode Password, tombol Show/Hide, placeholder `••••••••` kalau
  sudah dikonfigurasi atau "Not configured" kalau belum).
- **Voice**: TTS Model, TTS Voice, STT Model Size — semua Read Only.
- **Avatar**: VTube Studio URL, Model Config Path, VTube Studio Token
  (Present/Not found) — semua Read Only.
- **Developer**: **tidak ada section ini sama sekali** (lihat temuan §3).
- Footer: `[Cancel] [Apply]` — **disabled by default**, cuma aktif kalau ada
  perubahan nyata di field API key (dilacak lewat `QLineEdit.textEdited`,
  BUKAN `textChanged` — supaya klik "Show" yang mengisi field secara
  programatik tidak ikut dianggap "dirty").
- Catatan "Some changes require restarting Arona." muncul otomatis begitu
  field API key diedit (sebelum Apply pun sudah kelihatan, sebagai
  peringatan dini).
- **Re-mask otomatis** setiap kali halaman dibuka (`showEvent`) atau
  Cancel/Apply ditekan — field API key selalu kembali ke mode Password dan
  placeholder, tidak ada nilai revealed yang "nempel" kalau user pindah
  halaman lalu balik lagi.
- Error state: kalau `save_api_key()` gagal, tampilkan pesan error di
  `settingsErrorLabel` (merah), field tetap terisi (tidak hilang), user bisa
  coba lagi.

## 3. `ui/navigation.py` — diubah

- "Settings" sekarang clickable (sebelumnya "· Coming Soon").
- **Semua 5 item sidebar sekarang fungsional** — tidak ada lagi placeholder
  "Coming Soon" di aplikasi.
- `navigate_requested` signal sekarang bisa emit `"chat"`, `"memory"`,
  `"voice"`, `"avatar"`, atau `"settings"`.

## 4. `ui/window.py` — diubah (struktural, bukan logic)

- `SettingsService()` diinstansiasi **tanpa dependency ke `Companion` atau
  manager apa pun** — murni baca `config/constants.py` + `config/settings.py`
  + file check lokal. Ini sengaja, sesuai Companion Rules (§31): Settings
  bukan `SettingsManager` yang menjangkau ke subsystem lain.
- `SettingsPage(self._settings_service)` ditambahkan sebagai page kelima di
  `QStackedWidget`.
- `_on_navigate()` ditambah 1 cabang untuk `"settings"`.
- Semua logic chat/voice/avatar/memory existing **tidak diubah**.

## 5. `ui/theme.py` — ditambah (append-only)

Blok CSS baru: `settingsPage`, `settingsPageTitle`, `settingsSectionLabel`,
`settingsFieldLabel`, `settingsFieldValue`, `settingsHintLabel` (amber
`#e0b054`, sama seperti hint di Avatar page), `settingsErrorLabel` (merah
`#e88a8a`, sama seperti error di Voice page), `settingsSecondaryButton`
(gaya outline untuk tombol Cancel/Show, beda dari tombol primer biru).

# Deviasi dari mockup (disengaja, didokumentasikan)

Semua deviasi di bawah adalah **konsekuensi langsung dari inspeksi source**,
bukan keputusan sepihak:

1. **Cuma 1 field editable dari seluruh halaman (API Key)** — semua field
   lain di mockup (Model, TTS Model, Theme dropdown, dst) ditampilkan Read
   Only karena memang tidak ada mekanisme edit/persist yang nyata.
2. **Kategori Developer dihapus total** — `DEVELOPER_MODE` tidak ada di
   source sama sekali.
3. **Tidak ada field Temperature/top_p/max_tokens** — tidak dipakai di
   kontrak `GeminiClient` aktual project ini.
4. **Theme ditampilkan sebagai Read Only dengan catatan**, bukan dropdown —
   cuma ada satu tema yang benar-benar ada.
5. **Avatar section tidak ada tombol Connect/Disconnect apa pun** — sesuai
   larangan eksplisit di spec §15, konsisten dengan temuan v1.3.

# Known limitation (bukan bug, konsekuensi dari desain yang disengaja)

- Kalau Teacher mengubah field API Key lalu pindah halaman **tanpa** klik
  Apply/Cancel, perubahan itu hilang begitu saja (tidak ada dialog konfirmasi
  "unsaved changes, yakin pindah?"). Ini keputusan sadar untuk menjaga scope
  minimal — field ini satu-satunya yang editable dan bukan operasi
  destruktif, jadi risiko rendah. Kalau user ingin proteksi navigasi ini
  ditambahkan nanti, itu perubahan kecil tapi butuh `MainWindow` tahu status
  "dirty" dari `SettingsPage` sebelum mengizinkan `_on_navigate()` pindah
  halaman — belum diimplementasikan.
- Setelah Apply berhasil, API key baru **tidak langsung aktif** — restart
  aplikasi tetap wajib (dikomunikasikan lewat `settingsHintLabel`), karena
  `GeminiClient`/`VoiceManager`/dst sudah di-construct sekali di startup.

# Instruksi untuk sesi Claude berikutnya

1. v1.4 Settings GUI **selesai dan terverifikasi jalan**. Ini adalah
   **halaman terakhir yang direncanakan** dari roadmap v1.1-v1.4 (Memory,
   Voice, Avatar, Settings). Semua sidebar item sekarang fungsional.
2. **Kalau user minta field baru jadi editable di Settings** (mis. Model,
   TTS Voice, Temperature): itu BUKAN pekerjaan GUI kecil. Field itu tidak
   punya persistence/setter mechanism sama sekali di backend saat ini.
   Menambahkannya butuh perubahan ke subsystem yang dibekukan (`GeminiClient`,
   `VoiceManager`, dst) — **wajib didiskusikan eksplisit dengan user sebelum
   eksekusi**, bukan diasumsikan sebagai kelanjutan alami dari v1.4.
3. **Kalau user minta Developer Mode/toggle**: `DEVELOPER_MODE` masih belum
   ada spec-nya. Jangan bikin constant sembarangan — tanya dulu apa
   sebenarnya yang ingin di-toggle dan bagaimana efeknya ke Developer Tools
   yang sudah ada (`developer/developer.py`), baru desain kontraknya.
4. **JANGAN PERNAH** menampilkan `GEMINI_API_KEY` (atau secret lain) secara
   default di UI manapun, memasukkannya ke log, ke Developer Snapshot
   (`export_json()`/`export_markdown()`), atau ke exception message. Pola
   yang sudah benar: `SettingsSnapshot` cuma bawa boolean
   `api_key_configured`, nilai asli cuma keluar lewat `reveal_api_key()`
   yang dipanggil eksplisit oleh aksi user.
5. **JANGAN PERNAH** menulis ke `.env` dari tempat lain selain
   `SettingsService.save_api_key()` — kalau ada kebutuhan menulis config
   lain ke `.env` di masa depan, reuse pola yang sama (`find_dotenv()` +
   `set_key()`), jangan bikin mekanisme file-writing baru.
6. Arsitektur v1.0 (Architecture Freeze Policy) **masih berlaku** untuk
   semua subsystem di luar GUI. `Companion` tetap satu-satunya orchestrator.
   `SettingsService` sengaja tidak punya referensi ke `Companion` — kalau ada
   kebutuhan Settings memengaruhi Companion di masa depan, itu perubahan
   arsitektur, bukan ekstensi kecil.
7. Pola yang established sepanjang v1.1-v1.4: boundary tipis non-Qt kalau
   memang perlu, reuse manager/worker instance yang sama lewat constructor
   injection, `QStackedWidget` untuk page switching, append-only ke
   `theme.py`, **klasifikasikan tiap konfigurasi (Runtime Editable/Startup
   Editable/Read Only/Secret/Unsupported) berdasarkan source aktual sebelum
   membuatnya editable** — jangan pernah mengarang field/default/mekanisme
   restart.
8. User komunikasi Bahasa Indonesia, kode/komentar teknis boleh Inggris.
