## 1. Apa Project Ini

AI Waifu Companion desktop app, terinspirasi Arona (Blue Archive). Dirancang modular: voice, avatar Live2D, memory, emosi, vision, routine, initiative, developer tools.

**Prinsip pengembangan:** incremental, per-milestone, jangan lompat fitur, jangan overengineering, jangan redesign arsitektur tanpa alasan kuat.

**Status besar:** Phase 1 (Foundation) ✅, Phase 2 (Behavior) ✅, Phase 3 (Intelligence) ✅ — semua TUNTAS. **Phase 4 (Release) — v1.0 SEDANG BERLANGSUNG: Release Engineering Audit.**

**v1.0 Release Philosophy (WAJIB dipahami sebelum lanjut apa pun):** v1.0 **BUKAN** milestone fitur. Tidak ada subsystem baru, tidak ada redesign arsitektur, tidak ada "Behavior v2"/"Memory v2"/dst. **Architecture Freeze Policy** — subsystem berikut BEKU, cuma bug fix yang diperbolehkan: `Companion`, `GeminiClient`, `PromptBuilder`, `ContextBuilder`, `Conversation`, Behavior Engine (semua subsystem), Vision, Routine, Initiative, Memory, Voice, Avatar, Developer Tools, GUI, seluruh Public API, struktur folder, tanggung jawab tiap subsystem. **Prinsip pasca-v1.0 (dari GPT, harus dipertahankan selamanya):** *"Jika sebuah fitur baru mengharuskan merombak Companion atau mengubah tanggung jawab subsystem yang sudah ada, maka desain fitur tersebut perlu ditinjau ulang terlebih dahulu."*

**Dokumen pendukung v1.0 (sudah dibuat, ada di `/mnt/user-data/outputs/` riwayat sesi sebelumnya, user simpan lokal):**
- `CODE_STYLE.md` — standar penamaan, type hints, logging, exception, constants, import, dataclass immutability.
- `V1.0_AUDIT_CHECKLIST.md` — breakdown actionable tiap kategori audit spec.

## 3. Perubahan Kode Hasil Audit (✅ SUDAH DIEKSEKUSI)

### Bug Fix Kritis
1. **`avatar/avatar_manager.py` — `animation_state` kehilangan `@property`.** Tanpa ini, `developer/avatar_debug.py` (`avatar_manager.animation_state.active_layers`) selalu `AttributeError` diam-diam (dibungkus try/except) tiap `DeveloperService.get_avatar()` dipanggil dari GUI sungguhan (`avatar_manager` selalu ada, bukan `None`, di `ui/window.py`). **Dikonfirmasi user sudah di-fix.**
2. **`config/logger.py` — API key bocor ke `logs/app.log` lewat `diagnose=True` (default loguru).** Traceback exception dari objek `google-genai` (`HttpRequest`/`Client`) mencetak header `x-goog-api-key` mentah. **Terbukti nyata** — ketemu langsung di traceback yang pernah di-paste user waktu debug bug TTS. Fix: `logger.add(..., diagnose=False)`. Traceback tetap lengkap (module/line/exception), cuma local variable disuppress.
3. **`main_gui.py` — orphan `Routine` instance.** `routine = Routine(memory_manager=None)` dibuat tapi tidak pernah dipakai (Companion sudah bikin `Routine`-nya sendiri secara internal sejak v0.8). Dihapus beserta import yang jadi tidak terpakai.

### Concurrency & Thread Safety
4. **`avatar/vtube.py` — `_send_request()` race condition.** `requestID` di-generate tapi tidak dicocokkan dengan response; 3 sumber pemanggil konkuren (IdleScheduler breathing/blink, LipSyncCoordinator, AvatarManager.react_to_reply) bisa saling interleave `send()`/`recv()` di event loop yang sama. Fix: `self._send_lock = asyncio.Lock()`, bungkus body `_send_request()` dengan `async with self._send_lock:`.
5. **`speech/recorder.py` — `_frames` tanpa lock.** Ditulis dari audio callback thread (`sounddevice`), dibaca/direset dari GUI/worker thread. Fix: `threading.Lock()`, critical section seminimal mungkin (cuma swap referensi list, `np.concatenate()` di luar lock).

### Konsistensi Lintas-Domain
6. **Suppression keyword list divergen** antara `routine_rules.py` dan `initiative_rules.py` (beda kata kunci "meeting"/"coding"). Konsolidasi ke `vision/vision_signals.py` (BARU, pure function `matches_presentation()`/`matches_focused_work()`, cuma baca `VisionContext`, tidak tahu Routine/Initiative — aman terhadap dependency order). **Efek samping behavior nyata**: Initiative sekarang ikut suppressed kalau Teacher nulis email/mengetik umum; Routine ikut suppress kalau Vision deteksi "debugging"/"presentation".
7. **Duplicate persistence boilerplate** (upsert `search_memory`→`update_memory`/`save_memory`, pola identik 4x) di `RelationshipCoordinator`, `InternalStateCoordinator`, `RoutineHistory`, `InitiativeHistory`. Konsolidasi ke `database/persistence_helper.py` (BARU — `save_by_marker()`/`load_by_marker()`, generik, tidak melanggar Independence Policy karena semua domain sudah boleh import `database.memory_manager`).
8. **Naming collision**: `behavior/initiative.py` (define `InitiativeState`) vs `initiative/initiative.py` (define `Initiative`, konsep beda total). Rename `behavior/initiative.py` → `behavior/initiative_state.py` (konsisten pola `emotion_state.py`/`relationship_state.py`). Import di `internal_state.py` diupdate. *(Catatan: sempat ada bug regresi kecil saat rename — import balik salah tertulis, sudah dikonfirmasi diperbaiki.)*
9. **`vision/image_analyzer.py`** — ditambah `VisionAnalysisError` (domain exception sendiri, konsisten `GeminiResponseError`/`CompanionError`), `contents` dirapikan jadi `types.Content(role="user", parts=[...])` konsisten dengan `gemini.py`/`memory_extractor.py`.

### Type Hints & Docstring
10. `Initiative.evaluate()` — dari `*args/**kwargs` generik jadi signature eksplisit sama persis `update()`.
11. Docstring baru/diupdate: `Conversation`, `ContextBuilder` (sinkron sampai v0.9 Initiative), `IdleCoordinator`, `ChatWorker`/`VoiceWorker`/`SpeakWorker`/`AvatarWorker` (semua ikut pola "TIDAK PERNAH X").

### Logic Gap
12. **`developer/developer.py` — `get_health()` diperbaiki.** Sebelumnya beberapa field placeholder (`vision` selalu `True`, `routine`/`initiative` cuma cek `Companion is not None`, `avatar` cuma cek object ada bukan `connection_state`). Sekarang `avatar` cek `connection_state == AvatarState.READY.value`, `routine`/`initiative` pakai hasil snapshot build (berhasil = sehat). `gemini` field didokumentasikan eksplisit sebagai **proxy** (`behavior_ok`), bukan live probe (Developer Tools dilarang kirim request Gemini sungguhan).

### Security Hardening
13. **`config/settings.py`** — `GEMINI_API_KEY` sekarang divalidasi saat import, `raise RuntimeError` dengan pesan jelas kalau `.env` hilang/kosong (fail-fast, bukan error generik SDK yang membingungkan di titik jauh lebih dalam).

## 4. Item yang BELUM Dieksekusi — Perlu Keputusan/Belum Diminta

**Direkomendasikan, solusi sudah didesain lengkap (siap tempel kalau user minta lanjut):**
- Konsolidasi 3 ring buffer identik (`EmotionHistory`/`RelationshipHistory`/`InternalStateHistory`) jadi 1 `behavior/_ring_buffer.py` generic (`RingBufferHistory[T]`) + subclass 3 baris masing-masing. Kode lengkap sudah ada di `AUDIT_CHANGELOG_behavior.md`.
- Duplicate `_matches_any()` di `emotion_analyzer.py` & `relationship_analyzer.py` — belum ditentukan taruh di file shared mana.
- Type hint `InternalStateCoordinator.manual_override(self, component: str, value)` — `value` tanpa hint, fix: `value: str | int`.
- Comment penjelas untuk `RelationshipState.manual_override: bool` (dead/write-only field, disiapkan untuk GUI Developer Panel masa depan).
- `from __future__ import annotations` hilang di beberapa file "pinggiran" (`conversation.py`, `personality.py`, `prompt_builder.py`, `constants.py`, `logger.py`).
- Docstring hilang: `GeminiClient`, `CommandResult`.
- Type hint generik/hilang di `companion.py`: `get_last_routine_event() -> Optional[object]` (harusnya `Optional[RoutineEvent]`), `get_last_initiative_result()` (tanpa return type), `get_history() -> list`, `get_pending_routine_events() -> list`.
- Magic number `limit=10` (jumlah memori inject) → `config/constants.py` sebagai `MEMORY_INJECT_LIMIT`.
- Log message stale `"Behavior Injected"` di `_build_contents()` → rename `"Context Assembled"` (method itu sekarang inject Vision/Routine/Initiative juga, bukan cuma Behavior).
- Import grouping `routine.*`/`initiative.*` di `companion.py`/`context_builder.py`.
- Urutan private method `ContextBuilder` tidak match urutan pemanggilan di `build()`.

**Perlu keputusan desain user dulu (BUKAN otomatis dieksekusi):**
- `database/database.py` (file kosong total, 0 baris) — opsi (a) hapus [direkomendasikan, karena "reserved for future DB abstraction" melanggar Architecture Freeze kalau tidak eksplisit diminta], atau (b) kasih docstring placeholder kalau memang ada niat spesifik. **Belum diputuskan.**
- `personality.py` tanpa error handling — kalau `prompts/*.txt` hilang, `FileNotFoundError` mentah saat startup. Opsi (a) fail-fast dengan exception custom, atau (b) skip file yang hilang dan lanjut (risiko: system prompt diam-diam tidak lengkap). **Belum diputuskan.**
- `vtube_token.json` berisi token asli — perlu verifikasi masuk `.gitignore` bersama `memory.db`+`.env`. **Belum diverifikasi** (user belum upload `.gitignore`).
- `.env.example` belum ada — item Packaging Policy, bisa dibuat kapan saja (isi cuma `GEMINI_API_KEY=your_gemini_api_key_here`).
- `DEVELOPER_MODE` constant — **sengaja belum ditambahkan**, definisi persis apa yang di-toggle butuh spec desain dulu (bukan diasumsikan dari 1 constant, hindari kasus serupa `EventPriority.CRITICAL` yang jadi setengah-jadi).
- `VISION_MODEL_NAME` sama persis `MODEL_NAME` — **sengaja TIDAK digabung** (opsi masa depan pakai model vision berbeda), tinggal tambah komentar penjelas kalau user mau.

**Observasi murni, TIDAK PERLU dieksekusi (byproduct desain yang valid):**
- `EventPriority.CRITICAL` didefinisikan tapi belum ada event yang pakai — infrastruktur siap, belum ada pemakainya, bukan dead code yang perlu dihapus.
- `expression.py` (avatar) tidak ikut pola `_state.py` — sengaja dibiarkan, beda kasus dari `initiative.py` (rename di sana punya alasan struktural kuat: naming collision antar folder; di sini cuma kosmetik, risiko rename > manfaat).
- Lazy `import mss` di `screen_capture.py` — sudah dikasih komentar penjelas niatnya, bukan oversight.

## 10. Roadmap Selanjutnya
