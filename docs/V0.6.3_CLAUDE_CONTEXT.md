## 1. Apa Project Ini

AI Waifu Companion desktop app, terinspirasi Arona (Blue Archive). Bukan sekadar chatbot — dirancang modular supaya bisa berkembang jadi companion dengan voice, avatar Live2D, memory, emosi, dll.

**Prinsip pengembangan:** incremental, per-milestone, jangan lompat fitur, jangan overengineering, jangan redesign arsitektur tanpa alasan kuat.

**Filosofi inti:** Desktop GUI **bukan** aplikasinya. Aplikasi sesungguhnya adalah `Companion`. GUI, Voice, Avatar (+animasinya), dan Behavior Engine hanyalah layer di sekitar `Companion`:

```
Teacher
  ↓
Conversation
  ↓
Emotion Analyzer → Emotion Transition ─┐
Relationship Analyzer → Relationship Transition ─┴→ Behavior Engine → BehaviorState (skeleton, BELUM terhubung ke Companion)
  ↓ (rencana v0.6.5)
Companion (+ Memory + waktu + nanti BehaviorState) → Gemini → reply (str)
  ↓
GUI chat bubble │ TTS → AudioPlayer + Lip Sync │ HaloMapper → Hotkey ekspresi │ Idle Animation
```

**Human-in-the-Loop Memory Policy (v0.3):** Memory milik Teacher. **Avatar Independence Policy (v0.5):** avatar cuma me-render reaksi visual, opsional. **Animation Independence Policy (v0.5.1/v0.6.1):** layer animasi independen digabung `AvatarManager`. **Behavior Engine Policy (v0.6.0):** Behavior Engine cuma menghasilkan state, tidak pernah bahasa/kontrol langsung. **Emotion Transition Policy (v0.6.2):** emosi = state machine yang bergerak (decay + transition), bukan nilai statis. **Relationship Base/Current Policy (v0.6.3, BARU, rekomendasi GPT):** tiap dimensi relationship (Trust/Comfort/Affection/Respect/Familiarity) punya **2 nilai terpisah** — `base` (anchor point manual, diatur lewat override/preset — belum ada GUI-nya) dan `current` (nilai aktual yang dipakai Behavior Engine, bergerak naik/turun lewat interaksi otomatis). Manual override cuma reset `base` dan `current` ke titik baru, **tidak pernah mematikan** pertumbuhan otomatis setelahnya. Model ini memungkinkan preset karakter ("baru kenal", "teman dekat") dan reset-tanpa-kehilangan-arsitektur di masa depan.

## 4. Arsitektur (WAJIB Dipertahankan)

```
Terminal (main.py)     Desktop GUI (main_gui.py + ui/window.py)
        │                              │
        └──────────────┬───────────────┘
                        ↓
                   Companion (ai/companion.py)   ← BELUM terhubung ke BehaviorEngine
                        ↓
     ┌──────────────────┼──────────────────┐
     ↓                  ↓                  ↓
Conversation       MemoryManager       GeminiClient
                        ↓
                     memory.db  ← JUGA nyimpen Relationship state (kategori "general" + marker)

Voice/Avatar/Lip Sync/Idle Animation: TIDAK BERUBAH sejak v0.6.1.
Emotion System: TIDAK BERUBAH sejak v0.6.2.

Relationship System (BARU v0.6.3, terisolasi dari Companion/GUI, sudah terhubung ke BehaviorEngine):

RelationshipCoordinator(memory_manager=None, auto_load=True)   [behavior/relationship.py]
    ↓ __init__: load() otomatis kalau memory_manager ada — restore dari memory.db
    ↓ .process_message(user_input, emotion_state)
   1. decay(current_state)                          [relationship_rules.py — HANYA familiarity meluruh, dimensi lain TIDAK]
        ↓
   2. RelationshipAnalyzer.analyze(user_input, emotion_state) -> RelationshipTransitionProposal
        [relationship_analyzer.py — keyword/regex + baca EmotionState Arona, BUKAN Gemini]
        ↓
   3. apply_transition(decayed_state, proposal) -> RelationshipState BARU
        [relationship_rules.py — tiap delta di-clamp ±5 (Growth Policy: no sudden jumps)]
        ↓
   RelationshipHistory.record(old_state)              [in-memory]
        ↓
   save() -> upsert ke MemoryManager                   [persistence]
        ↓
   .current -> RelationshipState (immutable, snapshot terakhir)

   .manual_override(dimension, value) -> set base=current=value, growth OTOMATIS TETAP LANJUT setelahnya
   .reset() / .get_history(limit)

BehaviorEngine.update(user_input, reply):
    emotion_state = EmotionCoordinator.process_message(user_input)
    relationship_state = RelationshipCoordinator.process_message(user_input, emotion_state=emotion_state)
    → BehaviorState baru dengan emotion+relationship terisi, sisanya masih TODO placeholder

BehaviorEngine MASIH BELUM dipanggil dari Companion/ui manapun — terisolasi sampai v0.6.5.
```

**Aturan besi (v0.1–v0.6.2, tetap berlaku penuh):** `Companion`/`VoiceManager`/`AvatarManager` masing-masing satu-satunya koordinator domainnya. UI Independence. Conversation vs Memory tidak dicampur. Layer animasi tidak boleh bicara `VTubeStudioClient` langsung. Emotion Arona ≠ Emotion Teacher. `EmotionAnalyzer` tidak boleh panggil Gemini.

**Aturan besi BARU v0.6.3 — Relationship System:**
- **Setiap dimensi relationship punya `base` DAN `current` terpisah** (`DimensionValue`) — `current` yang dipakai Behavior Engine dan bergerak lewat interaksi (`adjust()`), `base` cuma berubah lewat `override()` (manual). Pola ini WAJIB dipertahankan kalau ada dimensi baru ditambah di masa depan.
- **Manual override TIDAK PERNAH mematikan automatic growth** — `manual_override()` cuma reset anchor point (`base=current=value`), `process_message()` berikutnya tetap jalan normal dan terus menggeser `current`.
- **Growth SELALU gradual** — `apply_transition()` clamp tiap delta ke `±_MAX_STEP=5` (Growth Policy spec: "no sudden jumps", 5 = maksimum & sangat jarang; delta harian biasa cuma ±1/±2).
- **Cuma `familiarity` yang meluruh otomatis** (kalau Teacher menghilang berhari-hari, ada grace period 3 hari dulu) — Trust/Comfort/Affection/Respect **TIDAK** meluruh otomatis karena hubungan yang sudah terbentuk tidak boleh hilang cuma karena waktu (beda filosofi dengan Emotion yang memang jangka pendek).
- **`RelationshipAnalyzer`/`RelationshipCoordinator` TIDAK PERNAH memanggil Gemini, TIDAK PERNAH akses SQLite langsung** — persistence HARUS lewat method publik `MemoryManager` yang sudah ada (`search_memory`/`save_memory`/`update_memory`), TIDAK menambah kategori/tabel baru ke `MemoryManager` itu sendiri.
- **`RelationshipAnalyzer` boleh membaca `EmotionState`** (Emotion Integration di spec: emosi Arona ikut memengaruhi arah relationship, mis. Arona merasa senang → trust naik sedikit) — tapi Emotion System sendiri tidak diubah untuk ini, cuma di-pass sebagai parameter.
- **Relationship System TIDAK PERNAH bicara ke Avatar/Voice/GUI langsung** — pengaruh ke sistem lain (nanti) HARUS lewat `BehaviorState` → `Companion`, bukan panggilan langsung dari `behavior/relationship*.py`.
- **GUI Relationship Inspector (slider, preset save/load, reset button, dll) SENGAJA belum dibuat** — spec eksplisit "Current milestone implements backend only, No GUI implementation". Backend-nya (`manual_override()`, `save()`, `load()`, `reset()`, `get_history()`) sudah siap dipakai kapan pun GUI-nya dikerjakan.

### `behavior/relationship_state.py` — `DimensionValue` + `RelationshipState` (BARU v0.6.3)
```python
@dataclass(frozen=True)
class DimensionValue:
    base: int = 0      # anchor point manual
    current: int = 0   # nilai aktual dipakai Behavior Engine
    adjust(delta: float) -> DimensionValue    # geser CURRENT saja, clamp 0-100, base tetap
    override(value: int) -> DimensionValue     # reset base DAN current ke value sama, clamp 0-100

@dataclass(frozen=True)
class RelationshipState:
    trust: DimensionValue
    comfort: DimensionValue
    affection: DimensionValue
    respect: DimensionValue
    familiarity: DimensionValue
    timestamp: datetime
    manual_override: bool = False

    elapsed_seconds() -> float
    get_dimension(name: str) -> DimensionValue
    with_dimension(name: str, value: DimensionValue, manual_override: bool=False) -> RelationshipState

DEFAULT_RELATIONSHIP_STATE = RelationshipState()
DIMENSION_NAMES = ("trust", "comfort", "affection", "respect", "familiarity")
```

## 9. Keputusan Desain Kumulatif (Tambahan v0.6.3)

- **Base/Current split di level `DimensionValue`** (bukan di `RelationshipState` langsung) — supaya tiap dimensi independen sepenuhnya, dan logic clamp/validasi (0-100) cuma perlu ditulis sekali di satu tempat kecil yang reusable.
- **Persistence pakai kategori `"general"` + marker teks unik di `MemoryManager`, bukan tabel baru** — solusi konkret untuk requirement yang tampak kontradiktif ("must persist via MemoryManager" vs "WITHOUT modifying MemoryManager"). Row tunggal di-upsert (search dulu, update/save sesuai kondisi) supaya tidak numpuk record baru tiap `process_message()`.
- **Hanya `familiarity` yang meluruh otomatis, dimensi lain tidak** — keputusan filosofis eksplisit: Trust/Comfort/Affection/Respect yang sudah terbentuk itu "berat", tidak boleh hilang cuma karena Teacher lagi sibuk beberapa hari; familiarity ("seberapa kenal") lebih wajar meluruh kalau lama tidak berinteraksi.
- **`RelationshipAnalyzer` menerima `EmotionState` sebagai parameter opsional** (bukan meng-import `EmotionCoordinator`) — dependency satu arah yang jelas (Relationship boleh tahu Emotion, Emotion tidak perlu tahu Relationship), konsisten dengan urutan pemanggilan di `BehaviorEngine.update()`.
- **Manual override sengaja TIDAK punya flag "lock" yang mematikan growth** — walau GUI belum ada, kontraknya (`manual_override()`) sudah didesain sesuai spec eksplisit "Manual editing does NOT disable the Relationship System", supaya kalau nanti GUI ditambah, behavior-nya sudah pasti benar tanpa perlu redesign backend.
- **`RelationshipHistory` dan `EmotionHistory` sengaja punya struktur identik** (in-memory ring buffer, `record()`/`recent()`/`clear()`) — konsistensi pola antar subsystem Behavior Engine, memudahkan kalau nanti (v0.6.4 Mood) butuh baca riwayat dari keduanya dengan API yang familiar.
