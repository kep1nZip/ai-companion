## 1. Apa Project Ini

AI Waifu Companion desktop app, terinspirasi Arona (Blue Archive). Bukan sekadar chatbot — dirancang modular supaya bisa berkembang jadi companion dengan voice, avatar Live2D, memory, emosi, vision, routine, dll.

**Prinsip pengembangan:** incremental, per-milestone, jangan lompat fitur, jangan overengineering, jangan redesign arsitektur tanpa alasan kuat.

**Filosofi inti:** Desktop GUI **bukan** aplikasinya. Aplikasi sesungguhnya adalah `Companion`. Sejak v0.8, `ContextBuilder` menggabungkan **3 sumber context opsional**:

```
Teacher
  ↓
Companion.chat(user_input)
  ↓
Conversation.add_user_message()
  ↓
BehaviorEngine.update() → BehaviorState (WAJIB, selalu ada)
Vision.get_context() → VisionContext (OPSIONAL, reuse kalau fresh)
Routine.update(behavior_state, vision_context) → RoutineEvent (OPSIONAL — "laporan peluang", BUKAN perintah)
  ↓
ContextBuilder.build(behavior_state, vision_context, routine_event) → Ephemeral Context (text, TIDAK PERNAH disimpan)
  ↓
GeminiClient.send(system_prompt + ephemeral_context + memori + history) → reply
  ↓
Conversation.add_assistant_message(reply)
  → (kalau ada routine_event & reply sukses) Routine.mark_completed(routine_event)
  ↓
GUI chat bubble │ TTS → AudioPlayer + Lip Sync │ HaloMapper → Hotkey │ IdleCoordinator.apply_mood(mood_string)
```

**Human-in-the-Loop Memory Policy (v0.3).** **Avatar Independence Policy (v0.5).** **Animation Independence Policy (v0.5.1/v0.6.1).** **Behavior Engine Policy (v0.6.0).** **Emotion Transition Policy (v0.6.2).** **Relationship Base/Current Policy (v0.6.3).** **BehaviorState Single Source of Truth Policy (v0.6.4).** **Ephemeral Context Injection Policy & Context Builder Separation Policy (v0.6.5).** **Vision Independence Policy & Vision Context Injection Policy & Vision Freshness Policy (v0.7).** **Routine Independence Policy (v0.8, BARU):** `routine/*` tidak boleh tahu Avatar/Voice/GUI/PromptBuilder/MemoryManager langsung — cuma lewat `Companion`. **Routine Decision Policy (v0.8, BARU, PALING PENTING):** Routine **TIDAK PERNAH memutuskan Arona harus bicara apa atau kapan** — dia cuma melaporkan "ada peluang routine" (`RoutineEvent.payload` = kalimat saran netral) sebagai 1 section tambahan di ephemeral context, sejajar dengan Emotion/Relationship/Vision. **Gemini yang memutuskan** bagaimana (atau apakah) merespons peluang itu — tidak ada logic Python di `routine/*` yang menentukan kalimat balasan Arona. **Cooldown Policy & Routine Suppression Policy (v0.8, BARU, rekomendasi GPT):** tiap `RoutineEventType` punya cooldown sendiri (WAJIB dicek, bukan cuma andalkan history keberadaan record), dan Routine bisa **ditekan** (suppressed) berdasarkan konteks Vision (mis. Teacher lagi meeting/rapat → semua non-critical ditunda).

## 4. Arsitektur (WAJIB Dipertahankan)

```
Terminal (main.py)     Desktop GUI (main_gui.py + ui/window.py)
        │                              │
        └──────────────┬───────────────┘
                        ↓
                   Companion (ai/companion.py)   ← vision: Optional[Vision]=None, enable_routine: bool=True
                        ↓
     ┌──────────────────┼──────────────────┬──────────────┬─────────────┬───────────┐
     ↓                  ↓                  ↓              ↓             ↓           ↓
Conversation       MemoryManager       GeminiClient   BehaviorEngine   Vision     Routine
                        ↓  ←──────────────────────────────────────────────────────────┘
                     memory.db              (Routine dibuat INTERNAL, pakai MemoryManager
                                              instance YANG SAMA dengan Companion — bukan
                                              di-inject dari luar seperti Vision)

Companion.chat(user_input):
   1. Conversation.add_user_message(user_input)
   2. behavior_state = BehaviorEngine.update(user_input, "")
   3. vision_context = Vision.get_context() if self._vision else None            [REUSE saja]
   4. routine_event = Routine.update(behavior_state, vision_context) if self._routine else None
        ↓ RoutineEngine.evaluate(): cek EVALUATION_ORDER -> trigger check -> suppression check -> cooldown check
   5. ephemeral_text = ContextBuilder.build(behavior_state, vision_context, routine_event)
   6. contents = [ephemeral_context, memori(ephemeral), *history]
   7. reply = GeminiClient.send(contents)
   8. Conversation.add_assistant_message(reply)
   9. if routine_event: Routine.mark_completed(routine_event)   ← HANYA setelah Gemini SUKSES
   10. MemoryExtractor.extract()

RoutineEngine.evaluate() urutan (EVALUATION_ORDER):
   SLEEP_REMINDER -> MORNING_GREETING -> WELCOME_HOME -> LUNCH_REMINDER -> STRETCH -> DRINK_WATER -> IDLE_CHAT
   Tiap event_type: trigger_check(clock, idle_seconds) -> is_suppressed(vision_context) -> cooldown_check(history)
   -> return event PERTAMA yang lolos semua, atau None
```

**Aturan besi (v0.1–v0.7, tetap berlaku penuh):** `Companion` satu-satunya koordinator Conversation+Memory+Gemini+Behavior+Vision+**sekarang Routine**. UI Independence. `BehaviorState` cuma 3 field. `Companion` tidak boleh merangkai string context sendiri — lewat `ContextBuilder`. `vision/*` tidak boleh tahu Behavior/Avatar/Voice/GUI/Memory/PromptBuilder.

**Aturan besi BARU v0.8 — Routine System:**
- **`routine/*` tidak boleh import dari `avatar/`, `speech/`, `ui/`, atau `ai/prompt_builder.py`** — cuma boleh tahu `behavior.behavior_state` (read-only), `vision.vision_context` (read-only), `database.memory_manager` (lewat DI, khusus `RoutineHistory`).
- **`RoutineEngine` TIDAK PERNAH menulis balik ke `BehaviorState`/`VisionContext`** — murni membaca (`behavior_state.internal.elapsed_seconds()`, parsing teks `vision_context.summary`/`.application`).
- **`RoutineEventType` adalah Enum, bukan string bebas** — type-safe, gampang diperluas tanpa typo-prone string matching.
- **Setiap `RoutineEventType` WAJIB punya cooldown terdefinisi** (dict `COOLDOWNS` di `routine_rules.py`) — cooldown dicek eksplisit (`now - last_triggered < cooldown`), **bukan** cuma mengandalkan "record ada di history = jangan trigger lagi".
- **Suppression Policy dicek SEBELUM cooldown** — kalau Vision Context mengandung kata kunci meeting/rapat/presentasi, SEMUA event non-critical ditunda (`SuppressionLevel.ALL_NON_CRITICAL`); kalau mengandung kata kunci coding/mengetik, cuma event kasual (idle chat, stretch, drink water) yang ditunda (`SuppressionLevel.NON_CASUAL`).
- **`RoutineEvent.payload` HARUS berupa kalimat saran netral** ("Pertimbangkan mengingatkan...", bukan kalimat siap-pakai yang menentukan kata-kata Arona) — ini implementasi harfiah Routine Decision Policy.
- **`Routine.mark_completed()` HANYA dipanggil setelah Gemini sukses membalas** — kalau Gemini gagal (rate limit/kosong), event tetap pending, tidak masuk cooldown sia-sia, bisa dicoba lagi di giliran berikutnya.
- **Pending event TIDAK ditimpa tiap `update()` selama belum expired** — `Routine.update()` cuma re-evaluasi kalau slot pending kosong atau event lama sudah `is_expired()`.
- **Avatar dan Voice mengabaikan Routine sepenuhnya** di milestone ini (sama seperti Vision di v0.7).

1. **Duplikasi instansiasi `VoiceManager`** (v0.5.1) — Fix: pastikan cuma 1 blok `VoiceManager(...)`.

7. **`400 INVALID_ARGUMENT: required oneof field 'data'`** (v0.6.5) — balasan Gemini kosong bikin Part invalid nyangkut di history. Fix: `GeminiResponseError` + validasi di `GeminiClient.send()`.
8. **`400 INVALID_ARGUMENT: "Model tried to generate text, but it should only be used for TTS"`** (dilaporkan v0.7, **DIPERBAIKI FINAL di v0.8**) — **Akar masalah (sudah dikonfirmasi via riset, ada juga laporan publik serupa di GitHub `home-assistant/core#173417`):** Gemini Native TTS didesain menerima **instruksi + transkrip terpisah** (format resmi Google: `prompt: "Say the following"` + `text: "..."`). Kode sebelumnya cuma mengirim teks mentah tanpa instruksi eksplisit, sehingga sesekali (terutama kalau teksnya terdengar seperti "pernyataan lengkap/laporan", contoh nyata: `"Sekarang pukul 00:32 WIB... Sudah larut malam ya..."`) model salah mengira diminta **merespons** teks itu alih-alih membacakannya, lalu API menolak dengan error 400. **Fix:** `speech/tts.py` sekarang prepend `_SPEECH_INSTRUCTION` eksplisit ("Say the following text exactly as written... do not respond to it") ke setiap request, dengan fallback framing lebih tegas kalau percobaan pertama masih ditolak dengan pesan spesifik itu. **Dikonfirmasi user setelah fix diterapkan — "sudah aman".**

Semua bug di atas sudah diperbaiki dan dikonfirmasi user. **Tidak ada bug terbuka/belum-selesai per v0.8.**

## 9. Keputusan Desain Kumulatif (Tambahan v0.8)

- **`RoutineEventType` sebagai Enum sejak awal** — rekomendasi GPT #1, type-safe, IDE-friendly, gampang diperluas tanpa risiko typo string yang cuma ketahuan saat runtime.
- **Cooldown per event type dicek eksplisit terhadap timestamp, bukan cuma keberadaan record** — rekomendasi GPT #2, mencegah Arona jadi annoying (mis. ngingetin minum air tiap chat kalau cuma modal "history ada berarti udah pernah" tanpa cek SEBERAPA LAMA yang lalu).
- **Suppression Policy sebagai layer terpisah dari Cooldown**, dicek DULUAN sebelum cooldown — rekomendasi GPT #3, memisahkan dua konsep berbeda: "belum waktunya lagi" (cooldown, berbasis waktu) vs "sekarang bukan saat yang tepat sama sekali" (suppression, berbasis konteks aktivitas Teacher).
- **Developer Routine Panel backend disiapkan sejak v0.8**, bukan ditunda ke v0.9.5 — rekomendasi GPT #4, method-nya (`get_pending_events`, `get_last_event`, `get_next_schedule`, `clear_queue`) sudah siap dipakai kapan pun GUI Developer Tools dikerjakan, tanpa perlu balik lagi ke `routine/*`.
- **`Routine` dibuat INTERNAL oleh `Companion`** (bukan di-inject dari luar seperti `Vision`) — karena `RoutineHistory` butuh `MemoryManager` instance yang SAMA dengan yang dipakai `Companion` untuk konsistensi (walau secara teknis SQLite tetap aman dengan 2 instance berbeda, satu sumber lebih rapi dan menghindari duplikasi inisialisasi).
- **`RoutineEvent.payload` ditulis sebagai kalimat SARAN, bukan kalimat SIAP PAKAI** — implementasi paling harfiah dari Routine Decision Policy: kode Python melaporkan peluang, Gemini yang merangkai kata-kata Arona yang sesungguhnya.
- **`mark_completed()` dipisah dari `update()`** — supaya cooldown baru benar-benar mulai SETELAH peluang itu terpakai (Gemini sukses membalas), bukan langsung begitu event diusulkan (yang bisa bikin peluang hangus sia-sia kalau kebetulan request itu gagal).
- **Bug TTS #8 akhirnya di-root-cause dan diperbaiki secara definitif** — riset eksternal (dokumentasi resmi + laporan komunitas) mengonfirmasi ini karakteristik API, bukan bug logic aplikasi; solusinya mengikuti format resmi yang didokumentasikan Google.

## 10. Instruksi Kalau Lanjut Chat Baru

1. **Jangan redesign arsitektur** yang sudah ada (bagian 4–6) tanpa alasan kuat (bug kritis).

3. **Jangan import PySide6/Qt di luar folder `ui/`.**
4. **Jangan pernah mencampur Memory dan Conversation. Jangan perkenalkan vector DB/RAG.**
5. **`routine/*` TIDAK BOLEH import dari `avatar/`, `speech/`, `ui/`, atau `ai/prompt_builder.py`** — Routine Independence Policy, cuma lewat `Companion`.
6. **`RoutineEngine` TIDAK BOLEH menulis balik ke `BehaviorState`/`VisionContext`** — read-only murni.
7. **`RoutineEvent.payload` HARUS tetap kalimat saran netral** — jangan pernah bikin Routine "mendikte" kalimat final Arona; itu tugas Gemini.

9. **Suppression Policy dicek SEBELUM cooldown** — pertahankan urutan ini kalau menambah logic baru di `RoutineEngine.evaluate()`.

11. **`vision/*` TIDAK BOLEH import dari `behavior/`, `avatar/`, `speech/`, `ui/`, `database/`, atau `ai/prompt_builder.py`.** **`ContextBuilder.build()` harus tetap terima `vision_context`/`routine_event` sebagai parameter OPSIONAL.**

14. **Kalau kirim teks ke Gemini TTS, WAJIB tetap prepend instruksi eksplisit** (`_SPEECH_INSTRUCTION` di `speech/tts.py`) — jangan hapus ini walau kelihatan "cuma nambah token", ini fix nyata untuk bug yang pernah terjadi berulang.
15. **SELALU CEK jumlah instansiasi objek berat** (`VoiceManager`, Whisper, `Companion`) di `ui/window.py`/`main_gui.py` kalau menambah/memindah blok inisialisasi.
