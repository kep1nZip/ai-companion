> **Dokumen ini adalah context tunggal.** Kalau mulai chat baru dengan Claude/GPT untuk lanjutin project ini, cukup upload dokumen ini — nggak perlu jelasin ulang dari awal.

## 1. Apa Project Ini

AI Waifu Companion desktop app, terinspirasi Arona (Blue Archive). Bukan sekadar chatbot — dirancang modular supaya bisa berkembang jadi companion dengan voice, avatar Live2D, memory, emosi, dll.

**Prinsip pengembangan:** incremental, per-milestone, jangan lompat fitur, jangan overengineering, jangan redesign arsitektur tanpa alasan kuat.

**Filosofi inti:** Desktop GUI **bukan** aplikasinya. Aplikasi sesungguhnya adalah `Companion`. GUI, Voice, dan Avatar (termasuk animasinya) hanyalah presentation/reaction layer di sekitarnya:

```
Keyboard  → Text ─┐
Mic → STT → Text ─┴→ Companion (+ Memory + waktu) → Gemini → reply (str)
                                                                  │
                        ┌─────────────────────────────────────────┼───────────────┐
                        ↓                                         ↓               ↓
                  GUI chat bubble                        TTS → audio (PCM)   HaloMapper→Hotkey
                                                                  │           (ekspresi wajah)
                                                                  ↓
                                                    ┌─────────────┴─────────────┐
                                                    ↓                          ↓
                                              AudioPlayer               Lip Sync (amplitude→MouthOpen)
                                              (dengar)                  → AvatarManager → VTube Studio
```

**Human-in-the-Loop Memory Policy (v0.3):** Memory milik Teacher, arsitektur harus siap show/edit/delete/forget kapan pun. **Avatar Independence Policy (v0.5):** avatar bukan sumber kebenaran, cuma me-render reaksi visual dari `Companion`; kalau VTube Studio mati, aplikasi tetap 100% bisa dipakai. **Animation Independence Policy (v0.5.1, BARU):** sistem animasi avatar terdiri dari beberapa layer independen (Expression, Lip Sync, nanti Eye Blink/Breathing di v0.5.2) — tiap layer cuma kontrol parameternya sendiri, dan `AvatarManager` yang bertanggung jawab menggabungkan semua layer aktif sebelum kirim ke VTube Studio, supaya satu layer animasi tidak menimpa layer lain.

## 4. Arsitektur (WAJIB Dipertahankan)

```
Terminal (main.py)     Desktop GUI (main_gui.py + ui/window.py)
        │                              │
        └──────────────┬───────────────┘
                        ↓
                   Companion (ai/companion.py)
                        ↓
     ┌──────────────────┼──────────────────┐
     ↓                  ↓                  ↓
Conversation       MemoryManager       GeminiClient
                        ↓
                     memory.db

Jalur voice (ketemu lagi di Companion.chat()):
Mic → Recorder → SpeechToText → Companion.chat(text) → reply → TextToSpeech.synthesize()
                                                                        ↓ (pcm bytes, SAMA, tidak digenerate ulang)
                                    ┌───────────────────────────────────┼─────────────────────┐
                                    ↓                                                          ↓
                            AudioPlayer.play()                                    on_audio_ready(pcm, samplerate)
                            (dengar, di thread yang sama)                          → AvatarWorker.animate_lipsync()
                                                                                    → LipSyncCoordinator.animate()
                                                                                        ↓
                                                                                  AudioAnalyzer.analyze() → amplitudes
                                                                                        ↓
                                                                                  MouthMapper.map() → MouthOpen (0-1)
                                                                                        ↓
                                                                            AvatarManager.update_parameter_layer("lipsync", "MouthOpen", value)
                                                                                        ↓
                                                                            ParameterMapper.get_parameter_id() → nama param VTS
                                                                                        ↓
                                                                            VTubeStudioClient.set_parameter()

Jalur avatar (ekspresi wajah, dari v0.5, tidak berubah):
reply → HaloMapper.map() → Expression → ParameterMapper.get_hotkey() → VTubeStudioClient.trigger_hotkey()
```

**Aturan besi:**
- `Companion` satu-satunya koordinator Conversation + MemoryManager + GeminiClient.
- `VoiceManager` satu-satunya koordinator Recorder → STT → Companion → TTS → Player. **BARU v0.5.1:** punya parameter opsional `on_audio_ready: Callable[[bytes, int], None] = None` — generic hook, `VoiceManager` **tidak tahu** ini dipakai untuk lip sync atau fitur lain apa pun. Kalau tidak diisi (misal di `main.py` terminal), behavior 100% identik seperti sebelumnya.
- `AvatarManager` satu-satunya koordinator yang boleh bicara ke `VTubeStudioClient`. **Lip Sync tidak boleh panggil `VTubeStudioClient` langsung** — harus lewat `AvatarManager.update_parameter_layer()`.
- **Animation Independence Policy (BARU v0.5.1):** `AvatarManager.update_parameter_layer(layer_name, logical_parameter, value)` adalah pintu masuk generik untuk **layer animasi apa pun** (Lip Sync sekarang; nanti Eye Blink/Breathing di v0.5.2) — `AvatarManager` yang bertanggung jawab menyimpan/menggabungkan seluruh layer aktif (`self._parameter_layers` dict) sebelum dikirim ke VTS, supaya satu layer tidak menimpa layer lain.
- **2 layer mapping avatar tetap dipisah tegas**: `HaloMapper`/`expression.py` = Logical Expression (permanen, model-agnostic). `ParameterMapper` = Model Configuration (baca `vtube_model_config.json`, berubah kalau ganti model) — sekarang menangani **baik** hotkey ekspresi **maupun** nama parameter kontinu (`get_hotkey()` dan `get_parameter_id()`).
- **Audio TIDAK PERNAH digenerate dua kali** — PCM hasil `TextToSpeech.synthesize()` yang sama dipakai untuk playback (`AudioPlayer`) DAN untuk analisis lip sync (`AudioAnalyzer`).
- **Lip Sync cuma RMS amplitude sederhana** — tidak ada phoneme detection, tidak ada viseme prediction, tidak ada AI/ML.
- UI tetap tidak boleh import modul backend/speech/avatar secara langsung — semua lewat `Companion`/`VoiceManager`/`AvatarManager` beserta worker Qt masing-masing.
- **UI Independence**: PySide6/Qt tidak boleh di-import di luar `ui/` — termasuk seluruh `avatar/*` (baik yang lama maupun `audio_analyzer.py`/`mouth_mapper.py`/`lipsync.py` yang baru).
- **Conversation vs Memory tidak boleh dicampur.** **Avatar Independence Policy tetap berlaku**: kalau VTS/avatar gagal, chat & voice tetap jalan normal.
- Tidak ada vector DB/RAG, tidak ada webcam/ARKit tracking, tidak ada hardcode nama parameter/hotkey VTS di kode Python manapun (selalu lewat `ParameterMapper` + JSON).

## 9. Lip Sync System (v0.5.1) — Detail Penting

### Alur Kerja
1. `VoiceManager._speak(text)` panggil `TextToSpeech.synthesize(text)` → dapat `pcm` (bytes).
2. **Sebelum** `AudioPlayer.play(pcm, ...)` dipanggil, `on_audio_ready(pcm, samplerate)` dipanggil dulu kalau ada — ini yang terhubung ke `AvatarWorker.animate_lipsync()`.
3. `animate_lipsync()` menjadwalkan `LipSyncCoordinator.animate(pcm, samplerate)` ke event loop asyncio milik `AvatarManager` (non-blocking dari sisi pemanggil) — **berjalan paralel** dengan `AudioPlayer.play()` yang blocking di thread `SpeakWorker`/`VoiceWorker`.
4. `LipSyncCoordinator.animate()`: panggil `AudioAnalyzer.analyze()` **sekali** di awal (dapat list amplitude per window ~50ms), lalu loop tiap window → `MouthMapper.map(amplitude)` → `AvatarManager.update_parameter_layer("lipsync", "MouthOpen", value)` → `asyncio.sleep(window_seconds)` supaya ritme mengikuti durasi window aslinya.
5. Selesai loop → set `MouthOpen = 0.0` (tutup mulut), log `Lip Sync Finished`.

### Timing & Sinkronisasi
- **Best-effort sync**, bukan sample-accurate: `animate_lipsync()` dan `player.play()` dipanggil nyaris bersamaan (beda beberapa ms) dari 2 thread/coroutine berbeda. Cukup natural secara visual, sesuai permintaan spec "smooth" (bukan frame-perfect, dan phoneme/viseme presisi eksplisit dilarang).
- **Dikonfirmasi dari log real** (`16:29:51.385` Playback started, `16:29:51.386` Lip Sync Started, `16:29:51.391` Amplitude Calculated) — jeda antar keduanya cuma beberapa milidetik.

### Konfigurasi (`config/constants.py`)
```python
LIPSYNC_WINDOW_MS = 50
LIPSYNC_SILENCE_THRESHOLD = 0.05
LIPSYNC_GAIN = 1.4
```

### `config/vtube_model_config.json` — section `parameters` (BARU)
```json
{
    "neutral": "Neutral", "happy": "Happy", "sad": "Sad", "...": "...",
    "parameters": {
        "MouthOpen": "MouthOpen"
    }
}
```
Value kanan harus persis nama parameter Input di VTube Studio (cek tab **Input Parameters** sambil ngomong ke mic). Kalau ganti model, cukup edit value ini.

### Batasan Sengaja
- Cuma RMS amplitude — tidak ada phoneme/viseme/AI/ML.
- Cuma 1 parameter logical (`MouthOpen`) — belum ada parameter mulut lain (lebar, bentuk, dst).
- `AvatarManager._parameter_layers` saat ini cuma menyimpan nilai per `layer_name` tanpa logic penggabungan kompleks (overwrite per parameter_id) — cukup karena tiap layer (mouth, nanti eye/breathing di v0.5.2) menargetkan `parameter_id` yang berbeda. **Kalau nanti 2 layer menargetkan parameter_id yang SAMA, logic penggabungan (mis. weighted sum) perlu ditambahkan di `update_parameter_layer()`** — catatan ini sudah ditinggalkan sebagai komentar di kode.

### Terkonfirmasi Bekerja (dari log real Teacher)
```
Lip Sync Started → Amplitude Calculated: 109 window, 0.050s/window → (mulut model VTS bergerak, dikonfirmasi visual) → Lip Sync Finished
```
Berjalan mulus berdampingan dengan Playback, Voice state machine, Avatar expression (Hotkey Happy), dan Memory dalam satu siklus chat yang sama.

## 12. Keputusan Desain Kumulatif (Tambahan v0.5.1)

- **`AvatarManager.update_parameter_layer()` dibuat generic** (`layer_name`, `logical_parameter`) sejak awal, bukan method khusus `set_mouth_open()` — supaya v0.5.2 (Eye Blink/Breathing) tinggal panggil dengan `layer_name` berbeda tanpa perlu mengubah `AvatarManager` lagi. Ini implementasi konkret dari Animation Independence Policy.
- **`VoiceManager` diberi hook generic `on_audio_ready`, bukan import langsung `LipSyncCoordinator`** — `VoiceManager` sengaja tetap tidak tahu lip sync itu apa; kalau di masa depan ada fitur lain yang butuh "audio siap sebelum diputar", hook yang sama bisa dipakai ulang tanpa modifikasi `VoiceManager`.
- **PCM tidak pernah digenerate ulang** — `on_audio_ready` menerima persis bytes yang sama yang akan dikirim ke `AudioPlayer`, bukan hasil TTS call kedua.
- **Retry TTS ditaruh di `tts.py`, bukan `voice_manager.py`** — karena ini karakteristik spesifik komunikasi jaringan `TextToSpeech`, bukan logic orkestrasi level atas.
- **`ParameterMapper` menangani baik hotkey (diskrit) maupun parameter kontinu** dalam satu file — tetap satu "Model Configuration layer", cuma section JSON-nya dipisah (`parameters` vs top-level) supaya jelas mana yang untuk trigger sesaat vs mana yang untuk nilai berkelanjutan.
