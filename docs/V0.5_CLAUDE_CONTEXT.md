# AI Companion (Arona) — Master Project Context

> **Dokumen ini adalah context tunggal.** Kalau mulai chat baru dengan Claude/GPT untuk lanjutin project ini, cukup upload dokumen ini — nggak perlu jelasin ulang dari awal.

---

## 1. Apa Project Ini

AI Waifu Companion desktop app, terinspirasi Arona (Blue Archive). Bukan sekadar chatbot — dirancang modular supaya bisa berkembang jadi companion dengan voice, avatar Live2D, memory, emosi, dll.

**Prinsip pengembangan:** incremental, per-milestone, jangan lompat fitur, jangan overengineering, jangan redesign arsitektur tanpa alasan kuat.

**Filosofi inti:** Desktop GUI **bukan** aplikasinya. Aplikasi sesungguhnya adalah `Companion`. GUI, Voice, dan (sekarang) Avatar hanyalah presentation/reaction layer di sekitarnya. Setiap modalitas input (keyboard, mic) akhirnya jadi teks sebelum mencapai `Companion`; setiap output (GUI, TTS, avatar) cuma bereaksi terhadap hasil `Companion`, tidak pernah memengaruhi logika AI-nya:

```
Keyboard  → Text ─┐
Mic → STT → Text ─┴→ Companion (+ Memory + waktu) → Gemini → reply (str)
                                                                  │
                        ┌─────────────────────────────────────────┼───────────────┐
                        ↓                                         ↓               ↓
                  GUI chat bubble                        TTS → Speaker      AvatarManager
                                                                              → VTube Studio
```

v0.2 dipikirkan sebagai **Desktop Shell**. **Human-in-the-Loop Memory Policy (sejak v0.3):** Memory milik Teacher, arsitektur harus siap show/edit/delete/forget kapan pun. **Avatar Independence Policy (sejak v0.5):** avatar bukan sumber kebenaran — `Companion` yang memutuskan reply, avatar cuma me-render reaksi visualnya; kalau avatar/VTube Studio mati, aplikasi harus tetap 100% bisa dipakai.

## 4. Arsitektur (WAJIB Dipertahankan)

```
Terminal (main.py)     Desktop GUI (main_gui.py + ui/window.py)
        │                              │
        └──────────────┬───────────────┘
                        ↓
                   Companion (ai/companion.py)
                        ↓
     ┌──────────────────┼──────────────────┐
     ↓                  ↓                  ↓
Conversation       MemoryManager       GeminiClient
                        ↓
                     memory.db

Jalur voice (terpisah, ketemu lagi di Companion.chat()):
Mic → Recorder → SpeechToText → Companion.chat(text) → reply → TextToSpeech → AudioPlayer → Speaker

Jalur avatar (BARU v0.5, HANYA di GUI, HANYA bereaksi SETELAH reply ada):
reply (dari Companion, lewat teks ATAU voice)
        ↓
  HaloMapper (avatar/expression.py)         "Logical Expression" — parsing "(Pink Heart Halo)" dst, PERMANEN
        ↓
  ParameterMapper (avatar/parameter_mapper.py)   "Model Configuration" — baca vtube_model_config.json, GANTI kalau ganti model
        ↓
  VTubeStudioClient (avatar/vtube.py)         protokol WebSocket murni
        ↓
  VTube Studio API (aplikasi eksternal, opsional)
```

**Aturan besi:**
- `Companion` satu-satunya koordinator Conversation + MemoryManager + GeminiClient.
- `VoiceManager` satu-satunya koordinator Recorder → STT → Companion → TTS → Player.
- **`AvatarManager` satu-satunya koordinator avatar** — menerima `reply` (string) SETELAH `Companion` selesai, memetakannya lewat `HaloMapper` + `ParameterMapper`, lalu memicu `VTubeStudioClient`. **Tidak ada kode WebSocket di `avatar_manager.py`** — itu domain `vtube.py`.
- **2 layer mapping avatar dipisah dengan sengaja** (rekomendasi eksplisit dari GPT, disetujui): `HaloMapper` = "Logical Expression" (halo teks → `Expression` enum, tidak pernah berubah walau ganti model). `ParameterMapper` = "Model Configuration" (`Expression` → nama Hotkey spesifik model yang lagi dipakai, dibaca dari `vtube_model_config.json`). **Ganti model Live2D gratis → model Arona custom = edit JSON saja, nol baris kode Python berubah.**
- UI (terminal maupun GUI) **hanya** boleh panggil API publik `Companion`, `VoiceManager` (via worker), dan `AvatarWorker.request_reaction()` / `stop_avatar()`.
- UI **tidak boleh** import `GeminiClient`, `MemoryManager`, modul `speech/*` secara langsung, atau `VTubeStudioClient`/`HaloMapper`/`ParameterMapper` secara langsung (semua lewat `AvatarManager`/`AvatarWorker`).
- **UI Independence**: PySide6/Qt **tidak boleh** di-import di luar `ui/`. Ini juga berlaku untuk seluruh `avatar/*` — translasi ke Qt Signal terjadi di `ui/avatar_worker.py`.
- **Conversation vs Memory tidak boleh dicampur** (aturan dari v0.3, masih berlaku penuh).
- **Avatar Independence Policy**: avatar bukan sumber kebenaran, tidak pernah memengaruhi logika AI. Kalau VTube Studio belum/tidak terbuka, `AvatarManager.react_to_reply()` cukup skip dengan log info (state bukan `READY`) — **tidak pernah** melempar error ke `Companion`/GUI. `Companion.chat()` **tidak tahu** avatar ada sama sekali.
- **Konteks waktu & memori tetap ephemeral** di `Companion._build_contents()` (dari v0.3/v0.4), tidak berubah.
- Tidak ada vector DB/RAG, tidak ada webcam/ARKit tracking untuk avatar, tidak ada lip sync yang diimplementasikan (`avatar/lipsync.py` sengaja kosong).

### `avatar/avatar_manager.py` — `AvatarManager` + `AvatarState` (BARU v0.5)
```python
class AvatarState(Enum):
    DISCONNECTED, CONNECTING, AUTHENTICATED, READY, BUSY

AvatarManager(vtube_client, halo_mapper, parameter_mapper, reconnect_interval=5.0, on_state_change=None)
state -> AvatarState
set_state_listener(callback: Callable[[AvatarState], None]) -> None
await run_forever() -> None        # loop connect+auth+auto-reconnect, jalankan sebagai 1 task asyncio
stop() -> None
await react_to_reply(reply_text: str) -> None   # skip diam-diam kalau state != READY
```

## 6. GUI (v0.2 shell + Mic Button v0.4 + Avatar Status v0.5)

- Layout dasar (sidebar, chat area, avatar icon di bubble, mic button) tidak berubah dari v0.4.
- **Baru di v0.5:** `QLabel` permanent widget di status bar (`self._avatar_status_label`, ditambah via `statusBar().addPermanentWidget()`) menampilkan `"Avatar: <state>"` — otomatis update lewat `AvatarWorker.state_changed`.
- `MainWindow.__init__()` sekarang juga membangun `VTubeStudioClient` → `AvatarManager` → `AvatarWorker`, lalu langsung `.start()` di akhir constructor.
- `_on_reply_received` (balasan chat teks) dan `_on_voice_reply` (balasan chat voice) **keduanya** memanggil `self._avatar_worker.request_reaction(reply)` — avatar bereaksi sama persis baik Teacher ngetik atau ngomong.
- `closeEvent` memanggil `self._avatar_worker.stop_avatar()` sebelum `event.accept()`, supaya event loop asyncio berhenti bersih.
- **GUI tetap tidak import** `VTubeStudioClient`/`HaloMapper`/`ParameterMapper`/`websockets` secara langsung — semua lewat `AvatarManager`/`AvatarWorker`.
- **Edge case yang diketahui (bukan bug, minor & jarang terjadi):** ada race condition kecil di awal startup — `AvatarWorker.start()` cuma memulai thread, sementara `self._loop` di dalamnya baru ke-set setelah `run()` benar-benar jalan (beberapa ratus ms). Kalau Teacher kirim pesan **sangat cepat** (<1 detik setelah window terbuka), `request_reaction()` bisa no-op diam-diam karena `self._loop` masih `None` (ada guard `if self._loop is None: return`). Dalam praktiknya nyaris tidak pernah kejadian karena loading Companion + Whisper model duluan makan waktu beberapa detik. Dikonfirmasi lewat log real: `Companion` selesai loading di `14:39:57`, tapi window baru `Window opened` di `14:40:09` dan avatar baru `READY` di `14:41:12` — jeda ini jauh lebih dari cukup.

## 8. Avatar System (v0.5) — Detail Penting

### Alur Kerja per Balasan
1. `Companion.chat()` selesai → GUI dapat `reply` (string), baik dari `ChatWorker` (teks) maupun `VoiceWorker` (voice).
2. GUI panggil `self._avatar_worker.request_reaction(reply)` — non-blocking, dikirim ke event loop asyncio `AvatarManager` yang jalan di `AvatarWorker` (background `QThread`).
3. `AvatarManager.react_to_reply()`:
   - Kalau `state != READY` (VTS belum connect/auth) → skip, log info, **tidak ada error**.
   - `HaloMapper.map(reply)` cari pola `(... halo ...)` di teks → `Expression` enum (default `NEUTRAL` kalau tidak ketemu/tidak dikenal).
   - `ParameterMapper.get_hotkey(expression)` → nama Hotkey dari `vtube_model_config.json`. Kalau tidak ada mapping → skip.
   - State → `BUSY` → `VTubeStudioClient.trigger_hotkey(hotkey)` → state balik ke `READY`.

### Koneksi & Autentikasi
- `AvatarManager.run_forever()` loop: `CONNECTING` → `connect()` + `authenticate()` → `READY` → idle-wait → kalau exception (VTS ditutup/dsb) → `DISCONNECTED` → tunggu `VTUBE_RECONNECT_INTERVAL` detik → ulangi.
- Autentikasi otomatis: coba token tersimpan (`config/vtube_token.json`) dulu; kalau ditolak, minta token baru ke VTube Studio (butuh klik "Allow" di app VTS sekali), lalu simpan token untuk sesi berikutnya.
- **Dikonfirmasi dari log real:** proses `connect → tunggu izin Allow di VTS → authenticate → READY` makan waktu ~1 menit di percobaan pertama (`14:40:11` connect, `14:41:12` authenticated) — wajar karena Teacher perlu klik izin manual di VTube Studio. Sesi berikutnya seharusnya jauh lebih cepat karena token sudah tersimpan.

### Konfigurasi (`config/constants.py`, baru v0.5)
```python
VTUBE_STUDIO_URL = "ws://localhost:8001"
VTUBE_PLUGIN_NAME = "Arona Companion"
VTUBE_PLUGIN_DEVELOPER = "Kepin"
VTUBE_TOKEN_PATH = "config/vtube_token.json"
VTUBE_MODEL_CONFIG_PATH = "config/vtube_model_config.json"
VTUBE_RECONNECT_INTERVAL = 5.0
```

### `config/vtube_model_config.json` — Model Configuration Layer
```json
{
    "neutral": "Neutral",
    "happy": "Happy",
    "sad": "Sad",
    "angry": "Angry",
    "embarrassed": "Embarrassed",
    "excited": "Excited",

Value harus persis sama dengan nama Hotkey yang dibuat manual di VTube Studio untuk model Live2D gratis yang sedang di-load. **Kalau ganti model → edit file ini saja**, tidak perlu sentuh `avatar_manager.py`/`expression.py`/`vtube.py`.

### Batasan Sengaja (v0.5)
- Tidak ada webcam/face tracking/ARKit — avatar 100% AI-driven dari halo teks Arona.
- Tidak ada lip sync (`avatar/lipsync.py` kosong, reserved untuk v0.5.1).
- Model Live2D yang dipakai untuk testing adalah model gratis sementara — bukan model final Arona custom.
- Emosi tidak di-infer ulang di avatar layer — `HaloMapper` cuma parsing halo yang **sudah ditentukan** oleh prompt Arona (`halo.txt`), tidak ada logic AI baru di sini.

### Terkonfirmasi Bekerja (dari log real Teacher)
```

Hotkey dipicu: Happy    (saat balasan mengandung "(Pink Heart Halo)")
Hotkey dipicu: Neutral  (saat diminta ganti ke netral, balasan mengandung "(Blue Halo)")

## 11. Keputusan Desain Kumulatif

Poin-poin dari v0.1–v0.4 tetap berlaku (lihat riwayat kalau butuh detail). Tambahan v0.5:

- **2 layer mapping avatar dipisah tegas** (`HaloMapper` vs `ParameterMapper`) — supaya ganti model Live2D di masa depan cuma edit JSON, bukan kode.
- **`AvatarManager` pakai asyncio di dalam `QThread`**, bukan pola `QThread` sekali-jalan seperti `ChatWorker`/`VoiceWorker` — karena koneksi VTube Studio bersifat persisten (bukan request sekali selesai), dan `websockets` memang asyncio-native. `request_reaction()` dari GUI thread ke event loop lewat `asyncio.run_coroutine_threadsafe` — pola standar untuk situasi ini.
- **Avatar reaction dipicu SETELAH teks & suara**, bukan sebelum — urutan tidak signifikan secara teknis (semua background), tapi menegaskan alur konseptual `AICompanion → Reply → Avatar Layer` dari spec.
- **`react_to_reply()` skip diam-diam kalau state bukan `READY`** — mewujudkan Avatar Independence Policy: VTube Studio opsional, Conversation wajib.
- **Auto-reconnect tanpa henti** (`run_forever()` loop dengan `reconnect_interval`) — Teacher tidak perlu restart aplikasi kalau lupa buka VTube Studio duluan atau VTS-nya crash di tengah jalan.

5. **Jangan pernah mencampur Memory dan Conversation.** **Jangan perkenalkan vector DB/RAG.**
6. **Jangan gabungkan `HaloMapper` dan `ParameterMapper` jadi satu file** — pemisahan ini sengaja supaya ganti model Live2D di masa depan cuma butuh edit `config/vtube_model_config.json`, bukan kode Python. Kalau ada permintaan "biar simpel gabung aja", ingatkan trade-off ini dulu ke user.
7. **Jangan bikin `AvatarManager`/`vtube.py` memengaruhi logika balasan `Companion`** — avatar cuma boleh membaca `reply` setelah jadi, tidak pernah menyuntikkan apa pun balik ke `Companion`/`Conversation`.
8. **Perhatikan penamaan parameter yang benar:** `VoiceManager(..., voice_name=...)` bukan `tts_voice_name`. Untuk avatar, konstruktor `AvatarManager(vtube_client=..., halo_mapper=..., parameter_mapper=..., reconnect_interval=..., on_state_change=...)` — cek signature dulu kalau ragu sebelum menambah parameter baru.
9. **Format halo di `prompts/halo.txt` dan regex parsing di `HaloMapper` saling bergantung** — kalau ada perubahan format halo di prompt (misal nama halo baru), `_HALO_TO_EXPRESSION` dict di `avatar/expression.py` juga harus disesuaikan, dan `config/vtube_model_config.json` mungkin butuh key baru.
10. Kalau user minta fitur baru, cek dulu masuk milestone versi berapa (tabel bagian 2) — kalau versi depan, tanya dulu apakah user mau lompat milestone atau cuma nyiapin arsitektur.
11. Semua modul baru tetap Single Responsibility; backend logic tidak boleh nyasar ke `ui/`, dan modul avatar/speech/memory tidak boleh diakses langsung dari `ui/` — harus lewat `Companion`/`VoiceManager`/`AvatarManager` beserta worker Qt masing-masing.
12. User berkomunikasi dalam Bahasa Indonesia; kode & komentar teknis boleh Inggris seperlunya, penjelasan ke user pakai Bahasa Indonesia.
13. Kalau butuh tau isi kode file tertentu yang belum di-paste di chat baru, minta user paste isinya dulu — jangan asumsikan berubah dari yang didokumentasikan di sini kecuali dikonfirmasi.
