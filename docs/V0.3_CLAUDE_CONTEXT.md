> **Dokumen ini adalah context tunggal.** Kalau mulai chat baru dengan Claude/GPT untuk lanjutin project ini, cukup upload dokumen ini — nggak perlu jelasin ulang dari awal.

## 1. Apa Project Ini

AI Waifu Companion desktop app, terinspirasi Arona (Blue Archive). Bukan sekadar chatbot — dirancang modular supaya bisa berkembang jadi companion dengan voice, avatar Live2D, memory, emosi, dll.

**Prinsip pengembangan:** incremental, per-milestone, jangan lompat fitur, jangan overengineering, jangan redesign arsitektur tanpa alasan kuat.

**Filosofi inti:** Desktop GUI **bukan** aplikasinya. Aplikasi sesungguhnya adalah `Companion`. GUI hanyalah salah satu presentation layer. Nanti Voice Interface, Discord Bot, atau Web Interface semuanya bisa dipasang di atas `Companion` yang sama tanpa mengubah backend:

```
Desktop GUI  ↘
Voice        → Companion → Memory + Gemini
Discord Bot  ↗
Web          ↗
```

v0.2 dipikirkan sebagai **Desktop Shell** (bukan sekadar Chat Window) — cangkang yang nanti diisi Chat, Memory, Voice, Avatar, Settings, Emotion, Vision, Automation.

**Human-in-the-Loop Memory Policy (sejak v0.3):** Memory adalah milik Teacher. Teacher harus selalu tetap punya kontrol atas long-term memory-nya. Arsitektur harus siap kapan pun untuk fitur show/edit/delete/forget memori — meski belum semua diimplementasikan, arsitekturnya sudah kompatibel. Arona tidak boleh jadi sistem memori yang tidak bisa dikontrol.

## 4. Arsitektur (WAJIB Dipertahankan)

```
Terminal (main.py)     Desktop GUI (main_gui.py + ui/window.py)
        │                              │
        └──────────────┬───────────────┘
                        ↓
                   Companion (ai/companion.py)
                        ↓
     ┌──────────────────┼──────────────────┐
     ↓                  ↓                  ↓
Conversation       MemoryManager       GeminiClient
(ai/conversation)  (database/          (ai/gemini.py)
                    memory_manager)          ↓
                        ↓                Gemini API
                     memory.db
```

**Aturan besi:**
- `Companion` adalah satu-satunya modul yang tahu soal `Conversation`, `MemoryManager`, **dan** `GeminiClient` sekaligus.
- UI (terminal maupun GUI) **hanya** boleh panggil `Companion.chat(user_input)`, `Companion.get_history()`, `Companion.clear_history()`, dan (baru) `Companion.list_memories()` / `delete_memory()` / `clear_memories()` — tapi method memori ini **belum dipanggil dari `ui/` mana pun** sampai sekarang, cuma disiapkan.
- UI **tidak boleh** import `GeminiClient`, `MemoryManager`, `types.Content`, atau bangun prompt sendiri.
- **UI Independence**: PySide6/Qt **tidak boleh** di-import di luar folder `ui/`. Backend tidak boleh tahu bahwa GUI itu ada.
- **Conversation vs Memory — TIDAK BOLEH DICAMPUR (aturan paling kritis sejak v0.3):**
  - `Conversation` = sementara, per sesi, bisa di-`clear()`, isi dialog mentah.
  - `Memory` (SQLite via `MemoryManager`) = permanen, lintas sesi, isi fakta/pengetahuan hasil ekstraksi, bukan dialog mentah.
  - `Conversation` **tidak boleh** punya method `save_memory()`/`search_memory()`/`load_memory()`.
  - `memory.db` **tidak boleh** menyimpan history chat.
- `ai/gemini.py`, `ai/prompt_builder.py`, `ai/personality.py`, `ai/conversation.py`, dan seluruh `prompts/*.txt` **belum pernah diubah** sejak v0.1.0/v0.1.1 dan seharusnya tetap begitu sampai ada bug kritis.
- `PromptBuilder` **tidak tahu SQLite exist** — injeksi memori dilakukan `Companion` secara terpisah, bukan lewat `PromptBuilder`.
- Tidak ada vector DB/RAG (ChromaDB, FAISS, Qdrant, Milvus, Pinecone) — SQLite dengan `LIKE` query dianggap cukup sampai ada alasan kuat untuk berubah.
- Success criteria v0.2 & v0.3: kalau `main.py` (terminal) dihapus total, sisanya tetap jalan. Kalau `memory_manager.py` gagal/SQLite error, `Conversation` tetap lanjut (graceful degrade) — chat tidak boleh crash gara-gara memori.

## 5. Kontrak API Tiap Modul (Penting Buat Chat Baru)

### `ai/companion.py` — `Companion`
```python
Companion()                                   # init: load prompts, build system prompt, siapkan GeminiClient + Conversation + MemoryManager + MemoryExtractor
Companion.chat(user_input: str) -> str        # kirim pesan, inject memori relevan, return balasan Arona. Raise RateLimitError / CompanionError
Companion.get_history() -> list               # ambil history percakapan (list[types.Content])
Companion.clear_history() -> None             # hapus history percakapan (TIDAK menghapus memori)
Companion.list_memories(limit: int = 50) -> list[Memory]   # baru — belum dipanggil GUI
Companion.delete_memory(memory_id: int) -> None             # baru — belum dipanggil GUI
Companion.clear_memories() -> None                            # baru — belum dipanggil GUI
```
Exception: `RateLimitError` (429), `CompanionError` (error lain dari Gemini).

### `ai/conversation.py` — `Conversation` (TIDAK BERUBAH sejak v0.1.1, TIDAK ADA fungsi memori)
```python
add_user_message(text: str) -> None
add_assistant_message(text: str) -> None
rollback_last_message() -> None
clear() -> None
get_history() -> list[types.Content]  # return copy, bukan reference
```

### `database/memory_manager.py` — `MemoryManager` (baru, v0.3)
```python
MemoryManager(db_path: Path = DB_PATH)
save_memory(category: str, content: str) -> Memory     # dedup otomatis (COLLATE NOCASE), kategori invalid → "general"
load_memories(limit: int = 10) -> list[Memory]          # urut updated_at DESC
search_memory(keyword: str, limit: int = 10) -> list[Memory]   # LIKE query sederhana
update_memory(memory_id: int, content: str | None, category: str | None) -> None
delete_memory(memory_id: int) -> None
clear_all() -> None
```
`Memory` dataclass: `id, category, content, created_at, updated_at`. Kategori valid: `preference, relationship, identity, project, schedule, general`.

### `ai/memory_extractor.py` — `MemoryExtractor` (baru, v0.3 — "decision layer")
```python
MemoryExtractor(api_key: str, model_name: str)
extract(user_input: str) -> list[dict]   # [{"category": "...", "content": "..."}, ...] atau [] kalau tidak ada yang layak diingat
```
Pakai Gemini call terpisah (`temperature=0.0`) dengan system prompt klasifikasi khusus, **bukan** if-statement hardcoded, **bukan** vector search. Kalau parsing gagal/exception, return `[]` dengan aman (tidak pernah melempar error ke `Companion`).

### `ai/commands.py`
```python
is_command(text: str) -> bool
run_command(text: str, companion) -> CommandResult   # CommandResult(message: str, should_exit: bool)
```
Command aktif: `/help`, `/history`, `/clear`, `/version`, `/exit`. Belum ada command khusus memori (`/memory`, dll) — reserved untuk versi depan.

### `ai/gemini.py` — `GeminiClient` (stateless, TIDAK BERUBAH sejak v0.1.0)
```python
GeminiClient(api_key, model_name, system_prompt)
GeminiClient.send(contents: list[types.Content]) -> str
```

### `config/logger.py`
```python
from config.logger import logger   # loguru instance (file logs/app.log, rotation 1MB, retention 7 hari)
```

## 7. Memory System (v0.3) — Detail Penting

### Filosofi
- **Memory ≠ Conversation.** Memory menyimpan pengetahuan (fakta jangka panjang tentang Teacher), Conversation menyimpan dialog (sementara, per sesi).
- Contoh memori BAIK: "Teacher lebih suka dipanggil Kepin", "Teacher suka Blue Archive", "Teacher sedang membangun AI Companion", "Teacher pakai Windows 11".
- Contoh yang BUKAN memori (tetap di Conversation saja): "Halo", "Selamat pagi", "Haha", "Makasih", "Jam berapa sekarang?".

### Alur Kerja per `chat()`
1. `Companion._build_contents()` load hingga 10 memori teratas (`ORDER BY updated_at DESC`) dari `MemoryManager`, format jadi 1 blok teks, disisipkan sebagai `types.Content` tambahan **di depan** history — **ephemeral**, tidak pernah disimpan ke `Conversation`.
2. `GeminiClient.send()` dipanggil seperti biasa dengan `contents` gabungan itu.
3. Setelah dapat balasan, `Companion._remember_if_useful()` memanggil `MemoryExtractor.extract(user_input)` — Gemini call terpisah yang menilai apakah pesan Teacher barusan mengandung fakta jangka panjang.
4. Kalau ada, tiap fakta disimpan via `MemoryManager.save_memory()` (dengan dedup otomatis by `category + content COLLATE NOCASE`).

### Skema Database (`memories` table di `memory.db`)
```sql
id INTEGER PRIMARY KEY AUTOINCREMENT
category TEXT NOT NULL        -- preference/relationship/identity/project/schedule/general
content TEXT NOT NULL
created_at TEXT NOT NULL      -- ISO 8601 UTC
updated_at TEXT NOT NULL      -- ISO 8601 UTC, diperbarui saat dedup match
```
Index: `idx_memories_category`.

### Batasan Sengaja (Jangan "Diperbaiki" Tanpa Diminta)
- Limit 10 memori per injeksi — biar prompt tidak membengkak. Belum ada relevance ranking pintar (misal semantic search) — masih "top N terbaru".
- Dedup hanya exact-match case-insensitive, bukan fuzzy/semantic dedup.
- Belum ada field `importance`, `last_access`, `access_count` — sengaja ditunda sesuai spec ("do not implement unnecessary fields yet").
- Belum ada UI untuk show/edit/delete memori — method `Companion.list_memories()` dll sudah ada tapi GUI belum memanggilnya.
- Semua error di pipeline memori (SQLite gagal, JSON parsing extractor gagal, dll) di-catch dan cuma menghasilkan `logger.warning`, **tidak pernah** melempar exception ke pemanggil — chat harus tetap jalan walau memori error total.

## 10. Keputusan Desain Kumulatif (Kenapa Sesuatu Dibangun Begitu)

- **`GeminiClient` stateless** — history dikirim dari luar, gampang diganti/diuji.
- **`Companion` sebagai satu pintu masuk backend**, sekarang juga koordinator Memory — UI tetap cuma tahu `companion.chat()`.
- **Command system dipisah dari UI** — reusable di terminal & GUI.
- **Logging di level backend, bukan UI.**
- **Avatar chat bubble di-cache**, bukan reload tiap pesan.
- **`main.py` dan `main_gui.py` dipisah total.**
- **Stylesheet dipisah ke `ui/theme.py`.**
- **Sidebar non-fungsional, disiapkan sebagai shell.**
- **Avatar besar/Live2D sengaja tanpa placeholder sama sekali** — ditunda total sampai v0.5.
- **Memory dipisah total dari Conversation** — dua siklus hidup berbeda (permanen vs sementara), supaya v0.4 (Voice) dan v0.5 (VTube) bisa "otomatis untung" dari Memory tanpa Conversation ikut berubah bentuk.
- **Injeksi memori bersifat ephemeral (dibangun ulang tiap `chat()`, tidak disimpan ke `Conversation`)** — supaya `/clear` (yang menghapus Conversation) tidak pernah ikut menghapus memori permanen, dan sebaliknya.
- **Keputusan "layak diingat atau tidak" didelegasikan ke Gemini call terpisah (`MemoryExtractor`), bukan if-statement manual** — sesuai permintaan spec supaya sistem tetap extensible tanpa hardcoding, sekaligus tetap bukan RAG/vector DB (cuma klasifikasi teks biasa).
- **Dedup memori hanya exact-match case-insensitive** — cukup untuk mencegah entri identik berulang, tidak overengineering ke arah semantic dedup yang belum dibutuhkan.
- **Semua kegagalan di pipeline memori di-swallow jadi log warning**, chat tidak pernah crash karena SQLite/extractor — "graceful degrade" eksplisit dari spec.

Kalau kamu (AI) baca dokumen ini di awal chat baru:

2. **Jangan ubah** `ai/gemini.py`, `ai/personality.py`, `ai/prompt_builder.py`, `ai/conversation.py`, atau isi `prompts/*.txt` kecuali diminta eksplisit.

9. User berkomunikasi dalam Bahasa Indonesia; kode & komentar teknis boleh Inggris seperlunya, penjelasan ke user pakai Bahasa Indonesia.
10. Kalau butuh tau isi kode file tertentu yang belum di-paste di chat baru, minta user paste isinya dulu — jangan asumsikan berubah dari yang didokumentasikan di sini kecuali dikonfirmasi.
