# Objective

Introduce Developer Tools.

Developer Tools provide runtime inspection.

Developer Tools never change application behavior.

Developer Tools are read-only.

Developer Tools are intended only for developers.

# Success Criteria

Developer Tools work independently.

All information is obtained through public APIs.

No runtime state is modified.

No Gemini requests are created.

No memory is modified.

No avatar state is modified.

No behavior state is modified.

No architecture redesign is required.

If implementing Developer Tools requires redesigning Behavior, Vision, Routine, Initiative, Companion, PromptBuilder, ContextBuilder, MemoryManager, Avatar, Voice, or GUI,

the implementation is considered architecturally incorrect.
